# 計算任務與快取掃描工具開發指導

> 狀態：P05 通用框架已完成；M、L、E、C 的業務 executor／adapter 仍依各自開發階段接線，N 維持非計算邊界
>
> 對應大點：I. 核心參數滑桿與快取掃描工具
>
> 用途：定義後續研究功能中，原子計算、複合研究任務、批次回測、掃描、分析與視覺化所需的按需計算、進度、取消、快取與滑桿互動規則。此文件不是三份真源文件，不取代既有穩定系統規格。

## 一、系統定位

本文件定義共通計算任務規則，並把任務分為兩層：

```text
原子計算任務：一次可獨立重試、取消、去重的計算
複合研究任務：由使用者明確建立，協調多個有邊界的原子任務與研究階段
```

它不只服務滑桿，也適用於所有會造成大量計算的新研究功能。

原則：

```text
使用者點哪個分析項目，才計算哪個分析項目。
已計算結果可重用。
切換圖表不得重跑底層回測。
```

不得因開啟頁面或切換圖表，自動建立一個大任務讓使用者被迫等待所有項目完成。

M 可以建立複合研究任務，但每個階段都必須先顯示計算計畫與計算量，再由使用者明確啟動；下一階段不得在未確認計算量時自動無限擴張。

C 研究同樣是複合研究任務：CVT 特徵校準、初始有限搜尋、追加有限預算及每個 anchor 鄰域探測都是分開的 batch。每個 batch 必須具有固定 manifest；`current_plan_completed` 只表示目前計畫完成，不阻止使用者日後明確追加新 batch。

## 三、適用範圍

下列功能都屬於計算任務：

- 一維參數掃描。
- 二維 heatmap。
- 3D 曲面資料計算。
- 多維鄰域抽樣。
- 長週期風險濾網批次回測。
- 隨機參數與無意義規則對照。
- 曝險序列打散對照。
- 報酬分析補算。
- L 來源快照、擾動版本生成、內容驗證及擾動資料上的批次回測。
- E 片段重組預覽、實體行情生成、日期映射、內容驗證及原子發布。
- C 的 CVT 特徵校準、MOME 路徑評估、追加搜尋預算與 anchor 鄰域探測。
- 預測模型訓練、walk-forward 驗證與 OOF 預測物化。
- M 的全域探索、局部細化、地形分析與候選驗證協調。
- M `ResearchSeries` 的共同評估 manifest 與跨設定配對補算。

N「通用研究結果與參數比較工具」不屬於計算任務。N 只讀各來源已保存的不可變成果；矩陣轉置、有號差、合法步數差、篩選、排序、相容 metadata 判定及圖表資料載入都是一般同步介面操作，不建立 I 任務。若來源缺少 G、回測或其他分析，N 只能顯示未計算及來源入口，不得透過 I 暗中補算。

## 四、按需計算與任務分層

### 4.1 原子計算任務

每個可獨立計算的分析項目必須是獨立動作。

例如：

```text
一維 Beta 曲線：點了才算
Beta × Gamma heatmap：點了才算
3D 曲面：若 heatmap 格點已算完，只轉換視覺化，不重算
多維鄰域抽樣：點了才算
半徑穩健性衰退曲線：點了才算
```

若多個視覺化使用同一批底層回測結果，底層結果只計算一次。

### 4.2 複合研究任務

複合研究任務只負責協調原子任務，不得把所有階段合成不可理解、不可中止的黑盒工作。

複合任務必須：

- 綁定不可變研究設定。
- 保存父任務、階段與子任務關係。
- 每個階段有固定輸入、輸出、版本與完成條件。
- 每個階段開始前顯示本階段精確計算量。
- 由使用者明確啟動每個會新增大量計算的階段。
- 允許只取消目前階段，不破壞先前有效結果。
- 能在重開頁面後繼續下一階段或補算缺漏。

若後續細化範圍必須依前一階段結果決定，系統應先完成前一階段，再提出新的細化計畫與精確計算量；不得用不確定的「持續算到找到答案」取代總計算量。

## 五、計算量、進度與取消

所有計算任務都必須在開始前顯示：

- 預計計算項目。
- 預計回測次數或分析次數。
- 預估耗時，若無法可靠預估，至少顯示未知。
- 是否會產生或重用快取。
- 若為複合任務，顯示目前階段、後續尚未啟動階段及其依賴。

計算中必須顯示：

- 已完成數量。
- 總數量。
- 百分比進度。
- 目前階段。
- 錯誤數量。
- 取消按鈕。

使用者取消後：

- 已完成且有效的子結果可保留為快取。
- 未完成任務不得標記為完成。
- 前端必須清楚顯示任務已取消。
- 取消子任務不得把整個複合研究任務錯誤標成完成。
- 複合研究任務應依已完成階段標示「部分完成」或「等待下一階段」。
- Executor 不得只在開始與結束時檢查取消；長時間 CPU 計算必須把任務 context 傳入核心，並在 epoch、fold、候選或其他有限工作單位邊界合作停止。取消後不得繼續占用 worker 與 CPU 直到整批自然完成。

## 六、快取 key

掃描與分析結果必須使用可重現的分層 key，不得把研究任務 metadata 全部塞進底層 `backtest_key`，否則相同回測會因來自不同研究任務而無法重用。

至少分為：

```text
Backtest key：只描述會改變實際回測結果的條件
Evaluation point key：研究設定 + 參數空間 schema + 標準化參數向量
Analysis key：底層結果 + 分析設定 + 分析版本
```

C 的生成路徑身分另以 W/H 日期及 canonical 四座標形成 path hash。Path hash 作為該內部合成 dataset 的內容身分；C study、batch、CVT cell、父代與血緣只屬研究 metadata，不得塞入 `backtest_key` 降低相同實際回測的重用率。

各層合計至少能追溯：

- dataset hash。
- instrument id。
- interval。
- data source。
- 回測起訖時間。
- 參數包 hash。
- spawn / 本金 / 現金流設定。
- execution mode。
- 手續費、滑價與成本設定。
- position structure。
- 長週期濾網設定。
- 模型 artifact 與預測資料 hash，如有。
- 動態政策 hash，如有。
- 參數空間 schema 與量化版本。
- 研究設定 hash，如屬 M。
- 研究階段、取樣與細化設定。
- 掃描設定。
- 分析版本。

不同分析若共享同一批底層回測結果，應重用底層結果，再各自產生視覺化資料。

不同 M 研究設定若產生相同實際參數包與相同回測條件，也應重用同一個標準化回測結果；研究設定差異只形成不同評估點引用。

`ResearchSeries` 的配對比較先建立一組共同標準化參數向量，再展開為「成員研究設定 × 共同向量」的有限複合 manifest。I 必須在啟動前顯示每個設定的快取命中、缺漏點與實際新增回測量；某成員失敗或取消不得讓其他成員已完成結果失效。

共同 manifest 只保證評估座標配對，不允許 I 合併不同研究設定的評估點、J 區域或候選。若底層 `backtest_key` 相同仍重用同一標準化回測結果；若實際執行條件不同則分別計算。

## 七、滑桿規則

滑桿主要服務參數掃描與穩健區域分析。

預設規則：

```text
滑桿範圍 = 中心參數 ± 目前選定鄰域半徑
滑桿步長 = 核心參數最小有效步長
小數位 = 2
```

滑桿拖動時不得即時觸發回測。

滑桿只能讀取已計算完成的快取結果，並更新圖表或摘要。

若拖到尚未計算的格點，前端應提示該點尚未計算，並提供單點計算或範圍補算。

## 八、計算量上限

系統必須避免使用者無意間建立爆量計算。

若計算量超過目前環境的建議上限，前端必須提示：

- 本次計算量。
- 建議縮小範圍、調大步長或降低解析度。
- 是否仍要送出。

硬上限可由系統設定；超過硬上限時不得開始任務。

目前單機研究環境的預設硬上限為 `300000` 估算工作單位；超過建議上限仍須由使用者明確確認。這只是允許建立較大的有限任務，不提高 worker 併發數，也不取消進度、取消與失敗重試保護。

大量單點回測屬於高記憶體工作。單機環境即使共用 worker 數較高，同一時間最多只執行兩個完整路徑回測；等待執行名額的項目仍須立即回應取消。回測核心、額外期間評分及結果寫入前都必須沿用同一個取消 context，不得只取消排程紀錄而讓當前回測繼續運算。

標準化路徑的 JSON 內容不得插值到 SQL 慢查詢或錯誤日誌。容器日誌必須輪替，SaaS 與資料庫容器必須設記憶體上限，Go heap 必須有軟上限；這些限制是主機存活保護，不改變任務硬上限、結果語義或既有快取身分。

## 九、任務保存

長時間計算任務應保存任務紀錄。

任務紀錄包含：

- 任務 ID。
- 任務類型。
- 父任務 ID，如有。
- 研究設定 ID 與 hash，如有。
- 階段 ID、階段類型與階段順序。
- 本階段計算 manifest。
- 設定。
- 快取 key。
- 狀態。
- 進度。
- 錯誤。
- 建立時間。
- 完成時間。
- 取消時間。
- 有效子結果數、失敗數與缺漏數。
- 隨機演算法與版本、根 seed、目前 RNG 位置及 checkpoint，如任務含亂數。

使用者應能重開任務查看既有結果，並能補算缺漏項目。

複合研究任務重開後，必須能看到：

- 已完成階段。
- 目前部分完成階段。
- 尚未啟動階段。
- 各階段的子任務與錯誤。
- 哪些結果可由快取重用。

只有設定、資料與版本 hash 全部相容時，才可從既有階段繼續。

## 十、低功耗視覺化

圖表視覺化必須採低功耗策略：

- 預設不自動動畫。
- 不在滑桿拖動時重算。
- 不在隱藏分頁持續渲染。
- 不在未開啟面板時輪詢大量資料。
- 大型 3D 圖需提供 2D heatmap 替代視圖。

## 十一、完成判準

此功能完成後，至少必須滿足：

- 所有大量計算任務都有總計算量、進度與取消。
- 可用原子任務組成有明確階段的複合研究任務。
- 複合任務每一階段都在執行前提供精確計算 manifest，並由使用者啟動。
- 可用穩定 key 快取掃描與分析結果。
- 可重開任務查看已完成結果。
- 可補算缺漏項目。
- 可只取消目前階段並保留先前有效結果。
- 滑桿拖動只讀取快取，不觸發回測。
- 視覺化符合低功耗要求。
- L 可把每個擾動版本與每個 subject × dataset 回測作為獨立原子任務，取消後保留完成版本，並依原 manifest 續跑缺漏。
- E 可把預覽、片段展開、日期映射、實體寫入與發布前驗證納入有限 manifest；取消或失敗時不得發布半成品行情。
- C 可把 CVT 特徵校準、有限 MOME 搜尋、追加預算與 anchor 探測分成可重現 batch；取消、重啟及續跑不得改變既有路徑、RNG 順序或血緣。

## 十二、P05 實作與驗收紀錄

完成日期：2026-07-15。

本階段完成 I 的通用基礎設施，不提前宣稱 M、L、E、C 的業務功能已完成。後續模組需以正式 executor／adapter 接入本框架，不得另建任務、快取或續跑真源。

- 建立版本化 canonical manifest、task/cache key、分層 key、原子任務、階段 DAG 與複合任務；複合任務的每個階段必須先預覽再由使用者明確啟動。
- 建立 PostgreSQL 任務、依賴、項目與快取真源，並以 GORM AutoMigrate 管理；worker 具固定併發、租約、heartbeat、panic 隔離、取消、部分完成、缺漏重試與服務重啟恢復。
- 同使用者、同 key 的完成結果可重用；不同使用者隔離；版本或內容 hash 不相容即失效；併發同 key 只執行一次。heartbeat 持續至終態落庫，避免忙碌資料庫造成租約空窗與重複計算。
- 任務中心只輪詢輕量摘要；完整 settings／manifest／checkpoint 與項目結果採明確按需讀取。隱藏分頁停止輪詢，不因開頁、圖表切換或空資料建立任務。
- 計算量預覽提供總項目、快取命中、實際新增量、未知耗時、建議上限與硬上限；完成、失敗、取消、缺漏與進度分開呈現，不以部分結果冒充完成。
- 備份格式升級為 v4，增量備份會帶入父子任務、依賴、項目與快取引用閉包；還原後驗證版本、manifest、輸入、結果、checkpoint 與依賴 hash。

驗收證據：

- `go test ./... -count=1` 通過；設定 PostgreSQL 整合資料庫後再次執行全專案測試亦通過。
- P05 PostgreSQL 測試通過失敗重試、checkpoint 續跑、快取重用、跨使用者隔離、內容失效唯讀、同 key 併發去重、取消保留結果、複合階段顯式啟動及租約過期重啟恢復；同 key 壓力案例連跑十次通過。
- 備份工具 PostgreSQL 整合測試通過 P03／P04／P05 關聯圖閉包還原及 hash 驗證。
- 全專案 vet、前端 `tsc -b && vite build`、Docker 重新建置與服務狀態檢查通過。
- 實際瀏覽器驗收通過登入後任務中心、限制載入、空資料、390px 行動版無水平溢出及 console 無錯誤。
