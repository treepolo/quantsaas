# 研究構想整理

本資料夾集中保存本輪腦力激盪後整理出的研究功能討論稿與開發指導文件。

這些文件不是三份真源文件，不取代既有穩定系統規格。正式開發前仍需依各文件的完成定義、依賴關係與測試要求逐項確認。

## 文件清單

1. `研究功能規格討論流程.md`
   - 規定每個研究功能從想法到完整開發指導文件的討論方式。
   - 後續尚未完成的字母大點，以及既有功能的追加討論，均須依此流程進行。

2. `研究功能構想初步分組.md`
   - 原始構想的分組整理。
   - 用來確認每段想法是否都有被對應到功能或研究方向。

3. `每日實際持倉計算機制開發指導.md`
   - 定義每日實際持倉比例的語義、計算時點與輸出欄位。
   - 是曝險分析、曝險序列打散對照、報酬分析的前置依賴。

4. `回測核心模組開發指導.md`
   - 定義底層共用回測核心。
   - 供回測頁、參數搜尋、隨機對照、報酬分析等功能共同調用。

5. `標準化回測結果保存機制開發指導.md`
   - 定義回測結果保存、去重、重用與跳轉機制。
   - 讓回測結果可被報酬分析與對照任務重複引用。

6. `報酬分析共用模組開發指導.md`
   - 定義基準相對績效指標、日/週/月報酬分佈、日報酬累加走勢、最長水下期、Sortino、自選基準 Beta、曝險相關指標等分析。
   - 是共用模組，不是獨立頁面。

7. `隨機參數與無意義規則對照系統開發指導.md`
   - 定義隨機參數、無意義規則、曝險序列打散對照、任務保存與結果重用。
   - 是獨立頁面，預計放在回測頁下一個。

8. `計算任務與快取掃描工具開發指導.md`
   - 定義所有大量計算型研究功能的原子任務、複合研究任務、按需計算、總計算量、進度、取消、快取與低功耗視覺化規則。
   - 對應 I，並作為 D、J、H、K、M 等功能的共通操作契約。

9. `長週期風險濾網與過濾模型開發指導.md`
   - 定義 N 月線下彎濾網、實務模型與過濾模型分離、濾網平倉與重新建倉規則。
   - 對應 D。

10. `參數穩健區域分析開發指導.md`
   - 定義一維曲線、二維 heatmap、3D 曲面、多尺度鄰域、多維抽樣、疊圖、穩健區域與高原中心提案。
   - 對應 J。

11. `動態適應參數機制開發指導.md`
   - 定義 1 日 / 20 日預測、上下行空間聯合分佈、六種結構狀態、兩條模型路線、連續動態與六狀態參數政策。
   - 對應 K；規格已確認，完整參數研究由 M 統籌。

12. `參數績效地形研究與穩健候選產生系統開發指導.md`
   - 定義不可變研究設定、Sobol 與完整枚舉、局部細化、績效地形、穩健區域、代理提案、跨設定比較、候選、參數庫銜接及舊系統退場。
   - 對應 M；完整規格已確認，包含資料模型、API、UI、遷移、測試與完成判準。

13. `參數績效地形研究與穩健候選產生系統討論稿.md`
   - 保存 M 的討論脈絡與逐項決策。
   - 討論已完成；後續實作以正式開發指導為準。

14. `擾動行情資料產生器開發指導.md`
   - 定義來源快照、四座標對數擾動、確定性 seed、多尺度版本、批次回測、seed 分佈、G 按需分析與 M 候選驗證連結。
   - 對應 L；完整規格已確認，包含資料模型、API、UI、任務恢復、測試及完成判準。

15. `擾動行情資料產生器討論稿.md`
   - 保存 L 的研究定位與 5 個決策單元。
   - 討論已完成；後續實作以正式開發指導為準。

16. `K線片段重組行情產生器開發指導.md`
   - 定義人工片段選取、裁切、重排、重複、跨商品同週期組合、首日跳空銜接、新日期映射、預覽及不可變實體行情版本。
   - 對應 E；不包含自動分段、自動研究或 M 研究編排。

17. `參數可獲利K線樣貌反推系統開發指導.md`
   - 定義固定一組參數後，以 CVT-MOME 數值搜尋可獲利合成 K 線，並分析 W/H 行為特徵、完整路徑距離、A/B 覆蓋、局部失敗邊界及生成血緣。
   - 對應 C；完整規格已確認，不是歷史獲利片段蒐集、K 線型態下單或參數搜尋。

18. `通用研究結果與參數比較工具開發指導.md`
   - 定義參數矩陣、既有研究成果面板、逐資料區塊四級相容規則、固定版本引用、比較工作區保存與低功耗延遲載入。
   - 對應 N；完整規格已確認，是獨立唯讀工具，不重新計算、不修改來源，也不取代 M 的受控 `ResearchSeries`。

19. `研究功能整體開發順序與驗收清單.md`
   - 統一管理 P00 至 P16 的正式實作順序、循環依賴收口、部分完成邊界、舊系統退場與逐步驗收。
   - 是本資料夾唯一的跨模組開發排程；各功能行為及公式仍以個別開發指導文件為準。

## 正式開發順序

正式順序、硬依賴、整合關卡、每步完成條件與總進度只維護於：

```text
docs/研究構想整理/研究功能整體開發順序與驗收清單.md
```

高層順序固定為：

1. 鎖定既有回測基線及已結案問題的回歸保護。
2. 完成每日實際持倉、共用回測核心、標準化結果、G 與 I。
3. 完成 E 核心、D、J 與 K 核心。
4. 建立 M 主系統，逐項接入 H、C、L、K 與 E/L 雙向來源。
5. M 與既有參數搜尋是獨立研究工作流；依 2026-07-23 使用者決策，既有參數搜尋必須保留，不因 M 完整驗收而退場。
6. 所有來源介面完成後才建立 N。
7. 最後執行全系統驗收，經使用者核准後才同步三份穩定真源。

README 不另維護第二套詳細依賴表，避免與正式順序文件及個別完成判準漂移。
