# 參數搜尋雙演算法與逐層格點搜尋開發指導

> 封存狀態：已撤回，不得作為目前或後續實作依據。
>
> 撤回原因：目前逐層格點實作沒有建立可驗證、可持續的完整搜尋狀態，並與已撤回的市場區間候選結構耦合。
>
> 後續依據：`../參數搜尋退版與功能恢復開發指導.md`。若未來重新研究有序枚舉，必須另立新討論稿，不得直接續修本方案。

## 目的

參數搜尋必須同時保留既有 GA 演化搜尋與新增的逐層完整格點搜尋；預設採用後者。
任何候選在送入回測前均須完成跨任務去重。不得以未揭露的候選數上限、隨機退回或裁切市場資料判定值改變搜尋空間。

## 搜尋演算法

- `layered_grid`：預設。以目前中心候選為基準，維護各有效核心參數的離散區間。每輪只擴張一個參數的一側界線，僅列舉新增加的切片；原先已算組合不得重算。
- `genetic`：保留既有交叉與變異流程，作為使用者可選的替代方法。

## 逐層完整格點搜尋

1. 每個有效核心參數都有明示的中心值、步長與目前下／上界。
2. 目前區間內的候選組合必須依固定順序完整列舉；候選量可分批進入回測，但不可跳過。
3. 一次只擴張一個參數的一側界線，並只列舉該次新增切片。
4. 局部搜尋與未知區域搜尋同時存在，兩者比例為使用者可見設定；未知區域同樣使用有序格點／區塊，不得退回隨機抽樣。
5. 每一輪以同一評分語義比較結果；較佳候選自動更新後續局部搜尋中心。
6. 中心更新只能在目前切片完整列舉後生效；不得因新最佳出現而清空或跳過尚未完成的切片。
7. 候選預約必須分批寫入同一資料庫交易，避免候選量大時超過資料庫單一命令參數上限。

## 市場內涵資料區間

- 不得設置固定的區間組合／參數包數量上限。
- 不得因組合數量刪除任何市場資料判定值。
- 判定值使用原始市場資料的候選格點；原始數值不可標準化、轉換或被強制四捨五入到核心參數的 0.05 步長。
- 僅對訓練資料實際出現、需評估的區間組合建立狀態參數；狀態參數為 Gamma、三項權重、強制滿倉門檻與強制空倉門檻。

## 冠軍繼承與連續搜尋

- 「繼承同標的冠軍」必須明確區分資金設定繼承與參數候選繼承。
- 參數候選繼承以同搜尋語義的最佳候選為中心；連續搜尋完成一輪後，若新候選較佳，下一輪自動採用。
- 使用者不得需要手動重新選擇新的起始基因。
- 多行情繼承必須比對完整行情集合、各行情資料源及各自起迄範圍，不得只憑第一張行情誤用其他搜尋的冠軍。

## 去重身分

- 同設定跨任務去重身分必須包含實際評估行情資料內容的版本雜湊與評分語義版本。
- 多行情模式不得把上方單行情研究標的或其隱藏日期帶入去重身分。
- 某市場內涵資料使用零個判定值時，其窗口不構成候選差異，也不得消耗運算。

## 透明度

UI 必須顯示搜尋演算法、有效參數、步長、區間邊界、局部／未知探索比例、已完成／待完成候選數與去重狀態。不得把「最大可用欄位」誤標成已實際演化。
