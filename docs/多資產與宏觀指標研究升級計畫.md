# 單商品多參考指標研究架構計畫

**文件定位：** 本文件是「單交易商品 + 無/一/多參考指標」重大更新的獨立開發計畫與架構規格，不是三份真源文件。未經使用者確認的指標公式、特徵轉換、參數搜尋邏輯、權重聚合方法，不得寫入三份真源文件，也不得在程式中臨場發明。

**本階段狀態：** 一次到位建立架構骨架，不做 MVP 式假演算法。

## 1. 本階段完成定義

本階段只完成可擴充骨架：

- 支援研究資料集定義：一個主交易商品，搭配零個、一個或多個參考指標。
- 支援不同週期資料對齊，不強制主商品與參考指標同週期。
- 支援缺值策略選項：保留空值、延續前值、線性插值。
- 新增獨立「研究資料集」頁，位於「研究資料」下一個導覽順位。
- 後端提供資料集預覽 API，顯示對齊後筆數、序列起訖、缺值與補值統計。
- 參數搜尋若選了參考指標但尚未選擇已確認的指標演算法，必須禁止開始搜尋並顯示提示。
- 文件明確列出未來會被參數搜尋的值、標準、權重、核心參數保留位。

本階段不做：

- 不新增任何指標市場狀態判斷公式。
- 不新增任何 `IndicatorSignal` 計算公式。
- 不新增 z-score、百分位、斜率、均線偏離、比值或 spread 等未確認特徵。
- 不改變既有單商品、零參考指標時的參數搜尋、回測、市場狀態計算結果。
- 不做多交易商品配置。

## 2. 名詞

| 名稱 | 定義 |
|---|---|
| 主交易商品 | 本次研究要產生目標權重的商品，例如 SOXL。 |
| 參考指標 | 提供市場背景資訊但不直接交易的序列。可以是商品價格、指數、ETF、利率、經濟數據或衍生序列。 |
| 研究資料集 | 主交易商品與參考指標按決策時間對齊後，供參數搜尋、回測、市場狀態共用的輸入資料。 |
| 資料集建構器 | 只負責讀資料、對齊時間、處理缺值、回報資料品質的內部服務；不負責策略計算。 |
| 指標演算法 | 未來可插入的模組，用來把參考指標轉成市場狀態、MarketBetaMultiplier 或 IndicatorSignal。 |

## 3. 目標權重計算流程草案

此流程是未來完整版應保持的架構方向。本階段只建立資料與接口，不實作第 4、6、7 中尚未確認的指標演算法。

1. 取得帳戶資訊，算出目前總資產、目前主商品倉位比例、可用現金。
2. 取得主商品與零個、一個或多個參考指標資料，依決策時間對齊。
3. 對主商品計算並判斷市場狀態，決定主商品 `MarketBetaMultiplier`。
4. 每個參考指標未來可各自判斷市場狀態；狀態定義由參數搜尋產生。此處為保留位。
5. 主商品與所有參考指標各自有 `MarketBetaMultiplier` 權重。所有 multiplier 與權重皆需大於 `0.01`。有效 `MarketBetaMultiplier` 為加權平均，`EffectiveBeta = Beta * EffectiveMarketBetaMultiplier`。
6. 主商品照既有方式算出 `BaseSignal`。每個參考指標未來可依自己的核心參數與資料算出 `IndicatorSignal`。此處為保留位。
7. `BaseSignal` 與所有 `IndicatorSignal` 各自有正數權重。加權平均後得到 `TotalSignal`。若沒有參考指標，`TotalSignal = BaseSignal`，避免稀釋既有單商品模型。
8. `Exponent = TotalSignal * EffectiveBeta + Gamma * InventoryBias`。其中 `InventoryBias = CurrentWeight - NeutralWeight`，`CurrentWeight` 固定指主交易商品實際總倉位除以總帳戶淨值。
9. `RawTargetWeight = sigmoid(Exponent)`，代表基準模型想投入主交易商品的總資產比例。
10. 套用強制空倉、強制滿倉門檻，得到門檻後目標權重。
11. 門檻後目標權重與目前實務模型目標權重比較；差距大於等於調倉門檻時更新實務模型目標權重，否則延續前值。
12. 依執行假設，在當日收盤或隔日開盤調倉。

## 4. 資料集建構器規格

### 4.1 輸入

- 主交易商品 ID。
- 主商品資料週期。
- 參考指標清單，可為空。
- 每個參考指標的資料週期。
- 資料起訖日期。
- 缺值策略：
  - `empty`：保留空值，不補資料。
  - `forward_fill`：延續前值。
  - `linear`：線性插值。

### 4.2 輸出

- 主商品資料摘要。
- 每個參考指標資料摘要。
- 對齊後時間點數。
- 每個序列的原始筆數、對齊後可用筆數、缺值筆數、補值筆數。
- 資料集是否可供搜尋。
- 若不可搜尋，原因必須明確。

### 4.3 限制

資料集建構器不得：

- 計算市場狀態。
- 計算 Signal。
- 決定目標權重。
- 新增或套用任何未確認的指標公式。
- 在策略核心內做 I/O、資料庫或網路行為。

## 5. 參數搜尋禁止規則

零個參考指標時：

- 沿用既有單商品搜尋邏輯。
- 不應改變既有結果。

一個或多個參考指標時：

- 若沒有選擇已確認、已實作的指標演算法，禁止開始搜尋。
- UI 必須提示：已建立參考指標資料集，但尚未啟用任何指標演算法，因此不能開始搜尋。
- 禁止為了讓搜尋能跑而臨時把指標平均、標準化或壓成單一訊號。

## 6. 未來可被參數搜尋的值與保留位

以下欄位是未來可擴充的參數搜尋空間。尚未確認前不得實作成有效演算法。

### 6.1 市場狀態相關

| 保留位 | 對象 | 約束 | 說明 |
|---|---|---|---|
| `indicator_state_rule` | 每個參考指標 | 待定 | 定義參考指標如何分成市場狀態。 |
| `indicator_market_beta_multiplier` | 每個參考指標狀態 | `> 0.01` | 參考指標狀態對 beta 敏感度的影響。 |
| `indicator_market_beta_weight` | 主商品與每個參考指標 | `> 0.01` | 用於加權平均有效 `MarketBetaMultiplier`。 |

### 6.2 訊號相關

| 保留位 | 對象 | 約束 | 說明 |
|---|---|---|---|
| `indicator_signal_rule` | 每個參考指標 | 待定 | 定義參考指標如何產生 `IndicatorSignal`。 |
| `indicator_signal_params` | 每個參考指標 | 待定 | 指標訊號公式需要的核心參數集合。 |
| `base_signal_weight` | 主商品 | `> 0` | 主商品 `BaseSignal` 在 `TotalSignal` 中的權重。 |
| `indicator_signal_weight` | 每個參考指標 | `> 0` | 指標訊號在 `TotalSignal` 中的權重。 |

### 6.3 聚合與防過擬合

| 保留位 | 對象 | 約束 | 說明 |
|---|---|---|---|
| `max_enabled_indicators` | 任務 | 待定 | 限制同一任務啟用的參考指標數量。 |
| `indicator_complexity_penalty` | 任務 | `>= 0` | 每啟用一個參考指標或特徵時的評分懲罰。 |
| `indicator_group_limit` | 任務 | 待定 | 同類指標數量限制，例如利率類最多幾個。 |
| `indicator_missing_policy` | 每個指標 | enum | 缺值策略可被任務記錄，但是否納入演化待定。 |

### 6.4 既有核心參數互動

以下既有核心參數仍屬主商品目標權重流程：

- `Beta`
- `Gamma`
- `WMean`
- `WMomentum`
- `WBreakout`
- `RebalanceThreshold`
- `ForceFullThreshold`
- `ForceEmptyThreshold`
- `MicroReservePct`
- `WedgeDeltaThreshold`
- `WedgeVolRatioThreshold`

未來任何參考指標演算法若要新增核心參數，必須在本文件新增名稱、範圍、預設值、是否可演化、是否影響既有零指標結果。

## 7. UI 位置

新增頁面：

- 名稱：研究資料集。
- 導覽位置：研究資料下一個順位。
- 功能：建立與預覽資料集，不負責匯入行情，不負責啟動搜尋。

頁面必須顯示：

- 主商品與週期。
- 參考指標清單，可為空。
- 每個參考指標的週期。
- 缺值策略。
- 對齊結果與資料品質。
- 若參考指標數量大於零，且沒有已確認指標演算法，顯示禁止搜尋原因。

## 8. 回歸要求

- 零參考指標時，既有參數搜尋、回測、市場狀態不得改變。
- 所有新增 API 與 UI 只能提供資料集預覽，不得影響既有策略計算。
- 測試至少涵蓋：
  - 零參考指標資料集。
  - 一個參考指標且同週期。
  - 一個參考指標且不同週期。
  - 缺值策略 `empty`、`forward_fill`、`linear`。
  - 選參考指標但無演算法時禁止搜尋。
