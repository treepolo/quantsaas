# 策略數學引擎

**文件目標：** 定義 QuantSaaS 策略邏輯的數學規格、`Step()` 輸入輸出契約、資產三態、宏觀 DCA、微觀 Sigmoid 動態天平、底倉釋放規則與可進化參數邊界。

---

## 第 0 章：引擎身份

策略引擎是純函數無狀態轉換器。唯一入口為：

```go
Step(input StrategyInput) StrategyOutput
```

`StrategyInput` 是 SaaS 在 cron tick 外圈構造出的完整快照，包含價格序列、時間戳、資產狀態、上一輪 runtime 狀態、策略參數、出生點設定與下單精度。`StrategyOutput` 只描述交易意圖、帳本語義轉換與新的 runtime 狀態，不直接呼叫交易所。

鐵律如下：回測與實盤共用同一個 `Step()`；`Step()` 內禁止 `if isBacktest`；策略內禁止網路、資料庫、檔案 I/O、計時器與不可控隨機；交易所 API Key 永遠不進入策略輸入。

研究模式可把同一套 `Step()` 套用到不同標的的日 K 序列，但資料降級、交易假設、成交價選擇與標的隔離都必須在外圈 adapter 完成。策略核心不直接讀 `quant.Bar`、不認識資料來源，也不因 `instrument_id` 或 `execution_mode` 分支改寫邏輯。

## 第 1 章：資產結構三態（Portfolio State）

資產以三態表示：

- `DeadBTC`：宏觀底倉，只進不出，代表長期複利水庫。
- `FloatBTC`：微觀浮動倉，可買可賣，供 Sigmoid 動態天平調整權重。
- `ColdSealedBTC`：冷封存資產，永不釋放，不參與任何賣出與底倉轉換。

通用公式如下：

```text
AssetBTC      = DeadBTC + FloatBTC + ColdSealedBTC
TotalEquity   = USDTBalance + AssetBTC × Price
ReserveFloor  = TotalEquity × micro_reserve_pct
SpendableUSDT = max(0, USDTBalance - ReserveFloor)

CurrentMicroWeight = FloatBTC × Price / max(TotalEquity, epsilon)
```

`micro_reserve_pct` 是微觀層資金保留比例，預設 `0.25`，可由 GA 進化。保留資金不是閒置資金，而是風險緩衝與宏觀 DCA 的燃料，避免微觀引擎在短線波動中耗盡可用 USDT。

## 第 2 章：市場狀態感知層

市場狀態感知層把近期行情分為四類：`BULL_TREND`（趨勢牛）、`BEAR_TREND`（趨勢熊）、`QUIET`（安靜態）、`SHOCK`（衝擊態）。分類只使用無量綱特徵。

核心特徵：

```text
LogReturnN      = ln(Close[t] / Close[t-N])
EMADeviation    = Close[t] / EMA(Close, 21) - 1
TrendSlope      = EMA(Close, 21) / EMA(Close, 112) - 1
VolatilityRatio = clip(MAVAbsChange(16) / MAVAbsChange(112), 0.1, 3.0)
DrawdownRatio   = Close[t] / RollingHigh(112) - 1
```

分類規則：

| 狀態 | 判斷邏輯 | 用途 |
|---|---|---|
| `BULL_TREND` | `TrendSlope > 0.03` 且 `LogReturnN > 0` | 宏觀 DCA 降速，微觀偏向保護利潤 |
| `BEAR_TREND` | `TrendSlope < -0.03` 或 `DrawdownRatio < -0.20` | 宏觀 DCA 加速，微觀允許分批吸收 |
| `QUIET` | `VolatilityRatio < 0.75` 且 `abs(EMADeviation) < 0.015` | 微觀粉塵訂單歸零，降低無效交易 |
| `SHOCK` | `VolatilityRatio > 1.8` 或單根絕對對數收益超過近期標準差 2.5 倍 | 放大反應係數，但仍受風險邊界限制 |

若多個狀態同時成立，優先級為 `SHOCK → BEAR_TREND → BULL_TREND → QUIET`。分類結果只影響倍率、粉塵過濾與宏觀節奏，不改變 `Step()` 的純函數身份。

## 第 3 章：訊號與目標函數框架

微觀訊號是多個無量綱特徵的線性合成，方向約定為：正值傾向減倉，負值傾向加倉。

```text
MeanReversionX = EMADeviation / max(StdDev(LogReturn, 21), epsilon)
MomentumX      = ln(Close[t] / Close[t-21])
BreakoutX      = Close[t] / RollingHigh(112) - 1

TechSignal = w_mean × MeanReversionX
           + w_momentum × MomentumX
           + w_breakout × BreakoutX
```

此框架保留 MPC（Model Predictive Control）的概念層：策略每次只在當下快照上計算下一步最合理的目標權重，並把長期風險透過狀態、保留資金與底倉釋放規則反映出來，而不是在 `Step()` 內求解多步未來路徑。

GA 的責任是搜尋權重、倍率、閾值與釋放參數，使策略在多時段坩堝中跑贏 Ghost DCA 並控制回撤。GA 不直接改寫策略結構。

目前真源文件未定義 `SJM` 或 P/V/A 三特徵作為正式策略輸入。市場狀態判讀頁第一版只能使用現有 `Diagnostics` 與市場狀態感知層輸出；若未來要導入 P/V/A 或三態感知，必須先補明公式、資料序列、狀態名稱、與現有市場狀態層的關係。

## 第 4 章：宏觀引擎

宏觀引擎負責長期吸入底倉，買入的 BTC 進入 `DEAD_STACK`。它的核心任務不是短線擇時，而是在熊市與低迷期提高吸收速度，在趨勢過熱期降低吸收速度，讓資產池具備長期複利基礎。

每個自然月第一個已完成聚合桶觸發月度 DCA 檢查。可用預算為：

```text
MacroBudget = MonthlyInjectUSDT × MarketRegimeMultiplier
            + max(0, USDTBalance - ReserveFloor - MicroReserveBuffer) × ExtraDeployPct
```

狀態倍率預設：

| 狀態 | `MarketRegimeMultiplier` |
|---|---|
| `BULL_TREND` | 0.60 |
| `QUIET` | 1.00 |
| `BEAR_TREND` | 1.40 |
| `SHOCK` 且價格遠低於 112 期均線 | 1.80 |

宏觀買入需同時滿足：`SpendableUSDT > DustUSD`、未超過實例風險邊界、當月尚未觸發宏觀 DCA。宏觀買入只產生 `BUY / MACRO / DEAD_STACK` 意圖，不產生賣出意圖。

複利發生方式：當總權益成長，`ReserveFloor` 與可投入資金上限同步成長；月度注資與策略收益共同擴大未來可部署資金，底倉成為長期資產水庫，微觀浮倉則在波動中回收或再配置。

## 第 5 章：微觀引擎

微觀引擎使用 Sigmoid 動態天平計算目標浮動倉權重，並透過買賣 `FLOATING` 讓實際權重靠近目標權重。

```text
CurrentWeight  = FloatBTC × Price / TotalEquity
Signal         = TechSignal

EffectiveBeta  = max(0.01, β × MarketBetaMultiplier)
InventoryBias  = clamp(CurrentWeight, 0, 1) - 0.5
Exponent       = EffectiveBeta × Signal + γ × InventoryBias

TargetWeight   = clamp(1 / (1 + e^Exponent), 0, 1)
DeltaWeight    = TargetWeight - CurrentWeight
TheoreticalUSD = DeltaWeight × TotalEquity
```

`MarketBetaMultiplier` 由市場狀態提供：`QUIET=0.65`、`BULL_TREND=1.00`、`BEAR_TREND=1.15`、`SHOCK=1.40`。它只改變反應速度，不改變訊號方向。

粉塵與楔形區過濾：

- `abs(TheoreticalUSD) >= DustUSD`：允許產生微觀訂單。
- `0 < abs(TheoreticalUSD) < DustUSD`：只有非安靜態且滿足楔形突破時，強制最小訂單。
- 楔形突破：`abs(DeltaWeight) >= WedgeDeltaThreshold` 或 `VolatilityRatio >= WedgeVolRatioThreshold`。
- `QUIET` 狀態下，粉塵訂單一律歸零。

買入意圖使用 `BUY / MICRO / FLOATING`，金額不得超過 `SpendableUSDT`。賣出意圖使用 `SELL / MICRO / FLOATING`，數量不得超過可釋放後的浮動倉。

## 第 6 章：`DeadBTC` 釋放規則

底倉釋放是 SaaS 側帳本語義轉換，不是交易命令。釋放只把符合條件的 `DEAD_STACK` lot 轉為 `FLOATING`，讓微觀引擎可以賣出；不向 Agent 下發任何命令。

軟釋放條件：

1. lot 不是 `COLD_SEALED`。
2. lot 年齡大於 `SoftReleaseMonths`。
3. 市場狀態為 `BULL_TREND` 或 `SHOCK` 後恢復，且 `CurrentMicroWeight` 高於目標權重。
4. 釋放量不超過 `DeadBTC × SoftReleasePct`，也不超過微觀賣出缺口。

硬釋放條件：

1. 微觀引擎產生賣出意圖。
2. `FloatBTC` 不足以滿足賣出數量。
3. 非冷封存底倉可補足差額。
4. 釋放量不超過 `DeadBTC × HardReleaseMaxPct`。

`ColdSealedBTC` 在任何情況下不可釋放、不可賣出、不可轉為浮動倉。所有釋放必須寫入審計日誌，並保留原始 lot 成本資訊。

## 第 7 章：可進化參數契約（Chromosome）

染色體只包含可在代內交叉與變異的參數。出生點參數在 Epoch 啟動時凍結，全種群共享，不進入基因組指紋。

### 染色體欄位

| 欄位 | 型別 | 預設 | 邊界 | 語義 |
|---|---:|---:|---:|---|
| `MicroReservePct` | float | 0.25 | [0.10, 0.45] | 微觀層保留資金比例 |
| `Beta` | float | 2.00 | [0.20, 8.00] | Sigmoid 訊號激進係數 |
| `Gamma` | float | 1.00 | [0.00, 5.00] | 倉位均值回歸偏置 |
| `WMean` | float | 1.00 | [-3.00, 3.00] | 均值回歸訊號權重 |
| `WMomentum` | float | -0.50 | [-3.00, 3.00] | 動量訊號權重 |
| `WBreakout` | float | 0.75 | [-3.00, 3.00] | 突破/過熱訊號權重 |
| `DustUSD` | float | 10.10 | [5.00, 25.00] | 最小有效訂單金額 |
| `RebalanceThreshold` | float | 0.00 | [0.00, 0.20] | 實務模型調倉門檻；實務持倉權重與基準模型目標權重差距達門檻才執行微觀調倉 |
| `WedgeDeltaThreshold` | float | 0.04 | [0.01, 0.15] | 楔形區權重突破閾值 |
| `WedgeVolRatioThreshold` | float | 1.60 | [1.10, 2.50] | 楔形區波動突破閾值 |
| `MacroBearMultiplier` | float | 1.40 | [1.00, 2.50] | 熊市宏觀 DCA 加速倍率 |
| `MacroBullMultiplier` | float | 0.60 | [0.20, 1.00] | 牛市宏觀 DCA 降速倍率 |
| `ExtraDeployPct` | float | 0.20 | [0.00, 0.60] | 超額可用 USDT 部署比例 |
| `SoftReleaseMonths` | int | 12 | [3, 36] | 軟釋放最小 lot 年齡 |
| `SoftReleasePct` | float | 0.08 | [0.00, 0.25] | 單次軟釋放上限比例 |
| `HardReleaseMaxPct` | float | 0.15 | [0.00, 0.50] | 單次硬釋放上限比例 |

### 固定常數

| 常數 | 值 | 理由 |
|---|---:|---|
| EMA / 標準差窗長 | 21 根 | 微觀訊號基準，不進化以降低過擬合 |
| VolRatio 短窗 | 16 根 | 楔形過濾分子 |
| VolRatio 長窗 | 112 根 | 楔形過濾分母 |
| Fatal 最大回撤 | 88% | 適應度硬否決 |

### 出生點參數

出生點參數不進入染色體，包含：初始資金、月度注資、冷封存資產、交易對、下單精度、最小下單量、風險偏好、回測起點與使用者資金配置。它們是 Epoch 級上下文，代內不可交叉或變異。

### 結構約束

`MacroBearMultiplier` 必須大於等於 `MacroBullMultiplier`；`DustUSD` 不得低於交易所最小名義金額；`RebalanceThreshold` 為 0 時表示不啟用額外調倉門檻；所有釋放比例必須在 [0, 1]；任何 Clamp 後仍不合法的染色體由 Validate 判定為無效。

### 研究狀態判讀輸出

市場狀態判讀頁可顯示固定 champion 參數套用到最新資料後的診斷值。顯示方式必須由後端提供泛用 schema/value，避免前端硬綁染色體欄位。第一版可顯示：

```text
signal
current_weight
target_weight
delta_weight
volatility_ratio
market_beta
market_trend_slope
market_drawdown
```

若沒有真實持倉資料，目標浮動倉位只能標示為研究估算，不得假裝代表實際資產或交易建議。

研究 UI 需要同時區分兩種目標權重序列：

| 名稱 | 語義 |
|---|---|
| 基準模型 | 從指定起始日以空倉與指定本金開始，逐日呼叫同一套 `Step()` 所取得的理論目標。`Step()` 原始輸出仍是目標浮動倉位；研究 UI 顯示時必須加上當下宏觀底倉與封存資產曝險，轉成總倉位比例。此序列代表模型想要的總資產曝險，不代表實務上一定成交後的持倉水位。 |
| 實務模型 | 以基準模型每日輸出的目標浮動倉位作為理論微觀目標，但只有當實務模型目前浮動持倉權重與該微觀目標權重的絕對差距大於等於 `RebalanceThreshold` 時，才在指定 `execution_mode` 的執行時間進行微觀調倉並抹平差距。宏觀 DCA 不受此門檻阻擋。研究回測與參數搜尋的策略績效以實務模型淨值曲線為準；實務模型目標權重序列指調倉門檻後實際採用的總倉位目標。若未觸發調倉門檻，實務模型目標權重沿用前一次採用值，不得因價格漂移或實際持倉比例變化而自行改變。 |
| 空倉參考 | 每一日獨立假設當下帳戶為全現金、浮動倉位為 0，只用截至該日的已完成價格序列呼叫 `Step()`，取得「若昨日為空倉，今日參考目標權重」。因此參考輸出沒有既有宏觀底倉可加總，但 UI 欄位語義仍是總倉位比例。此序列不得混同為實際持倉路徑。 |

上述三種序列的「每日變化」皆定義為：

```text
TargetWeightChange[t] = TargetWeight[t] - TargetWeight[t-1]
```

第一筆沒有前值時，變化值為 0。前端可顯示實務模型、基準模型與空倉參考的每日值、每日變化值，但計算必須由後端以策略輸出產生，不得在前端重建策略公式。所有圖表與 tooltip 顯示的目標權重皆使用總倉位比例；調倉門檻判斷仍使用微觀浮動倉權重差距。
