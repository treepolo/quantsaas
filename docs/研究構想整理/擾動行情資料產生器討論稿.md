# 擾動行情資料產生器討論稿

> 狀態：L 全部 5 個決策單元已確認；討論完成，正式實作以開發指導文件為準
>
> 對應大點：L. 擾動行情資料產生器
>
> 用途：保存 L 的研究定位與逐項決策脈絡。本文件不是三份穩定真源；完整實作契約見 `docs/研究構想整理/擾動行情資料產生器開發指導.md`。

## 一、研究定位

L 將既有行情轉成小幅、可重現且合法的衍生 OHLC 資料，用來檢查同一參數或候選是否只對歷史行情的微小細節成立。

L 是局部資料敏感度壓力測試：

- 可以提供參數抗過擬合與資料容錯能力的研究證據。
- 不能單獨證明參數沒有過擬合。
- 不建立系統及格線或自動採用／淘汰規則。
- 不屬於已取消的 F，不以 Monte Carlo 或 bootstrap 命名或實作。
- 不使用相似歷史行情檢索。

## 二、相關研究定位

現有研究存在四個相鄰方向，但沒有一套公認標準，直接等同本專案的「既有 OHLC 附近小幅擾動後，重新回測規則策略」：

- 金融時間序列 jittering 與資料增強主要服務模型訓練，不是策略穩健性判定。參考：[Fons et al., Evaluating Data Augmentation for Financial Time Series Classification](https://arxiv.org/abs/2010.15111)。
- 金融 market generator 生成完整替代行情並要求保存報酬分佈、跨資產依賴與時間自相關，範圍比 L 大。參考：[Lezmi et al., Improving the Robustness of Trading Strategy Backtesting with Boltzmann Machines and Generative Adversarial Networks](https://arxiv.org/abs/2007.04838)。
- surrogate data testing 先指定虛無假設，再生成符合該假設的資料；它不等於局部微擾。參考：[Theiler et al., Testing for nonlinearity in time series: the method of surrogate data](https://www.sciencedirect.com/science/article/abs/pii/016727899290102S)。
- adversarial perturbation 刻意尋找最能破壞模型的方向，可證明微小變動可能造成模型脆弱，但不適合作為 L 的預設隨機擾動。參考：[Nehemya et al., Taking Over the Stock Market: Adversarial Perturbations Against Algorithmic Traders](https://arxiv.org/abs/2010.09246)。

因此 L 採可解釋、可重現、非目標導向的局部擾動，不宣稱為替代市場分佈，也不把針對受測策略最佳化的攻擊當成一般行情樣本。

## 三、固定討論範圍

L 只包含下列 5 個決策單元：

1. 擾動對象及必須保持的資料結構。
2. 噪音分佈與擾動幅度尺度。
3. 時間連續性及合法 OHLC 的邊界處理。
4. seed、版本、資料保存、重用與行情產生器整合。
5. 批次測試、結果顯示及 M 候選連結。

不得在討論過程中臨時增加未列入的新系統；若發現真正會改變 L 語義的新問題，必須先說明衝突並更新本清單。

## 四、已確認：四座標擾動表示

不得直接對原始 O、H、L、C 四個絕對價格各自加噪音，也不得只把整根 K 線上下平移。

每根 K 線先轉成四個 log 座標：

```text
m(t) = (ln(Open(t)) + ln(Close(t))) / 2
b(t) = ln(Close(t) / Open(t))
u(t) = ln(High(t) / max(Open(t), Close(t)))
d(t) = ln(min(Open(t), Close(t)) / Low(t))
```

語義：

- `m`：K 線價格中心。
- `b`：有方向的開收盤實體。
- `u`：非負上影線尺度。
- `d`：非負下影線尺度。

擾動後以同一組座標重建：

```text
Open'(t)  = exp(m'(t) - b'(t) / 2)
Close'(t) = exp(m'(t) + b'(t) / 2)
High'(t)  = max(Open'(t), Close'(t)) * exp(u'(t))
Low'(t)   = min(Open'(t), Close'(t)) / exp(d'(t))
```

`u'` 與 `d'` 必須非負，因此重建結果天然符合：

```text
High' >= max(Open', Close')
Low' <= min(Open', Close')
Open', High', Low', Close' > 0
```

使用 log 是座標轉換，使相同百分比變化在不同價格水準具有相同尺度，並不是修改策略的價格公式或圖表刻度。

## 五、已確認：不變資料

每份擾動資料都是來源資料的獨立衍生版本；原始資料永不覆寫。下列內容固定不擾動：

- 日期、K 線順序與市場日曆。
- 商品、資料來源與週期。
- 成交量與公司行動 metadata。
- 缺值位置。
- 原始行情內容與來源 hash。

不得刪除、複製或重排 K 線。資料正規化或公司行動處理必須先由既有行情資料層完成，L 只接收語義一致且可合法轉換的 OHLC。

## 六、已確認：噪音分佈與擾動幅度

### 6.1 局部活動尺度

每根來源 K 線使用對數真實波幅作為局部活動尺度：

```text
s(t) = max(
  ln(High(t) / Low(t)),
  abs(ln(High(t) / Close(t-1))),
  abs(ln(Low(t) / Close(t-1)))
)
```

第一根資料沒有前收盤價時，使用：

```text
s(t) = ln(High(t) / Low(t))
```

這個尺度同時涵蓋盤中高低波幅與相對前收盤的跳空，而且不依賴任意滾動視窗。`s(t) = 0` 時該根 K 線保持不變，不得憑空製造波動。尺度只由原始來源 K 線計算，不得由前一份擾動結果反覆推導。

L 是在完整來源歷史附近建立反事實資料，不是線上預測特徵；因此以當根完整來源 K 線衡量局部擾動尺度，不構成策略執行時的未來資料洩漏。

### 6.2 有界對稱三角分佈

每個基礎亂數使用：

```text
z = U1 - U2
U1, U2 ~ Uniform(0, 1)
```

因此 `z` 位於 `[-1, 1]`，平均值為零、上下方向機率相同，小幅擾動比接近邊界的擾動常見，而且具有硬上限。不得以無界 Gaussian 噪音作為 L 的預設分佈。

### 6.3 無單位幅度參數

四座標的基礎擾動量定義為：

```text
delta(k,t) = alpha * s(t) * z(k,t)
```

其中 `k` 對應 `m、b、u、d`；`alpha` 是無單位擾動比例。`alpha = 0.05` 代表單一座標的基礎擾動不超過該根來源 K 線對數真實波幅的 5%，不代表價格直接變動 5%。實際套用方式、時間相關性與非負邊界處理留由第 3 決策單元定義。

### 6.4 多尺度共同亂數場

- 一次研究可輸入多個 `alpha`，不得假定唯一正確幅度。
- 相同 seed 下，各 `alpha` 必須共用相同的 `z(k,t)`；不同尺度只改變幅度，不改變方向與亂數路徑。
- 不同 seed 代表不同的獨立擾動路徑。
- 系統不得搜尋最有利於受測參數的 `alpha`，也不得自行建立無研究依據的及格線。
- 研究輸出應呈現候選隨擾動幅度增加的退化情形，而不是只保存單一幅度的成敗。

## 七、已確認：時間連續性與合法 OHLC 邊界

### 7.1 逐根錨定原始行情

每根 K 線只在自己的原始位置附近擾動，不得從前一根擾動結果繼續累積：

```text
m'(t) = m(t) + alpha * s(t) * z_m(t)
b'(t) = b(t) + alpha * s(t) * z_b(t)
```

- 不採累積隨機漫步，避免誤差隨時間擴大並改寫原始長期趨勢。
- 不採跨日平滑或人造相關擾動，避免新增任意平滑週期及虛構短期趨勢。
- 各日期的基礎亂數彼此獨立；逐日小幅雜訊本身就是 L 要測試的價格細節敏感度。
- 每日資料允許隔夜跳空，不得強迫 `Open'(t) = Close'(t-1)`。
- 不得把任何擾動資料再作為另一份擾動資料的來源。

由於每天都錨定來源價格，中間誤差不會累積成長期漂移；整段首尾報酬的差異只受首尾有限偏移影響。

### 7.2 非負影線的對稱幅度限制

不得用 `max(0, value)` 截斷，也不得取絕對值反射非法結果。上下影線改用原始影線長度限制可用擾動幅度：

```text
limit_u(t) = min(alpha * s(t), u(t))
limit_d(t) = min(alpha * s(t), d(t))

u'(t) = u(t) + limit_u(t) * z_u(t)
d'(t) = d(t) + limit_d(t) * z_d(t)
```

因此上下擾動仍以原值為中心且機率對稱，`u'`、`d'` 天然非負。原本為零的影線保持為零；接近十字線的 `b` 則允許因局部擾動改變開收盤方向。

### 7.3 重建與驗證

完成擾動後，必須以第 4 章公式重建並再次驗證：

```text
Open'、High'、Low'、Close' 全部有限且大於 0
High' >= max(Open', Close')
Low' <= min(Open', Close')
```

- 來源 K 線若不符合正值、有限值或合法 OHLC 關係，任務必須失敗並指出日期，不得偷偷修復。
- 產生器內部不得依 UI 顯示位數提前四捨五入；顯示格式不得改變研究資料。
- 原始缺值保持缺值，不得因擾動補值。
- `m` 與 `b` 會共同影響實際開收盤偏移，所以衍生資料 metadata 除 `alpha` 外，還必須保存實際價格偏移的中位數、第 95 百分位與最大值。

## 八、已確認：seed、版本、保存、重用與行情產生器整合

### 8.1 兩層保存結構

L 的保存結構分成「擾動資料群組」與「擾動行情版本」。

擾動資料群組保存：

- 可修改的名稱、備註、標籤及封存狀態。
- 不可修改的來源商品、資料源、週期、日期區間、來源資料快照、來源內容 hash 與擾動演算法版本。
- 建立時必須保存選定範圍的不可變來源資料快照；同群組後續增加 seed 或 `alpha` 時，仍以這份快照計算，不受原研究商品之後重匯或覆蓋影響。

每個 `seed × alpha` 對應一份不可變擾動行情版本，至少保存：

- seed 與 canonical `alpha`。
- 來源快照、演算法版本與產生設定 hash。
- 完整生成 OHLC、生成內容 hash、K 棒數及日期範圍。
- 實際價格偏移中位數、第 95 百分位及最大值。
- 建立狀態與 I 計算任務引用。

來源快照可按內容 hash 去重，但不得只保存來源指標而依賴日後可能改變的即時資料。完整擾動 K 線與產生配方必須同時保存，不能只存 seed 後每次重新計算。

### 8.2 seed 與日期定位亂數

seed 是可保存、可貼回的 64 位種子碼，可由使用者輸入或系統產生；API 與前端必須以字串傳遞，避免 JavaScript 整數精度改變 seed。

不得依賴 Go 預設或遍歷順序相關的全域亂數序列。每個基礎均勻亂數由版本化、依日期定位的函數產生：

```text
U = HashToUnit(
  algorithm_version,
  seed,
  source_series_identity,
  interval,
  open_time,
  coordinate,
  draw_index
)

z = U(draw 0) - U(draw 1)
```

- 同一來源序列、日期、seed、座標及演算法版本必須得到相同亂數。
- 平行順序、執行緒數、取消、續跑及選取區間起點不得改變同一日期的亂數。
- `alpha` 不得進入亂數鍵，確保同 seed 各尺度共用亂數場。
- 來源內容 hash 不進入亂數鍵，使來源修正前後仍可用同 seed 保持方向；來源內容 hash 仍會進入產生設定 hash，兩份資料不會被誤判為同一版本。

`HashToUnit` 的 hash、位元轉換及 `[0,1)` 映射規格必須固定並納入演算法版本；實作不得自行更換後仍沿用舊版號。

### 8.3 三種 hash 與重用

```text
來源內容 hash
= 來源身分 + 日期 + canonical OHLCV + 必要 metadata

產生設定 hash
= 來源內容 hash + 日期範圍 + seed + canonical alpha + 演算法版本

生成內容 hash
= 實際保存的完整衍生 K 線
```

- exact 產生設定 hash 已存在、狀態完整且生成內容 hash 驗證通過時，直接重用，不重新計算。
- 同一群組可繼續加入 seed 或 `alpha`，重複版本自動去重。
- 來源內容改變時建立來源群組新版，不得覆寫舊群組；舊群組仍可基於自己的來源快照擴充。
- 演算法公式、亂數映射或 canonicalization 有任何變化都必須升版，舊資料及舊版計算語義不得被新版覆寫。
- 內容驗證失敗時標記損壞，禁止回測或快取命中，不得靜默修復後冒充原版本。

### 8.4 行情產生器操作

既有行情資料產生器使用互斥模式切換：

- `每日 n 倍做多`。
- `局部行情擾動`。
- `K 線片段重組`（後續 E 已確認，完整規格以 E 開發指導為準）。

L 模式允許合法 Yahoo、Binance 等 OHLC 商品、既有槓桿產生行情，以及後續確認之「不含 L 擾動祖先」的 E 完成版本作為來源；禁止 FRED 單值序列、L 擾動行情及任何含 L 擾動祖先的 E 版本再作為來源。底層每個完成版本仍具有一般研究商品身分，可被研究資料集、回測與參數研究選用；使用者介面按擾動群組折疊整理，商品 ID 與資料代號由設定 hash 自動產生，不要求逐份命名。

目前槓桿產生行情的 `High`／`Low` 僅為開收盤最大／最小值，L 必須明確顯示此來源限制；零影線依已確認規則保持為零，不得捏造原本不存在的盤中路徑。

### 8.5 計算、發布與生命週期

產生前顯示：

```text
來源 K 棒數 × seed 數 × alpha 數
= 衍生版本數與總生成 K 棒數
```

並顯示預估儲存量。所有生成工作調用 I 的共用任務能力，提供總計算量、進度、取消與續跑：

- 每個版本完整寫入並通過內容 hash 驗證後才可發布。
- 已完成版本在群組任務取消後保留，未完成版本不可被研究或回測選用。
- 重新開啟任務只續算缺少的版本或批次；不得重算已驗證版本。
- 已被研究資料集、回測、標準化結果或 M 證據引用的版本不得實體刪除；可封存但既有結果仍能調用。

## 九、已確認：批次測試、結果呈現與 M 候選連結

### 9.1 批次測試單位

一次 L 測試可選一個或多個受測參數，來源可為：

- M 穩健候選。
- 參數庫紀錄。
- 已保存回測結果中的不可變參數快照。
- K 完整模型、狀態規則與動態政策採用單位；不得只取靜態核心參數。

同批受測參數共用同一擾動資料群組、`alpha × seed` 矩陣及所有非參數回測設定。不同策略或不相容回測語義不得混入同一批。正式 manifest 計算量為：

```text
受測參數數 P × (原始來源快照 1 + alpha 數 A × seed 數 S)
```

開始前顯示總回測數、快取命中、實算數與預估時間；啟動後 manifest 不可修改。

### 9.2 回測語義

每個受測參數先在群組的原始來源快照回測一次，作為 `alpha = 0` 基準，再於每份擾動行情回測。所有資料成員必須固定相同日期區間、execution mode、初始資金、現金流、成本、交易規則、D 濾網、策略版本、回測核心版本與 K 完整版本化輸入。

每份擾動行情都以自己的價格重新計算 DCA，不能共用原始行情的 DCA。L 只引用標準化回測結果與既有 `backtest_key`，不得另存 NAV 副本。

### 9.3 每個幅度的獨立彙總

每個 `alpha` 分開統計，不把不同幅度混成單一分數。至少輸出：

- 參數與 DCA 的期末 NAV、總報酬及 MaxDD。
- 期末淨值比與 `log 期末淨值比`。
- 最大回撤殘值比與 `log 最大回撤殘值比`。
- 已確認的績效回撤綜合指標。
- 各指標相對原始行情的有方向差值與絕對差值。
- 有效 seed 樣本數、平均值、中位數、標準差、本批最小／最大值、P05、P25、P75 與 P95。
- 同時符合「總報酬贏過 DCA」及「MaxDD 小於 DCA」的樣本數與比例。
- 僅報酬條件失敗、僅回撤條件失敗及兩者皆失敗的數量。

失敗或缺漏回測不進入績效分佈，必須另列並同時顯示有效數／預定數。上述比例只能稱為本批擾動樣本比例，不得稱為未來機率、信賴度或市場情境機率；本批最小值也不得冒充理論最壞情況。

### 9.4 顯示與按需分析

行情資料產生器的「局部行情擾動」工作區包含：

- 以 `alpha` 為 X 軸的幅度敏感度曲線，中位數線、四分位帶及 P05 至 P95 帶。
- 同 seed 跨尺度軌跡。
- `alpha × seed` heatmap。
- 各幅度統計表及逐筆回測表。
- 多參數疊圖或並排比較，但不建立自動總排名。
- 每個資料點與標準化回測結果、已存在 G 報酬分析的雙向跳轉。

圖表只讀保存結果，切換不重新回測；採低功耗 2D、無自動動畫且不可見時停止繪製。G 的日／週／月分佈、Sortino、Beta 等完整報告不隨 L 自動全算，只有使用者明確啟動時才調用 G，並遵守 I 的總量、進度及取消契約。

### 9.5 保存、續測與 M

每次測試保存不可變設定、受測參數快照、manifest、根 I 任務及標準化回測結果引用。新增 seed 或 `alpha` 時追加新批次並建立新版分析快照；舊快照不改寫。參數或回測設定改變時必須複製為新測試。

M 候選與 L 中該受測參數結果建立雙向連結。同批多個 M 候選各自連到自己的結果。L 不設定整批及格線，不自動採用、淘汰或 Promote。

I 允許取消並保留部分有效結果，因此 M 候選驗證狀態補充「部分完成」與「已取消」；不得把取消冒充失敗，也不得把不完整 manifest 顯示成完整驗證。續跑後依實際狀態更新。

### 9.6 固定依賴順序

```text
來源快照、hash 與血緣
→ 擾動數學核心及確定性測試
→ I 生成任務與版本保存
→ 標準化回測批次
→ 統計與圖表
→ G 按需分析
→ M 雙向驗證連結
```

## 十、討論完成
