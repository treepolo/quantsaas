# 報酬分析共用模組開發指導

> 狀態：P04 已完成；共用分析、保存、API 與回測／參數頁接線已驗收，M、L、C 與 N 於各自階段依本文件契約接用
>
> 用途：定義可被回測頁、參數搜尋頁、隨機對照頁、M 候選、L 擾動測試、C 生成行情結果與 N 唯讀比較共同調用的報酬分析模組。此文件不是三份真源文件，不取代既有穩定系統規格。

## 一、系統定位

報酬分析共用模組負責回答：

```text
這條 NAV / 報酬序列長什麼樣？風險與曝險特徵如何？
```

它不是回測核心，不負責下單、成交、調倉或 NAV 模擬。

它只吃標準化回測結果，產生報酬分析報告。

## 二、依賴關係

此模組依賴：

```text
docs/研究構想整理/回測核心模組開發指導.md
docs/研究構想整理/標準化回測結果保存機制開發指導.md
docs/研究構想整理/每日實際持倉計算機制開發指導.md
```

原因：

- 回測核心產生回測路徑。
- 標準化回測結果保存機制保存可重用的回測結果。
- 每日實際持倉比例提供曝險分析所需資料。

開發順序上，報酬分析共用模組必須晚於每日實際持倉計算、回測核心模組與標準化回測結果保存機制。

此模組會被下列功能調用：

- 回測頁。
- 參數搜尋頁。
- 隨機參數與無意義規則對照頁。
- 參數穩健區域分析。
- M 參數績效地形研究與候選驗證。
- L 擾動行情批次測試。
- C 參數可獲利 K 線樣貌反推。
- N 通用研究結果與參數比較工具；只讀已存在的報告。

## 三、不是獨立頁面

報酬分析共用模組不是獨立頁面。

它是一個後端分析模組與前端共用視覺元件組合，被需要的頁面調用。

建議調用位置：

```text
回測頁：顯示完整報酬分析。
參數搜尋頁：顯示摘要級報酬分析，不納入評分。
隨機對照頁：用同一套分析結果比較正式參數與對照組。
M 研究任務：按需分析評估點或候選，不改變參數研究評分。
L 擾動測試：按需分析選定 run，不因開啟測試或切換圖表替所有版本自動補算。
C K 線樣貌反推：按需分析選定生成路徑，不替搜尋中的全部路徑建立完整報告。
N 研究比較：只讀使用者加入工作區的既有 PerformanceReport，不建立或補算報告。
```

M 所稱「績效地形」是不同參數向量對應之績效指標在參數空間中的分佈；本模組所稱「報酬分佈」是同一條回測路徑的日、週、月報酬統計。兩者不得混用名稱或資料結構。

## 四、與回測核心分離

報酬分析和回測核心必須分開。

回測核心負責：

```text
K 線 + 參數/規則/曝險序列 → NAV + 實際持倉
```

報酬分析負責：

```text
NAV + 實際持倉 + 可選基準 → 統計指標 + 圖表資料
```

報酬分析不得知道策略如何下單，也不得呼叫策略 `Step()`。

## 五、輸入

報酬分析輸入包含：

- 標準化回測結果 ID。
- NAV 序列。
- 可選基準 NAV 序列，包含 Ghost DCA 或其他指定基準。
- 每日報酬序列。
- 每日實際持倉比例。
- 時間戳。
- 可選 Beta 基準資料。
- 可選無風險利率設定。
- 分析版本。

若輸入缺少 `actual_exposure_weight`，則曝險分析不得視為完成。

## 六、輸出

報酬分析輸出 `PerformanceReport`。

每份報告包含：

- 回測結果 ID。
- 分析設定。
- 分析版本。
- 報酬分佈。
- 基準相對績效指標。
- 日報酬累加走勢。
- 最長水下期。
- Sortino。
- 自選基準 Beta。
- 持倉天數比例。
- 平均實際倉位。
- 曝險調整報酬。
- 圖表資料。
- 摘要指標。

## 七、基準相對績效指標

報酬分析必須納入基準相對績效指標。

主要顯示指標為：

```text
期末淨值比 = 參數期末 NAV / 基準期末 NAV
```

基準預設為 Ghost DCA，但應允許未來由呼叫端指定其他基準。

同時必須輸出 log 版本：

```text
log 期末淨值比 = ln(參數期末 NAV / 基準期末 NAV)
```

`log 期末淨值比` 用於讓跑贏與跑輸在尺度上對稱，也方便分段分析時加總比較。

本模組也必須輸出無現金流版本的年化報酬率：

```text
參數無現金流年化報酬率
基準無現金流年化報酬率
無現金流年化報酬率差 = 參數無現金流年化報酬率 - 基準無現金流年化報酬率
```

若原始回測含有每月注資或其他現金流，年化報酬率不得直接使用含現金流的 NAV 計算。系統應另行產生或引用同條件但無現金流的回測結果計算年化報酬率，並在前端明確標示該年化報酬率來自無現金流版本。

舊式：

```text
參數 ROI - Ghost DCA ROI
```

不得作為報酬分析的主要顯示指標。既有參數搜尋評分可先維持原邏輯；參數搜尋評分修改不是本文件範圍。

## 八、報酬分佈

報酬分析必須支援：

- 每日報酬直方圖。
- 每週報酬直方圖。
- 每月報酬直方圖。

報酬分佈資料至少包含：

- 分箱資料。
- 平均值。
- 中位數。
- 標準差。
- 偏態。
- 峰度。
- 最大值。
- 最小值。
- 分位數。

週與月報酬由 NAV 依時間聚合計算。

## 九、日報酬累加走勢

日報酬累加走勢定義為：

```text
Σ (NAV_t / NAV_(t-1) - 1)
```

此走勢不是實際複利累積報酬。

實際複利累積報酬仍為：

```text
NAV_t / NAV_0 - 1
```

回測頁已有 NAV / 累積報酬概念，因此本模組新增的是日報酬累加走勢，而不是把既有累積報酬當成新增功能。

## 十、最長水下期

名稱固定使用：

```text
最長水下期
```

定義：

```text
NAV 跌破歷史前高後，到重新創高之前的最長持續天數。
```

此指標用來衡量參數最久卡在前高以下多久。

## 十一、Sortino

本模組納入 Sortino。

Sortino 只懲罰下跌波動，用於衡量每承受一單位下行風險得到多少報酬。

本模組不把 Sharpe 作為本次完成品指標。

## 十二、自選基準 Beta

Beta 基準必須可由使用者選擇。

基準可以是：

- 交易標的本身。
- 母標的。
- S&P 500。
- 任一研究標的。

Beta 表示：

```text
參數每日報酬 對 基準每日報酬 的敏感度。
```

若未選擇基準，Beta 可以不計算。

## 十三、曝險分析

本模組納入下列曝險分析：

### 13.1 持倉天數比例

```text
持倉天數比例 = actual_exposure_weight > 0 的天數 / 總天數
```

### 13.2 平均實際倉位

```text
平均實際倉位 = 每日 actual_exposure_weight 的平均
```

### 13.3 曝險調整報酬

```text
曝險調整報酬 = 總報酬 / 平均實際倉位
```

若平均實際倉位為 0，曝險調整報酬為 0 或空值，前端必須明確顯示不可解讀。

## 十四、不納入本模組的項目

本模組不納入：

- 每筆交易分析。
- 連續賺錢天數。
- 連續虧損天數。
- Sharpe 作為本次完成品指標。

ROI、Final Equity、MaxDD 是既有回測指標，可以在報酬分析畫面沿用顯示，但不是本模組新增功能重點。舊式 `參數 ROI - Ghost DCA ROI` 不得作為本模組主要比較語言。

## 十五、報酬分析報告保存

一個標準化回測結果可以有多份報酬分析報告。

關係：

```text
BacktestResult 1 → N PerformanceReport
```

原因是報酬分析可能因下列設定不同而不同：

- Beta 基準。
- 無風險利率。
- 分析版本。
- 時間聚合方式。
- 未來新增指標後補算。

報酬分析報告必須保存：

- PerformanceReport ID。
- BacktestResult ID。
- 分析設定。
- 分析版本。
- 報告 schema 與內容 hash。
- 摘要指標。
- 圖表資料。
- 建立時間。
- 狀態。

## 十六、雙向跳轉

回測結果頁必須能看到：

- 這條回測的基本條件。
- 已產生的報酬分析報告列表。
- 建立新的報酬分析。
- 跳到某份報酬分析報告。

報酬分析報告頁或區塊必須能看到：

- 它引用哪一條標準化回測結果。
- 回測條件摘要。
- 分析設定。
- 分析結果。
- 跳回原始回測結果。

## 十七、參數搜尋頁使用方式

參數搜尋頁可以調用報酬分析摘要。

初期只顯示，不納入評分。

可顯示指標：

- 期末淨值比。
- log 期末淨值比。
- 參數無現金流年化報酬率。
- 基準無現金流年化報酬率。
- 無現金流年化報酬率差。
- Sortino。
- 最長水下期。
- 持倉天數比例。
- 平均實際倉位。
- 曝險調整報酬。

參數搜尋評分修改不是本文件範圍，必須另開文件討論。

### 17.1 M 研究任務使用方式

M 的每個實際評估點都引用標準化回測結果。J 所需的期末淨值比、最大回撤及合格條件可讀取既有摘要或相同底層結果。

完整 `PerformanceReport` 仍是獨立按需計算項目：

- 不要求替參數空間每個評估點自動產生完整日 / 週 / 月報酬分析。
- 使用者可以針對任何評估點補算。
- M 產生的穩健候選應提供明確入口建立完整報酬分析。
- 相同回測結果與相同分析設定必須重用既有 `PerformanceReport`。
- 是否已計算完整報酬分析不得影響該評估點的既有參數搜尋評分。

### 17.2 L 擾動測試使用方式

L 的每個來源快照或擾動版本 run 都引用標準化回測結果。L 自身的 `alpha` 敏感度、seed 分位帶與相對原始行情差值，只讀回測摘要及 L 的版本化統計快照。

完整 `PerformanceReport` 保持按需：

- 使用者可針對單一或明確選取的多個 L run 建立報告。
- 相同 BacktestResult 與分析設定重用既有報告。
- 開啟 L 頁、切換 subject、metric、seed 或 `alpha` 不得自動產生報告。
- 批次補算必須顯示總量、快取命中、進度與取消。
- G 報告是否完成不影響 L 的基礎統計、M 候選狀態或人工採用。

### 17.3 C K 線樣貌反推使用方式

C 的每個實際生成路徑評估都引用標準化回測結果。C 搜尋本身只讀取 `q_rel`、`q_abs` 與結果狀態所需摘要，不要求自動建立完整 `PerformanceReport`。

完整報告保持按需：

- 使用者選定永久保存的 C 路徑後才建立或開啟報告。
- 相同 BacktestResult 與分析設定重用既有報告。
- 切換 C 的 A/B 地圖、特徵軸、cell、anchor 或路徑篩選不得觸發 G。
- G 報告可跳回 C study 與 path；C path 可跳到其回測結果與 G 報告。
- G 是否完成不得影響 C 的搜尋、覆蓋率、血緣或 M 候選狀態。

### 17.4 N 通用研究比較使用方式

N 可以把精確 `PerformanceReport` 版本加入研究結果比較，並透過唯讀比較資料介面按需讀取：

- 報告設定、版本、狀態與內容 hash。
- 關聯 BacktestResult 及完整背景 metadata。
- 基準相對績效指標。
- 日／週／月報酬分佈與描述統計。
- 日報酬累加走勢。
- 最長水下期、Sortino 與自選基準 Beta。
- 持倉天數比例、平均實際倉位與曝險調整報酬。
- 已保存的圖表資料。

規則：

- N 必須固定引用 PerformanceReport ID、分析設定、分析版本與內容 hash。
- 完整圖表資料只在使用者展開對應區塊時讀取。
- BacktestResult 尚無相容 G 報告時，N 只顯示「未計算」及返回來源的入口。
- N 不得提供建立報告、批次補算或變更 Beta／無風險利率設定的動作。
- 不同分析版本、時間聚合、單位或公式不相容時，N 必須顯示原因並禁止共圖。
- N 工作區只保存報告引用與顯示狀態，不複製 `PerformanceReport` payload。
- 封存報告仍可由舊工作區讀取；若來源規則允許硬刪，刪除前必須列出受影響工作區，刪除後由 N 保留缺失 placeholder。

完整 N 契約見：

```text
docs/研究構想整理/通用研究結果與參數比較工具開發指導.md
```

## 十九、完成判準

此模組完成後，至少必須滿足：

- 能從標準化回測結果產生報酬分析報告。
- 能輸出期末淨值比與 log 期末淨值比。
- 能輸出參數與基準的無現金流年化報酬率，以及兩者差值。
- 能輸出日/週/月報酬直方圖資料。
- 能輸出日/週/月報酬分佈的平均值、中位數、標準差、偏態、峰度、最大值、最小值與分位數。
- 能輸出日報酬累加走勢。
- 能計算最長水下期。
- 能計算 Sortino。
- 能依自選基準計算 Beta。
- 能計算持倉天數比例、平均實際倉位、曝險調整報酬。
- 回測頁可調用完整報酬分析。
- 參數搜尋頁可調用摘要報酬分析，且不影響評分。
- M 可按需為評估點與候選調用相同報酬分析，且不把「績效地形」混同為「報酬分佈」。
- L 可按需為選定 run 調用相同報酬分析，不因擾動版本數量自動全算。
- C 可按需為選定生成路徑調用相同報酬分析，不因搜尋路徑數量自動全算。
- 報酬分析報告可保存，並能與標準化回測結果雙向跳轉。
- 已存在的 PerformanceReport 可透過固定版本與內容 hash 提供給 N 按需唯讀比較，且未建立報告時不會由 N 觸發補算。

## 二十、計算任務要求

若報酬分析執行大量補算、M 候選分析、C 路徑分析、批次比較或被其他研究工具批次調用，必須遵守：

- 顯示總計算量。
- 顯示進度。
- 支援取消。
- 可重用已存在的標準化回測結果與報酬分析報告。
- 取消後不得把半成品標示為完成。

完整共通規則見：

```text
docs/研究構想整理/計算任務與快取掃描工具開發指導.md
```

N 不屬於本節的批次調用者。N 只讀既有報告，不得建立 I 任務或觸發上述補算流程。

## 二十一、P04 實作與驗收紀錄

P04 於 2026-07-15 完成。實作直接讀取 P03 標準化回測結果；報酬分析純核心不呼叫策略、不重跑交易，也不含 I/O、時間或資料庫依賴。現行穩定靜態 runner 的完整範圍已完成；P09 未來若產生動態政策結果，必須由 K 提供可重放的有效參數序列，再沿既有無現金流重跑契約接入，不得在 G 內自行推導或假重跑。

### 21.1 已凍結版本

- 分析版本：`p04-analysis-v1`。
- 報告／摘要／圖表 schema：`p04-report-v1`、`p04-summary-v1`、`p04-chart-v1`。
- canonical key／設定：`p04-key-v1`、`p04-settings-v1`。
- 日曆聚合：`utc-calendar-v1`。
- 分佈統計：`population-moments-linear-quantiles-v1`。
- Sortino：`annualized-observed-days-v1`。
- Beta：`aligned-utc-endpoints-covariance-v1`。
- 無現金流年化：`cagr-365.2425-v1`。

### 21.2 計算慣例

- 日報酬取每個 UTC 日最後一個 NAV 端點；週報酬使用 UTC 時間的 ISO week，月報酬使用 UTC 年月。
- 平均值、標準差、偏態及超額峰度採母體動差；中位數與 `p05`、`p25`、`p50`、`p75`、`p95` 採線性分位數。直方圖預設 20 箱，可設定 1 至 100 箱。
- 日報酬累加同時保存算術和 `Σr` 與實際複利 `NAV / NAV_0 - 1`，前端不混用兩者。
- 最長水下期以原始時間戳量測跌破前高至重新創高，未復原區間會明確標記。
- Sortino 由觀測到的 UTC 日報酬頻率年化，先把年無風險利率換算成每觀測期利率；無足夠觀測或無下行偏差時回傳不可用原因。
- Beta 只在策略與自選基準共有的 UTC 日端點間建立同區間報酬，再以共變異數除以基準變異數；不把 BTC 週末與平日基準錯位配對。
- 持倉天數比例與平均實際倉位取 UTC 日端點的 `actual_exposure_weight`；曝險調整報酬使用完整路徑總報酬除以平均實際倉位，零平均曝險時標記不可解讀。
- CAGR 固定使用 365.2425 日；原結果有月注資時，由 P02 runner 以相同資料、參數、成本及 execution mode、僅把月注資設為 0 產生或重用另一條 P03 結果。G 不用含現金流 NAV 計算年化報酬率。

### 21.3 保存、權限與讀取契約

- 使用 GORM model 與 AutoMigrate 建立 `performance_reports`、`performance_report_summaries`、`performance_report_chart_blocks`，沒有 SQL migration。
- canonical analysis key 涵蓋來源結果及無現金流結果的 ID、版本、內容 hash、完整分析設定與 Beta dataset hash；相同 key 併發去重，版本或內容變更不會錯誤重用。
- 報告具有 pending、running、completed、failed、cancelled、invalidated、archived 生命週期；摘要、圖表 manifest、六個圖表 block 及整份報告均有內容 hash 與完整性驗證。
- 摘要可單獨讀取；日／週／月直方圖、日報酬累加、水下期與曝險六個圖表 block 只在展開對應區塊後載入。
- 使用者必須持有引用該標準化結果的 `BacktestRun` 才能讀取或建立報告。不可變結果及相同設定可跨使用者安全重用，但回傳的 run ID 只包含目前使用者自己的紀錄。
- P03 結果的引用報告會列出 G 的來源引用及無現金流年化引用；仍被報告引用的結果不得刪除路徑或硬刪。
- 增量備份格式升為 version 3，會保存 G 報告、摘要、六個圖表 block 及來源／無現金流結果依賴閉包；還原後重新驗證引用與內容 hash。
