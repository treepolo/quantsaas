# 回測核心模組開發指導

> 狀態：已完成；共用核心版本為 `p02-v1`
>
> 用途：定義可被回測頁、既有參數搜尋、M 參數研究、K 動態參數、L 擾動測試、C K 線樣貌反推、隨機對照與報酬分析等功能共同調用的底層回測核心。E 只產生一般研究行情；使用 E 行情時仍由上述既有呼叫者調用本核心，不建立 E 專用回測流程。此文件不是三份真源文件，不取代既有穩定系統規格。

## 一、系統定位

回測核心模組是一個底層共用模組，負責回答：

```text
如果照這個參數、規則或曝險序列執行，帳戶每天會變成什麼樣？
```

它不是頁面，不是 API handler，不是 GA 評分器，也不是報酬分析模組。

回測核心只負責產生標準化回測路徑結果，不負責解讀績效好壞。

## 二、依賴關係

回測核心模組必須產生每日實際持倉比例。

每日實際持倉比例的完整定義見：

```text
docs/研究構想整理/每日實際持倉計算機制開發指導.md
```

回測核心模組完成後，會被下列文件定義的功能依賴：

```text
docs/研究構想整理/標準化回測結果保存機制開發指導.md
docs/研究構想整理/報酬分析共用模組開發指導.md
docs/研究構想整理/隨機參數與無意義規則對照系統開發指導.md
docs/研究構想整理/長週期風險濾網與過濾模型開發指導.md
docs/研究構想整理/參數穩健區域分析開發指導.md
docs/研究構想整理/動態適應參數機制開發指導.md
docs/研究構想整理/參數績效地形研究與穩健候選產生系統開發指導.md
docs/研究構想整理/擾動行情資料產生器開發指導.md
docs/研究構想整理/參數可獲利K線樣貌反推系統開發指導.md
```

開發順序上，回測核心模組必須早於標準化回測結果保存、報酬分析、C、D、H、J、K、L 與 M 的完整落地。

N 通用研究比較不直接依賴或調用回測核心。N 只能讀取已保存的標準化回測結果與既有分析；若來源結果不存在，N 顯示未計算及來源入口，不得藉比較操作建立新回測。

## 三、核心職責

回測核心負責：

- 執行 SigmoidDCA 參數回測。
- 執行使用凍結 K 模型所產生之每日有效參數的 SigmoidDCA 回測。
- 執行無意義規則回測。
- 執行曝險序列重放回測。
- 套用 execution mode。
- 套用手續費與滑價。
- 套用初始資金與每月投入。
- 計算每日 NAV。
- 計算每日實際持倉比例。
- 計算交易次數與成交後狀態。
- 輸出標準化回測結果。

回測核心不負責：

- Sortino。
- Beta。
- 報酬直方圖。
- 最長水下期。
- 參數搜尋評分。
- 對照組百分位比較。
- 前端圖表呈現。

這些項目屬於上層報酬分析或對照比較模組。

## 四、輸入

回測核心的輸入包含：

- K 線資料。
- 標的資訊。
- 週期。
- execution mode。
- 初始資金。
- 每月投入。
- 手續費。
- 滑價。
- position structure。
- 回測起訖時間。
- 回測模式。
- 可選的歷史前綴與正式評估起點。

依回測模式不同，還會輸入：

```text
SigmoidDCA 固定參數回測：參數包 / chromosome / spawn point
SigmoidDCA 動態參數回測：全域基準參數 + 每日有效參數序列或純參數提供器 + 綁定模型與政策 metadata
無意義規則回測：規則類型與規則參數
曝險序列重放回測：每日目標曝險比例序列
```

每日有效參數序列或提供器必須在外圈完成模型載入、特徵計算、預測與狀態判定。回測核心不得自行讀模型檔、資料庫或網路。

純參數提供器的相同輸入必須得到相同輸出，且每個時間點只能使用當時可取得的因果快照。若可預先物化每日有效參數序列，參數研究與回測應優先重用同一份序列及 hash。

## 五、輸出

回測核心輸出標準化 `BacktestResult`。

每個結果至少包含：

- 回測條件摘要。
- 回測路徑。
- 最終資產。
- 總報酬。
- 交易次數。
- 費用/滑價成本摘要。
- 每日實際持倉比例。

每個 NAV point 至少包含：

- 時間。
- 價格。
- 總資產。
- 現金。
- 資產數量。
- 實際持倉比例 `actual_exposure_weight`。
- 模型目標權重。
- 實務目標權重。
- 每日報酬。
- 每日有效核心參數快照，如有使用 K。
- K 結構狀態、occurrence ID、模型與政策版本，如有使用 K。
- 有效參數回退或不可用事件，如有。

若是每天開盤買、收盤賣規則，還必須支援：

```text
intraday_exposure_weight
```

## 六、三種 Runner

回測核心包含三種 runner。

### 6.1 SigmoidDCA Path Runner

用於正式參數、隨機參數、M 研究評估點、L 擾動資料測試、C 生成行情評估與回測頁。

它負責：

- 呼叫 SigmoidDCA `Step()`。
- 在呼叫 `Step()` 前，把該日固定或動態有效參數放入同一個 `StrategyInput` 契約。
- 套用強制滿倉/空倉。
- 套用調倉門檻。
- 套用 execution mode。
- 套用費用與滑價。
- 產生 NAV 與實際持倉比例。

此 runner 必須保持和參數搜尋評分使用的回測語義一致。

C 使用本 runner 時，輸入是一條完整 W＋H 生成行情：

- W 只作為 H 的歷史前綴，不產生成交、成本、現金流或 NAV point。
- H 第一個有效交易日才建立共同起始本金並開始正式執行。
- 參數與 DCA 的每月投入均固定為 0。
- DCA 在 H 使用同一條生成行情作為期初一次投入並持有的基準。
- Backtest Spec 必須同時保存完整 W＋H dataset hash 與 H 的正式評估起訖位置。
- C 不得建立專用 NAV 模擬或簡化損益公式。

使用 K 時：

- K 研究模組負責產生每日有效參數。
- Runner 負責驗證每日參數上下限與跨欄結構限制。
- 無效且無法依 K 規格回退的參數點必須拒絕回測。
- Runner 不得讓模型直接輸出持倉，仍須呼叫同一個 `Step()`。
- M 研究、回測頁與市場狀態判讀必須共用同一有效參數產生契約與 `execution_mode`。

### 6.2 Rule Backtest Runner

用於無意義規則。

它不呼叫策略 `Step()`。

它只根據規則產生每日目標持倉：

```text
0% 或 100%
```

並由共用交易模擬器執行調倉。

支援規則：

- 奇數日買、偶數日賣。
- 偶數日買、奇數日賣。
- 固定 N 日切換持倉。
- 每天開盤買、收盤賣。

### 6.3 Exposure Replay Runner

用於曝險序列打散對照。

它不呼叫策略 `Step()`。

它根據輸入的每日目標曝險比例序列執行回測。

此 runner 允許：

```text
0% 到 100%
```

的部分持倉，因為它要重放正式參數產生的實際持倉比例序列。

## 七、共用交易模擬器

三種 runner 必須共用交易模擬器，不得各自實作買賣與 NAV 邏輯。

共用交易模擬器負責：

- 依目標曝險調整持倉。
- 買入。
- 賣出。
- 套用手續費。
- 套用滑價。
- 處理 Dust / 最小交易額。
- 更新現金與資產數量。
- 產生成交後狀態。

這可避免正式策略、無意義規則與曝險重放算出不同語義的 NAV。

## 八、execution mode 語義

回測核心必須統一管理 execution mode。

### 8.1 close_same_bar

```text
當日收盤產生訊號
→ 當日收盤成交
→ 當日 NAV 使用成交後持倉與收盤價計算
```

### 8.2 close_next_open

```text
第 T 日收盤產生訊號
→ 第 T+1 日開盤成交
→ 第 T+1 日 NAV 使用成交後持倉與第 T+1 日收盤價計算
```

### 8.3 每天開盤買、收盤賣

此規則不使用一般 execution mode。

```text
每根 K 線開盤買到滿倉
每根 K 線收盤賣到空倉
```

日終 `actual_exposure_weight = 0%`，並輸出 `intraday_exposure_weight = 100%`。

## 九、與現有程式的關係

現有回測頁與參數搜尋已共用部分 SigmoidDCA 回測路徑，但尚未形成乾淨獨立的回測核心。

開發此模組時，不應一次性重寫所有業務功能。

目標是逐步把現有共享回測邏輯整理成明確邊界：

```text
上層功能
→ 回測核心
→ 標準化回測結果
```

回測頁、既有參數搜尋、M 參數研究、L 擾動測試、C K 線樣貌反推、隨機對照頁與報酬分析頁不應各自實作 NAV 或交易模擬。

## 十、完成判準

回測核心模組完成後，至少必須滿足：

- 正式參數回測可透過核心 runner 產生與既有回測一致的 NAV。
- 參數搜尋可透過同一核心 runner 取得一致評分來源。
- M 的每個研究評估點可透過同一核心 runner 取得一致回測結果。
- L 可將同一受測參數送入來源快照及各擾動 dataset，並由同一核心 runner 重新計算參數與該 dataset 的 DCA，不建立 L 專用 NAV 模擬。
- C 可將 W 作為不交易的歷史前綴，僅在 H 產生參數與零月投入 DCA 的正式結果，且與回測頁使用同一 runner。
- K 的每日有效參數可透過外圈純提供器送入同一個 `Step()`，不在策略核心新增 I/O 或回測分支。
- K 回測路徑可追溯每日有效參數、狀態、模型版本、政策版本與回退事件。
- 無意義規則可透過 Rule Backtest Runner 產生 NAV。
- 曝險序列可透過 Exposure Replay Runner 產生 NAV。
- 所有 runner 都能輸出 `actual_exposure_weight`。
- 所有 runner 共用交易模擬與費用/滑價邏輯。
- 回測核心不直接計算報酬分析指標。

## 十一、實作紀錄

- 共用核心位於 `internal/backtestcore/`，包含交易模擬器、SigmoidDCA Path Runner、Rule Backtest Runner 與 Exposure Replay Runner。
- `BacktestResult` 路徑已包含現金、資產數量、成交後 `actual_exposure_weight`、盤中曝險、每日報酬、逐點交易摘要、費用與滑價成本摘要。
- 固定參數與 K 外圈純參數提供器使用同一個 `Step()` 路徑；動態參數會驗證單欄上下限、跨欄限制並保存模型、政策、occurrence 與回退 metadata。
- 回測服務、既有參數搜尋／評分、研究狀態模擬與緊急離線包已接到同一核心；既有評分公式未改動。
- C 所需 W 歷史前綴可使用 `history_only`，只向 H 提供歷史，不在 W 產生成交、成本、現金流或 NAV point；Spec 同時支援 dataset hash 與正式評估位置。
- 舊版固定資料集的兩種 execution mode 已建立精確數值回歸測試；共用核心、三種 runner、成本、月投入、position structure、動態參數、歷史前綴與實際持倉邊界均有單元測試。
