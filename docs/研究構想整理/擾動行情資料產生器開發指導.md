## 一、研究目的

L 使用一份既有 OHLC 行情作為來源，在每根 K 線附近建立小幅、合法、可重現且不累積漂移的衍生行情，回答：

```text
同一個參數若只面對原始歷史行情的微小局部變化，
其相對績效、回撤與合格狀態會如何變化？
```

L 是局部資料敏感度壓力測試。它提供參數是否依賴歷史資料微小細節的證據，但不代表：

- 未來行情的機率模型。
- 完整替代市場生成器。
- 對參數「無過擬合」的單獨證明。
- 針對受測參數尋找最差攻擊方向的 adversarial test。
- Monte Carlo、bootstrap 或 surrogate data test。
- 可自動採用或淘汰參數的評分器。

L 的結果由使用者解讀。系統不得建立總及格線、自動 Promote、自動淘汰或跨參數總冠軍。

## 二、相關研究定位

現有研究有數個相鄰方向，但沒有一套公認標準直接等同本專案的「保存既有 OHLC 附近的小幅衍生資料，再重新回測規則型參數」：

- 金融時間序列 jittering 與資料增強主要服務模型訓練，不是規則型參數的穩健性判定。參考：[Fons et al., Evaluating Data Augmentation for Financial Time Series Classification](https://arxiv.org/abs/2010.15111)。
- market generator 生成完整替代行情，通常要求保存報酬分佈、跨資產依賴與時間自相關，範圍比 L 大。參考：[Lezmi et al., Improving the Robustness of Trading Strategy Backtesting with Boltzmann Machines and Generative Adversarial Networks](https://arxiv.org/abs/2007.04838)。
- surrogate data testing 先指定虛無假設，再建立符合該假設的序列，不等於局部微擾。參考：[Theiler et al., Testing for nonlinearity in time series: the method of surrogate data](https://www.sciencedirect.com/science/article/abs/pii/016727899290102S)。
- adversarial perturbation 刻意尋找最能破壞模型的方向，研究問題不同。參考：[Nehemya et al., Taking Over the Stock Market: Adversarial Perturbations Against Algorithmic Traders](https://arxiv.org/abs/2010.09246)。

因此，本文件的三角分佈、對數真實波幅尺度、來源錨定與資料保存方式是本專案為局部敏感度研究建立的可解釋設計，不宣稱為學界統一標準。

## 三、完成品範圍

L 完成品必須同時包含：

1. 行情資料產生器的「局部行情擾動」模式。
2. 不可變來源資料快照與完整資料血緣。
3. 四座標對數擾動數學核心。
4. 有界、確定性且可跨工作執行順序重現的亂數場。
5. 多 seed、多 `alpha` 衍生版本的保存、去重、驗證及重用。
6. 一個或多個受測參數在原始快照與擾動版本上的標準化批次回測。
7. 每個幅度分開保存的 seed 分佈、差值、合格狀態及低功耗圖表。
8. G 報酬分析的按需調用與雙向跳轉。
9. M 候選驗證鏈的雙向連結。
10. I 的精確計算計畫、進度、取消、部分完成、續跑及快取。
11. 完整備份、還原、封存、引用保護與內容完整性稽核。

下列內容不屬於 L：

- 強化或修正槓桿行情產生公式。
- 從沒有影線的來源資料推測盤中路徑。
- 讓行情擾動參與策略執行或實盤決策。
- 將擾動幅度納入參數搜尋評分。
- 自動搜尋最有利或最不利於受測參數的擾動。
- 以平滑、隨機漫步或生成模型建立新的長期市場趨勢。

## 五、系統邊界

### 5.1 資料真源

- Postgres 是來源快照、擾動版本、K 線、任務引用、測試及分析快照的唯一真源。
- Redis 只能保存可重建快取或短期進度，不得成為 seed、版本、血緣或測試結果的唯一來源。
- 所有資料表只由 GORM model 與 AutoMigrate 管理，不建立 SQL migration。
- 交易所或資料商憑證不得進入 L 的資料表、設定、API、前端、日誌或測試 fixture。

### 5.2 純計算與 I/O 分離

擾動數學核心必須是純函數：

```text
來源 K 線快照 + 版本化擾動規格
→ 衍生 K 線 + 偏移統計 + 驗證結果
```

純計算層禁止：

- 資料庫、網路、檔案或時間依賴。
- 使用全域亂數狀態。
- 呼叫策略 `Step()`。
- 根據受測參數績效改變擾動方向。

SaaS service 層負責快照、任務、保存與回測編排；策略核心完全不知道資料來自真實行情、槓桿產生行情或 L 擾動版本。

### 5.3 執行角色

- 建立來源快照、生成擾動版本、執行批次回測及補算 G 報告只在 `lab` 或 `dev` 開放。
- `saas` 可依既有權限讀取已完成結果，但不得啟動寫入型算力任務。
- L 不下發交易命令，不接觸 LocalAgent，也不改變實盤狀態。

## 六、核心使用流程

### 6.1 建立擾動資料群組

```text
選擇來源商品、週期與日期範圍
→ 驗證來源資格與 OHLC
→ 顯示來源 K 棒數、先前收盤資訊及儲存預估
→ 建立不可變來源快照與內容 hash
→ 建立擾動資料群組
```

### 6.2 增加擾動版本

```text
輸入或產生 seed 清單
→ 輸入 alpha 清單
→ 預覽 seed × alpha 唯一版本、快取命中及總 K 棒數
→ 使用者啟動 I 任務
→ 逐版本生成、驗證、保存、計算內容 hash
→ 完整版本才發布成可選研究商品
```

同一群組可以日後加入新 seed 或 `alpha`。所有新增版本永遠使用群組建立時的來源快照，不讀取可能已更新的原商品。

### 6.3 建立擾動測試

```text
選擇一個或多個受測參數
→ 選擇同群組內的 alpha 與 seed
→ 固定非參數回測設定
→ 預覽 P × (1 + A × S)、快取與實算量
→ 啟動批次回測
→ 建立按 alpha 分開的統計快照
→ 視需要補算 G 報告或回連 M 候選
```

## 七、來源資料資格與快照

### 7.1 可用來源

L 可接受：

- Yahoo、Binance 或其他已由研究資料層正規化的合法 OHLC 商品。
- 現有行情產生器建立的每日 n 倍做多資料。
- `completed`、未 `corrupt`，且直接與遞迴來源均不含 L 擾動版本的 E 重組行情完成版本。
- 任一既有合法週期，不把日 K 寫死為唯一週期。

L 拒絕：

- FRED 等 `Open = High = Low = Close` 的單值觀測序列。
- 任一 L 擾動來源快照或擾動版本，禁止擾動套擾動。
- 任何直接或遞迴血緣包含 L 擾動版本的 E 重組行情；不得以 E 包裝方式繞過禁止擾動套擾動。
- 含非有限值、非正價格、重複時間、非遞增時間或非法 OHLC 的資料。
- 來源身分、週期或日期範圍無法唯一解析的資料。

現有槓桿產生器的 `High`／`Low` 只等於產生後開收盤的最大／最小值。L 可以使用這類來源，但必須在來源摘要顯示「沒有原始盤中影線資訊」；零影線依本文件規則維持為零，不能捏造盤中路徑。

### 7.2 來源正規化順序

```text
provider 匯入或已完成的合法 generated artifact
→ 來源自己的既有價格調整、公司行動、版本與完整性驗證
→ 選取來源區間
→ L 建立快照
→ L 擾動
```

L 不自行重做公司行動調整，也不在擾動後再次套用 provider 調整。

### 7.3 快照內容

來源快照至少保存：

- 原商品 ID、資料源、symbol、market、週期。
- 起訖時間、K 棒數與時間順序。
- 選定區間完整 canonical OHLCV。
- 必要公司行動／資料版本 metadata。
- 選定區間第一根之前的來源收盤價及其存在狀態。
- 來源內容 hash、建立時間及快照演算法版本。
- 來源直接與遞迴 artifact kind／內容 hash 血緣，用來證明是否含 L 擾動祖先。
- 一個供回測核心讀取的內部不可變研究商品身分。

第一根之前若有合法來源收盤價，該值只用來計算第一根的真實波幅，不額外成為輸出 K 棒。若不存在，第一根依第 9.1 節退回高低波幅。

### 7.4 不變資料

每個擾動版本必須保持：

- 日期、時間戳、順序、週期與市場日曆。
- 商品來源血緣與選定範圍。
- 成交量與必要公司行動 metadata。
- 原始缺日位置；不得補日、刪日、複製或重排。

若未來儲存格式允許某一 K 棒具有明確缺失 OHLC，L 不得補值；該來源在現有回測契約下應驗證失敗。不存在的日期則維持不存在。

## 八、四座標對數表示

每根合法 K 線先轉成：

```text
m(t) = (ln(Open(t)) + ln(Close(t))) / 2
b(t) = ln(Close(t) / Open(t))
u(t) = ln(High(t) / max(Open(t), Close(t)))
d(t) = ln(min(Open(t), Close(t)) / Low(t))
```

語義：

- `m`：K 線價格中心。
- `b`：有方向的開收盤實體。
- `u`：非負上影線尺度。
- `d`：非負下影線尺度。

重建公式固定為：

```text
Open'(t)  = exp(m'(t) - b'(t) / 2)
Close'(t) = exp(m'(t) + b'(t) / 2)
High'(t)  = max(Open'(t), Close'(t)) * exp(u'(t))
Low'(t)   = min(Open'(t), Close'(t)) / exp(d'(t))
```

使用 log 只是建立無量綱座標。它不改變策略公式、K 線圖價格尺度或回測顯示方式。

不得直接對四個絕對 OHLC 各自加價格噪音，也不得只把整根 K 線上下平移。

## 九、局部活動尺度與噪音

### 9.1 對數真實波幅

每根來源 K 線的活動尺度固定為：

```text
s(t) = max(
  ln(High(t) / Low(t)),
  abs(ln(High(t) / Close(t-1))),
  abs(ln(Low(t) / Close(t-1)))
)
```

若第一根沒有先前來源收盤價：

```text
s(t) = ln(High(t) / Low(t))
```

`s(t)` 同時反映盤中高低幅度及相對前收盤的跳空，不使用日報酬標準差，也不新增任意滾動視窗。`s(t) = 0` 時整根 K 線保持不變。

尺度永遠由來源快照計算，不得使用前一份擾動結果或受測參數結果反覆更新。

### 9.2 三角分佈

每個基礎亂數固定為：

```text
z = U1 - U2
U1, U2 ~ Uniform[0, 1)
```

因此 `z` 有界於 `[-1, 1]`、平均為零、上下方向對稱，而且小幅值比接近邊界的值常見。Gaussian 不作為 L 預設分佈，避免無硬上限的極端值。

### 9.3 幅度參數

`alpha` 是大於零的 canonical 十進位無量綱比例。基礎擾動量為：

```text
delta(k,t) = alpha * s(t) * z(k,t)
```

`alpha = 0.05` 表示單一座標的基礎擾動不超過來源 K 線對數真實波幅的 5%，不代表價格直接變動 5%。

- `alpha = 0` 不建立擾動版本；原始來源快照就是共同基準。
- 重複或數值等價的 `alpha` 經 canonicalization 後只保留一個。
- 不建立沒有研究依據的固定科學上限或系統及格幅度；非有限、非正或造成非法輸出的設定必須拒絕。
- 一次可輸入多個 `alpha`，但不同幅度不得混成單一分佈或總分。

## 十、時間路徑與合法邊界

### 10.1 逐根錨定來源

價格中心與開收盤實體使用：

```text
m'(t) = m(t) + alpha * s(t) * z_m(t)
b'(t) = b(t) + alpha * s(t) * z_b(t)
```

各日期基礎亂數彼此獨立。每根 K 線永遠錨定自己的來源值，禁止：

- 從前一根擾動結果繼續累積。
- 累積隨機漫步。
- 任意跨日平滑或人造相關週期。
- 強迫 `Open'(t) = Close'(t-1)`。

真實每日資料允許隔夜跳空。逐根錨定會增加受控的高頻局部變化，但不會把誤差累積成新的長期趨勢。

### 10.2 上下影線

不得用截斷、取絕對值、反射或重抽非法值修補影線。影線的允許擾動先受來源影線限制：

```text
limit_u(t) = min(alpha * s(t), u(t))
limit_d(t) = min(alpha * s(t), d(t))

u'(t) = u(t) + limit_u(t) * z_u(t)
d'(t) = d(t) + limit_d(t) * z_d(t)
```

結果必然滿足 `u'(t) >= 0`、`d'(t) >= 0`。來源影線為零時保持零；接近十字線的 `b` 則允許因局部擾動改變開收盤方向。

### 10.3 最終驗證

重建後每根 K 線必須滿足：

```text
Open'、High'、Low'、Close' 全部有限且大於 0
High' >= max(Open', Close')
Low' <= min(Open', Close')
時間與來源完全相同
Volume' = Volume
```

內部計算不得依 UI 顯示位數四捨五入。若資料庫儲存精度需要十進位量化，必須使用固定版本的儲存 canonicalization，對所有 OHLC 套用同一單調量化，再重新驗證；輸出 hash 以實際持久化值為準。

任何非有限、溢位或非法結果都使該版本失敗並保存日期與原因，不得偷偷修補或發布部分資料。

## 十一、版本化確定性亂數場

### 11.1 seed 表示

- seed 是 unsigned 64-bit 值。
- API、JSON、資料庫顯示值與前端一律以十進位字串傳遞，避免 JavaScript `Number` 精度損失。
- 使用者可貼入 seed，或由後端使用作業系統安全亂數來源產生；產生後立即保存字串。
- seed 不是密碼，不得與交易所憑證共用來源或儲存位置。

### 11.2 `HashToUnit` v1

L v1 不使用遍歷順序相關的全域 PRNG。每個均勻亂數由 SHA-256 直接定位：

```text
domain = "quantsaas:L:ohlc-log-tr-triangular:v1"

digest = SHA256(
  length_prefixed(domain)
  || uint64_be(seed)
  || length_prefixed(source_instrument_id)
  || length_prefixed(source_data_source)
  || length_prefixed(source_symbol)
  || length_prefixed(interval)
  || int64_be(open_time)
  || uint8(coordinate_id)
  || uint8(draw_index)
)

r = uint64_be(digest[0:8]) >> 11
U = r / 2^53
```

固定座標編號：

```text
m = 0
b = 1
u = 2
d = 3
```

`draw_index` 只允許 `0` 或 `1`，並以兩個 `U` 建立 `z = U0 - U1`。`length_prefixed` 的長度使用固定 unsigned 32-bit big-endian；所有文字先以 UTF-8 編碼。上述任一位元規則改變都必須升演算法版本。

### 11.3 確定性要求

固定來源序列身分、週期、日期、seed、座標及演算法版本時：

- 工作執行緒數不得改變亂數。
- 任務分批、取消、續跑或重啟不得改變亂數。
- 選取區間起點改變時，重疊日期不得改變亂數。
- `alpha` 不進入亂數鍵，因此同 seed 各尺度共用方向。
- 來源內容 hash 不進入亂數鍵，因此來源修正前後使用同 seed 仍保留相同日期方向；兩份產生設定仍因來源 hash 不同而維持不同身分。

同一 seed 可在同一次任務中先物化一份基礎 `z(k,t)` 並供多個 `alpha` 重用，以降低 CPU；此暫存可重建，不能取代 seed 與版本化公式。

## 十二、canonicalization 與 hash

### 12.1 Canonical 規則

所有身分 hash 使用版本化 canonical bytes，不使用 map 原始遍歷順序、未正規化 JSON 或二進位浮點記憶體：

- JSON key 固定排序，缺省值展開成正式值。
- 時間使用 UTC epoch millisecond 的 signed 64-bit 十進位或固定 big-endian 表示。
- seed 使用已驗證的 uint64 字串及固定二進位表示。
- `alpha` 與價格使用無指數、無前導加號、移除非必要尾零、`-0` 正規化為 `0` 的十進位字串。
- K 線依 `open_time` 遞增，欄位順序固定為 `open_time, open, high, low, close, volume, metadata`。
- 空值、缺值與不存在欄位必須有不同 canonical 表示。
- hash 演算法固定為 SHA-256，輸出小寫 hexadecimal。

### 12.2 來源內容 hash

```text
source_content_hash = SHA256(canonical {
  snapshot_schema_version,
  source instrument identity,
  interval,
  start_time,
  end_time,
  previous_close_present,
  previous_close,
  ordered source bars and required metadata
})
```

來源內容 hash 不等同商品 ID，也不等同日期範圍文字。任何實際輸入值改變都必須得到不同 hash。

### 12.3 產生設定 hash

```text
generation_recipe_hash = SHA256(canonical {
  source_content_hash,
  perturbation_algorithm_version,
  seed,
  alpha
})
```

日期範圍已包含在來源快照 hash，不需重複作身分，但 API 摘要仍應顯示。

### 12.4 生成內容 hash

```text
generated_content_hash = SHA256(canonical {
  output_schema_version,
  target instrument identity,
  ordered persisted OHLCV and metadata
})
```

相同 recipe 命中快取前，版本必須是 `completed`，K 棒數、日期邊界與內容 hash 必須通過完整性驗證。hash 不符時標成 `corrupt`，禁止回測、研究資料集選用或快取命中。

### 12.5 測試與分析 hash

L 另外保存：

- `subject_hash`：不可變受測參數或 K 完整模型包。
- `test_spec_hash`：群組、受測參數集合及所有非資料回測設定。
- `test_manifest_hash`：正式 subject × dataset 執行項目及順序。
- `analysis_set_hash`：納入某次統計快照的完成結果 ID、缺漏及分析版本。

新增批次或結果時建立新 `analysis_set_hash`，不得改寫舊分析快照。

## 十三、實際價格偏移統計

`alpha` 描述座標擾動上限，不等於最後 OHLC 偏移。每根 K 線另外計算：

```text
e_open(t)  = abs(ln(Open'(t)  / Open(t)))
e_high(t)  = abs(ln(High'(t)  / High(t)))
e_low(t)   = abs(ln(Low'(t)   / Low(t)))
e_close(t) = abs(ln(Close'(t) / Close(t)))

e_bar(t) = max(e_open(t), e_high(t), e_low(t), e_close(t))
```

每個版本保存：

- `e_bar` 中位數。
- `e_bar` P95。
- `e_bar` 最大值。
- 各 OHLC 欄位自己的最大絕對 log 偏移。

UI 顯示百分比時使用：

```text
percent_deviation = 100 * (exp(e) - 1)
```

保存與 hash 仍使用 log 偏移，不以格式化百分比作身分。

### 14.1 K 線與研究商品

- 每份來源快照與擾動版本都映射到獨立的不可變 `ResearchInstrument + KLine` 資料身分，供既有 loader 與回測核心使用。
- 來源快照是內部基準，不塞入一般商品清單；擾動版本在群組式 selector 中可選，不把數百個 hash 代號平鋪到主要商品頁。
- 底層 instrument ID 與 symbol 由完整 recipe hash 確定性產生；截短顯示不得取代完整 hash 唯一索引，碰撞時必須拒絕或確定性延長，不能覆蓋。
- 所有衍生資料仍使用內部 `generated` data source，但必須額外保存產生種類與 lineage。

現有 `DatasetMetadata.PriceAdjustment` 對 `generated` 目前會推斷成每日槓桿資料。L 實作時不得沿用這個錯誤分類：

- 來源快照使用明確的 snapshot adjustment／artifact kind。
- 擾動版本使用明確的 local perturbation adjustment／artifact kind。
- 舊槓桿資料仍維持既有 `generated_daily_leverage_v1` 語義。
- 不得只靠 `data_source = generated` 判斷產生公式。

### 14.2 狀態與封存分離

快照／版本執行狀態至少包含：

```text
pending
running
completed
failed
cancelled
corrupt
```

測試／批次狀態至少包含：

```text
draft
running
partially_completed
completed
failed
cancelled
```

封存使用獨立 `archived_at` 或等價欄位，不把 `archived` 當成會抹除原執行狀態的替代值。只有 `completed` 且未標記 `corrupt` 的資料 artifact 可以被新回測選用。

## 十五、來源快照與群組生命週期

### 15.1 建立計畫

群組建立前的 plan 必須回傳：

- 解析後來源身分與週期。
- 實際首尾時間及 K 棒數。
- 是否存在區間前一根收盤。
- 來源驗證錯誤及對應日期。
- 來源快照 hash 預覽。
- 預估快照儲存量。
- plan hash 與來源當前版本。

使用者提交建立時，後端必須重新核對 plan hash。來源在 plan 後已改變時拒絕 stale plan，要求重新預覽。

### 15.2 快照發布

快照資料可以分批寫入，但在完整 bar 數、日期邊界及內容 hash 通過前：

- 不得設為 `completed`。
- 不得出現在回測或研究資料 selector。
- 不得讓直接使用 instrument ID 的 loader 繞過狀態檢查。

發布狀態轉換必須在資料庫交易內完成。取消可保留可續跑的部分 row，但這些 row 仍不可見。

### 15.3 原來源變動

群組建立後不再跟隨原商品更新：

- 舊群組繼續使用自己的快照並可加入新版本。
- UI 比較目前原商品 hash 後可顯示「來源已有新版」。
- 使用目前來源建立新研究時，複製群組 metadata 並建立新快照／新群組。
- 不得覆蓋舊來源快照或讓舊測試結果指向新版資料。

## 十六、擾動版本生成任務

### 16.1 輸入

版本生成 plan 接收：

- group ID。
- seed 字串清單，或要求產生的 seed 數量。
- canonical `alpha` 清單。
- 演算法版本；預設固定為群組版本，不允許在同群組切換。

系統先去除：

- 重複 seed。
- canonical 後重複 `alpha`。
- 已存在且完整的 recipe。

### 16.2 精確計算量

```text
unique_variants = unique_seed_count × unique_alpha_count
total_output_bars = source_bar_count × unique_variants
```

plan 必須分別顯示：

- 已存在可重用版本。
- 待生成版本。
- 預估 K 棒寫入數及儲存量。
- 建議上限、硬上限與超限原因。
- 預估時間；無可靠歷史資料時明確顯示未知。

### 16.3 執行與續跑

- 一個群組生成工作是 I 複合任務，每個版本是可獨立重試的原子任務。
- 同一 seed 的四座標亂數場可在該 worker 內計算一次並供所有待生成 `alpha` 重用。
- 生成採固定 `open_time` 順序；分批寫入不得影響結果。
- 每個版本獨立發布，群組任務取消不撤銷已完成版本。
- 重新開啟群組時只補算 pending、failed 或 cancelled 的明確選定版本；corrupt 版本需先執行完整性處理，不能直接當失敗重試覆寫。

### 16.4 冪等與併發

- `generation_recipe_hash` 必須有資料庫唯一約束。
- 相同 recipe 的並行請求收斂到同一版本及任務，不建立兩份 K 線。
- worker 取得版本執行權時使用資料庫鎖或等價原子狀態轉換。
- 重複 HTTP、瀏覽器重送或服務重啟不得新增重複版本。
- 任何寫入失敗都不得刪除其他已完成版本。

## 十七、受測參數與測試設定

### 17.1 受測參數來源

L 接受不可變快照：

- `RobustCandidate` 的指定版本。
- `GeneRecord` 的指定版本／當下內容快照。
- `StandardizedBacktestResult` 所保存的參數快照。

受測參數保存原始引用及完整內容 hash。只保存可變資料 ID 而不保存快照不合格。

K 受測單位必須包括：

- 模型 artifact。
- 預測 schema 與物化預測版本。
- 狀態規則。
- 動態政策與控制模式。
- 核心參數包。
- 回測與回退 metadata。

不得把 K 候選降級成一組靜態核心參數。

### 17.2 同批相容性

同一 L 測試中的多個受測參數必須具有：

- 相同 strategy ID 與相容 strategy contract。
- 相同商品週期及群組來源快照。
- 相同 execution mode、成本、初始資金、現金流、position structure 及 D 濾網。
- 相同回測核心與指標版本。

參數內容或完整 K 模型包可以不同。若上述非參數背景不同，使用者必須建立另一個測試；系統不得自動拆分後仍顯示成同一控制背景批次。

### 17.3 測試不可變設定

測試至少固定：

- group 與 snapshot hash。
- 受測參數集合及各自 subject hash。
- 回測起訖區間；必須落在 snapshot 與所有版本共同覆蓋範圍。
- execution mode、初始資金、現金流、費用、滑價及 DCA 規則。
- position structure、D 濾網與所有 K 版本引用。
- 策略、回測核心、每日實際持倉及指標版本。

名稱、備註、標籤及封存狀態可修改；會影響結果的內容不得修改。

## 十八、批次 manifest 與回測語義

### 18.1 Manifest

選定 `P` 個受測參數、`A` 個幅度及 `S` 個 seed 時：

```text
planned_runs = P × (1 + A × S)
```

每個受測參數在來源快照只回測一次。`alpha = 0` 不依 seed 重複建立原始結果。

開始前必須顯示：

- planned runs。
- 標準化回測快取命中。
- 實際待算 runs。
- 目前不存在或尚未完成的 variant。
- 預估耗時與 I 任務上限。

測試不得暗中生成缺少的行情版本。若 variant 尚未完成，先建立獨立生成計畫並由使用者啟動；完成後再建立固定測試 manifest。

### 18.2 Dataset 與 DCA

每個 run 使用自己的 dataset：

```text
原始 run → 群組來源快照
擾動 run → 指定 seed × alpha 版本
```

參數 NAV 與 Ghost DCA 都必須在同一份 dataset 上重新計算。禁止：

- 將原始 DCA NAV 套到擾動參數 NAV。
- 只擾動參數價格而不擾動基準價格。
- 以不同日期、成本或現金流比較。

每個 run 交由共用回測核心並保存／引用 `StandardizedBacktestResult`。L 不實作第二套 NAV、交易、成本或 DCA 模擬。

### 18.3 Backtest 去重

L-specific metadata 不得無故塞入 `backtest_key`。只有實際改變回測輸入的 dataset hash、subject、回測設定與版本參與底層 key；L test ID、batch ID、顯示名稱及分析設定只屬於上層引用。

相同 dataset、subject 與回測條件已有完成結果時必須重用。失敗、invalidated 或資料已 corrupt 的結果不得快取命中。

## 十九、相對績效與合格定義

每個 run 的參數與該 dataset DCA 產生：

### 19.1 期末淨值比

```text
final_nav_ratio = parameter_final_nav / dca_final_nav
log_final_nav_ratio = ln(final_nav_ratio)
```

### 19.2 最大回撤殘值比

```text
drawdown_residual_ratio =
  (1 - parameter_max_drawdown) / (1 - dca_max_drawdown)

log_drawdown_residual_ratio = ln(drawdown_residual_ratio)
```

### 19.3 績效回撤綜合指標

```text
performance_drawdown_composite =
  log_final_nav_ratio * drawdown_residual_ratio
```

不開根號，也不把兩個 log 相乘。

### 19.4 合格狀態

```text
qualified =
  parameter_total_return > dca_total_return
  AND
  parameter_max_drawdown < dca_max_drawdown
```

等號不算贏過或小於。另存四種互斥分類：

```text
qualified
return_failed_only
drawdown_failed_only
both_failed
```

### 19.5 無效指標

若任一 NAV 非正、非有限，或回撤殘值比的分母／結果無法取合法 log：

- 對應指標標記 unavailable 並保存原因。
- 不得加入 epsilon、截斷成有限值或當成零。
- 原始 ROI、MaxDD 與 qualified 可在各自輸入有效時繼續保存。

## 二十、相對原始行情的敏感度

對每個 subject、seed、`alpha`，使用相同 subject 的來源快照結果作基準：

```text
signed_delta(metric) = metric_perturbed - metric_source
absolute_delta(metric) = abs(signed_delta(metric))
```

對 log 比率使用差值具有明確倍數意義：

```text
delta_log_final_nav_ratio
= ln(perturbed final NAV ratio / source final NAV ratio)
```

L 同時保存：

- 擾動版本上的絕對指標。
- 有方向差值，用來觀察系統性偏高或偏低。
- 絕對差值，用來觀察對行情細節的敏感程度。

結果不必隨 `alpha` 單調惡化；圖表名稱應使用「幅度敏感度」或「敏感度／退化曲線」，不得把上升結果強行改寫成下降。

## 二十一、seed 分佈統計

### 21.1 每個 alpha 分開

統計鍵至少包含：

```text
analysis_snapshot
subject
alpha
metric
```

不得將不同 `alpha` 的 seed 樣本合併、加權或平均成一個總分。

### 21.2 描述統計

每個有效 metric 集合保存：

- `planned_count`。
- `valid_count`。
- `failed_count`。
- `missing_count`。
- 平均值。
- 中位數。
- population standard deviation，分母使用 `n`。
- 本批最小值及最大值。
- P05、P25、P75、P95。

分位數使用固定版本的線性插值：

```text
排序後 x[0..n-1]
h = (n - 1) * p
i = floor(h)
j = ceil(h)
Q(p) = x[i] + (h - i) * (x[j] - x[i])
```

`n = 0` 時統計不可用；`n = 1` 時 population standard deviation 為 0。所有統計輸出保存統計演算法版本。

### 21.3 失敗與缺漏

- failed、cancelled、corrupt、unavailable 或缺漏 run 不得以零或差績效加入分佈。
- UI 必須始終顯示 `valid / planned`。
- 部分結果只能建立標記 `partial` 的分析快照。
- 補算完成後建立新 analysis snapshot；舊 partial snapshot 保留。

### 21.4 解讀限制

seed 樣本只來自本文件定義的人工擾動分佈，未經未來市場機率校準。因此：

- 合格比例稱為「本批擾動樣本比例」。
- 最小值稱為「本批最小值」。
- 分位帶稱為「本批 seed 分佈」。
- 不顯示「未來成功機率」、「信賴區間」、「風險值」或「理論最壞情況」。

## 二十二、測試保存、延伸與狀態

### 22.1 建立與啟動

L test 建立後先是 `draft`。使用者確認精確 manifest 後建立 `PerturbationTestBatch` 並啟動 I 根任務。

每個 subject × dataset run 是獨立原子任務：

- 可快取命中。
- 可獨立失敗與重試。
- 可在取消後保留完成結果。
- 不得因某一 run 失敗而刪除其他結果。

### 22.2 追加測試

同一 test 可以追加：

- 新 seed。
- 新 `alpha`。
- 同群組中先前未納入的完成版本。

每次追加建立新 batch、manifest hash 與 analysis snapshot。若受測參數、來源群組或任何非參數回測設定改變，必須複製成新 test。

### 22.3 取消與續跑

- 取消後狀態為 `cancelled`，已完成 run 仍可查看。
- 有完成 run 時可建立 `partial` 分析快照，但不能顯示成完整。
- 重開 test 可以依原 manifest 續跑缺漏或失敗項目。
- 續跑只在所有設定、dataset、subject、核心及版本 hash 相容時允許。
- 完整 manifest 成功後建立新的 `complete` snapshot，test 狀態轉成 `completed`。

真正程式錯誤使用 `failed`，使用者取消使用 `cancelled`，兩者不得混用。

## 二十三、G 報酬分析整合

L 批次本身只要求標準化回測摘要及第 19 至第 21 章的直接衍生統計。下列 G 報告保持按需：

- 日／週／月報酬直方圖與分佈統計。
- 日報酬累加走勢。
- 最長水下期。
- Sortino。
- 自選基準 Beta。
- 持倉天數比例、平均實際倉位及曝險調整報酬。

操作規則：

- 每個完成 run 都能跳到既有 `PerformanceReport` 或建立新報告。
- 使用者可選定一個或多個 run 批次補算；開始前顯示總量、快取及實算量。
- 相同 BacktestResult 與分析設定重用同一 PerformanceReport。
- 開啟 L 頁、切換 metric 或圖表不得自動替全部 run 建立 G 報告。
- G 報告是否完成不影響 L 的既有回測、M 候選或參數採用狀態。

## 二十四、M 候選驗證與 N 唯讀比較整合

### 24.1 所有權

- M 的 `RobustCandidate` 是候選真源。
- L 的 `PerturbationTestSubject` 與分析快照是擾動測試真源。
- `CandidateAnalysisLink` 只保存雙向引用、分析種類、任務、結果、版本與狀態。
- L 不複製 M 的區域、前緣、角色或人工採用紀錄。

### 24.2 啟動與跳轉

M 候選頁提供「擾動行情測試」動作，開啟 L 工作區並預填不可變候選版本。L 結果頁必須能跳回：

- 候選。
- 來源 M configuration、region 及 analysis snapshot。
- 候選連結的參數庫紀錄，如有。

同一 L test 含多個 M 候選時，每個 subject 建立自己的 link，不以整批單一狀態覆蓋各候選結果。

### 24.3 驗證狀態

M 的候選分析狀態固定擴充為：

```text
not_calculated
running
partially_completed
completed
failed
cancelled
not_applicable
```

- `partially_completed` 表示存在可查看結果，但 manifest 不完整。
- `cancelled` 表示使用者取消；可帶 partial snapshot 引用。
- `failed` 只表示非使用者主動造成的錯誤。
- 續跑時更新為 `running`，完整完成後才是 `completed`。

連結不得保存 `passed`、`approved` 或自動淘汰布林值。未執行、部分完成或失敗都不阻止使用者存入參數庫或 Promote。

### 24.4 N 通用研究比較

L 以精確 `PerturbationAnalysisSnapshot` 或等價不可變分析 snapshot 作為 N「研究結果比較」來源。唯讀比較資料至少包含：

- test、batch、manifest、完整度、統計版本與內容 hash。
- 每個受測參數的 canonical 來源與完整凍結採用單位。
- 來源快照、各 seed／alpha dataset 版本及回測背景。
- alpha 敏感度、中位數、分位帶與 `alpha = 0` 基準。
- seed matrix、同 seed 軌跡、逐筆結果引用及 qualified 分類。
- 缺漏、失敗、取消、partial 與 completed 狀態。
- 已存在的 BacktestResult、G 報告與 M 候選連結。

受測參數若來自正式參數庫或 M 候選，N 的參數分頁只引用該 canonical 來源；L subject 只提供 lineage，不重複建立參數項目。

規則：

- N 固定引用 test、analysis snapshot、統計版本與內容 hash。
- L 追加 seed、alpha、variant 或補算後建立新版 snapshot；舊 N 工作區不自動更新。
- 完整 matrix、逐筆結果與軌跡只在 N 展開區塊時讀取。
- N 不得建立 L test、追加 batch、生成 variant、重試 run 或補算 G。
- N 只保存來源引用與顯示狀態，不複製 K 線、回測、seed 分佈或分析 payload。
- N 的並排或疊圖不形成 L 的新驗證結論，也不得自動判定候選是否通過。

完整 N 契約見：

```text
docs/研究構想整理/通用研究結果與參數比較工具開發指導.md
```

不得要求使用者替每個 seed × `alpha` 手動輸入 instrument ID 或 symbol。

### 27.2 群組詳情

群組詳情採可掃描表格，不以多層巢狀卡片堆疊。至少顯示：

測試建立區顯示受測參數、資料矩陣、固定回測條件及精確計算計畫。測試詳情至少有：

- 摘要。

## 二十八、錯誤、併發與恢復

### 28.1 錯誤分類

至少區分：

- `invalid_source_bar`。
- `unsupported_source_kind`。
- `stale_plan`。
- `invalid_seed`。
- `invalid_alpha`。
- `numeric_overflow`。
- `illegal_generated_ohlc`。
- `recipe_conflict`。
- `content_hash_mismatch`。
- `incompatible_test_subject`。
- `missing_variant`。
- `backtest_failed`。
- `analysis_input_incomplete`。

錯誤不得被轉成零績效、空 K 線或成功狀態。

### 28.2 服務重啟

- 啟動時不得重新產生所有 L 資料。
- I 依既有恢復規則將 running 任務轉成可續跑、failed 或 cancelled；不得永久卡住。
- 續跑前重新驗證 snapshot、recipe、已寫入批次及內容 hash。
- 已發布 completed variant 不因服務重啟重寫。
- 分析 worker 中斷只影響尚未發布 snapshot，不改寫舊 snapshot。

### 28.3 併發追加

同一群組並行增加版本、同一 test 並行增加 batch 時，必須使用唯一索引及鎖定序號收斂：

- 同 recipe 只一份 variant。
- 同 batch ordinal 不重複。
- 同 subject × dataset × spec 只一個 run 引用。
- 同 analysis set hash 只一份 snapshot。

不同群組或測試可以平行執行，但必須服從 I 的 worker 與資料庫資源上限。

## 二十九、封存、刪除與備份

### 29.1 封存

- 群組、variant 及 test 可封存並從預設列表隱藏。
- 封存不改變內容、hash、引用或舊回測可讀性。
- 來源群組封存後，不允許新增版本，除非先解除封存。

### 29.2 刪除保護

下列任一引用存在時不得實體刪除對應 snapshot、variant、test run 或分析快照：

- ResearchDataset。
- StandardizedBacktestResult。
- PerformanceReport。
- M CandidateAnalysisLink。
- N 比較工作區或其他使用者保存的測試／比較。
- 其他已發布衍生 artifact。

無引用的 failed／cancelled partial rows 可透過明確人工維護動作清理。不得建立固定天數自動刪除器，也不得在啟動、AutoMigrate、一般重啟或備份時偷偷清理。

### 29.3 備份與還原

備份必須包含：

- 所有 L GORM model。
- 來源快照及完整 K 線。
- 擾動版本及完整 K 線。
- seed、`alpha`、演算法版本及全部 hash。
- I 任務與 manifest 引用。
- StandardizedBacktestResult、PerformanceReport 及 M 連結。

還原後執行抽樣及完整 hash 驗證，確認 group、variant、test、snapshot 與候選雙向引用一致。只備份 metadata、不備份 K 線不算完成。

## 三十、效能與資源控制

- 生成採串流／分批處理，不將 `bars × seeds × alpha` 全部同時放入記憶體。
- 同 seed 的基礎亂數場在多 `alpha` 間重用。
- source hash 與 output hash 使用 streaming hash。
- 大量 K 線寫入使用受控 batch，取消點位於 batch 邊界。
- 版本、run 與 metric summary 依 group、status、recipe hash、test、subject、alpha 建立必要索引。
- 開始前顯示精確 variant、bar 及 run 數；超過 I 硬上限不得啟動。
- 儲存估算必須計入來源快照、所有衍生 K 線及資料庫索引，不只計算 JSON metadata。
- 前端不可用持續動畫、隱藏輪詢或每次滑鼠移動重建大圖。

L 不要求 GPU。產生與回測使用既有受控本地 Lab CPU 工作池，效能優化不得改變確定性公式或結果順序獨立性。

## 三十一、測試矩陣

### 31.1 純數學單元測試

- `alpha = 0` 的座標轉換與重建逐值回到來源持久化 OHLC。
- 合法來源經任意有效 seed／`alpha` 後仍滿足正值及 OHLC 邊界。
- `s(t)` 正確涵蓋 high-low、high-prev-close、low-prev-close，第一根 fallback 正確。
- `s(t) = 0` 時整根不變。
- 零上影線／下影線保持零，非零影線不會因擾動變負。
- 接近 doji 的 `b` 可合法換方向。
- 每根錨定來源，不出現逐日遞迴累積。
- HashToUnit 固定 test vectors 在不同 worker 數與切片起點完全一致。
- 相同 seed 不同 `alpha` 使用相同 `z`；不同 seed 產生不同定位值。
- actual deviation 中位數、P95、最大值與百分比轉換正確。
- 溢位、NaN、Inf、非正價格及非法來源確實拒絕。

### 31.2 Canonical 與 hash 測試

- JSON map 順序不同得到相同 canonical hash。
- `0.05`、`0.050` canonical 後相同；不同合法值不同。
- `-0` 正規化為 `0`。
- seed 經 JSON round-trip 不失真。
- source bar 任一欄位、先前收盤或 metadata 改變，source hash 改變。
- 相同 recipe 只建立一個 variant。
- output 任一 persisted value 改變，內容 hash 驗證失敗並標記 corrupt。
- 演算法版本變更導致 recipe hash 變更。

### 31.3 統計單元測試

- mean、median、population standard deviation、P05／P25／P75／P95 使用固定 test vectors。
- `n = 0`、`n = 1` 邊界正確。
- signed delta 與 absolute delta 正確。
- 不同 `alpha` 不會被混入同一 summary。
- failed、missing、unavailable run 不會被當成零加入分佈。
- 四種 qualified 分類互斥且總和等於有效分類數。
- 無效 log 指標不加入對應 metric，但不破壞其他有效摘要。

### 31.4 Service 整合測試

- 可由一般 OHLC 來源建立快照與群組。
- 可由既有槓桿產生資料建立群組，且顯示影線限制。
- 可由不含 L 擾動祖先的合法 E 完成版本建立群組。
- FRED、L 衍生資料及任何含 L 擾動祖先的 E 版本被拒絕作為來源。
- 原商品重匯後舊 snapshot、variant 及結果不變，並可由舊 snapshot 續增版本。
- 多 seed × 多 `alpha` 生成、取消、重啟、續跑及快取重用正確。
- 未完成或 corrupt variant 即使知道 instrument ID 也不能回測。
- 相同建立請求並行時不產生重複 K 線或版本。
- 內容 hash 驗證與 corrupt 隔離正確。

### 31.5 回測與分析整合測試

- `P × (1 + A × S)` 計畫數正確，快取與實算量分開。
- 每個 variant 的參數與 DCA 使用同一 dataset。
- 所有 run 共用回測核心、成本與每日實際持倉語義。
- 相同 backtest key 重用標準化回測結果，不複製 NAV。
- 取消後完成 run 保留、partial snapshot 標記正確，續跑建立 complete 新版。
- 新增 seed／`alpha` 只新增 batch 及新 analysis snapshot。
- G 報告只在使用者啟動時補算並可雙向跳轉。
- M 候選與 L subject／snapshot 雙向引用完整，部分完成及取消狀態正確。
- L 結果不會自動 Promote、淘汰或改變 GeneRecord 角色。

### 31.6 回歸、前端與效能測試

- 未使用 L 時，既有匯入、槓桿產生、回測、參數搜尋及 M 結果不變。
- 槓桿產生模式仍維持既有公式與覆蓋行為，L 不偷偷改寫它。
- 來源 selector 在 L 模式可選槓桿 generated，在槓桿模式仍遵守既有限制。
- 來源 selector 可辨識 E 版本與遞迴血緣，不得只靠 `data_source = generated` 判斷來源種類。
- 大量 variants 不平鋪污染主要研究商品清單。
- 計畫、進度、取消、續跑、錯誤、缺漏與 corrupt 狀態可見。
- 圖表切換不發出回測請求，hidden tab 停止繪製。
- 大量 run table 使用分頁／虛擬化，桌面與行動視窗無重疊或截字。
- 取消大任務後 worker、goroutine、資料庫連線與記憶體正常釋放。
- 備份及還原後所有 hash、K 線、任務與連結一致。

## 三十二、端到端驗收情境

正式驗收至少完成：

1. 選擇一份合法日 K，建立含區間前收盤的不可變來源快照。
2. 使用兩個 seed 與三個 `alpha` 產生六份版本，確認同 seed 各尺度方向一致。
3. 取消生成後保留完成版本，重啟服務並續算缺漏。
4. 對任一版本修改測試資料，確認內容稽核標記 corrupt 並阻止回測。
5. 使用既有三倍費半產生行情建立群組，確認缺少真實影線的提示及零影線規則。
6. 選擇至少兩個相容 M 候選，預覽並執行 `P × (1 + A × S)` 批次。
7. 驗證每個資料版本都重新計算自己的 DCA，並引用標準化回測結果。
8. 查看每個 `alpha` 的中位數、分位帶、絕對差值、qualified 樣本比例及缺漏數。
9. 取消部分測試，確認 M 顯示部分完成或已取消；續跑後更新為完成。
10. 對指定 run 按需建立 G 報告，確認未選 run 沒有被暗中補算。
11. 在原來源資料更新後繼續替舊群組增加 seed，確認仍使用舊快照；另建群組新版使用新來源。
12. 使用一份不含 L 祖先的 E 完成版本建立群組；再用包含 L 片段的 E 版本嘗試建立，確認被遞迴血緣檢查阻擋。
13. 封存群組並完成備份還原，確認舊回測、G 報告及 M 雙向連結仍可開啟。

## 三十三、完成判準

- 五個已確認決策單元全部落地，沒有以暫時公式取代。

## 三十四、禁止的替代實作

- 不得把 L 稱為 Monte Carlo、bootstrap、未來機率或完整市場生成器。
- 不得對 O、H、L、C 絕對價格各自直接加噪音。
- 不得使用 Gaussian 作為未確認的預設，或允許無界極端值。
- 不得以日報酬標準差、任意 rolling window 或固定絕對價格作擾動尺度。
- 不得使用累積 random walk、跨日平滑或受測參數導向的擾動。
- 不得截斷、反射、取絕對值或重抽非法影線後冒充原分佈。
- 不得從 L 版本再產生 L 版本，也不得先把 L 版本包入 E 重組行情後再次擾動。
- 不得覆寫原行情、來源快照、完成 variant、舊 test 或 analysis snapshot。
- 不得只保存 seed 而每次重算，也不得只保存 bars 而丟失配方與來源 hash。
- 不得讓 `generated` 資料全部冒充每日槓桿公式。
- 不得共用原始 DCA 與擾動參數 NAV，或建立 L 專用第二套回測。
- 不得把不同 `alpha` 混成單一分佈、加權分數或自動排名。
- 不得把失敗／缺漏 run 當成零績效，也不得把本批比例稱為未來機率。
- 不得開頁即自動補算全部 G 報告，或切換圖表時重新回測。
- 不得建立系統及格線、自動淘汰、自動存入參數庫或自動 Promote。
- 不得只做資料表、空 API、空頁面、單張圖或 happy path 後宣稱完成。
- 不得在策略核心加入資料庫、網路、檔案、時間、task 或 `isBacktest` 分支。
- 不得使用 SQL migration、服務啟動、AutoMigrate 或一般重啟偷偷清理歷史資料。
