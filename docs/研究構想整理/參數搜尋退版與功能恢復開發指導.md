# 參數搜尋退版與功能恢復開發指導

> 文件定位：本文件是參數搜尋退回穩定基線後，重新恢復必要功能的獨立開發指導。它不是三份穩定真源文件，也不定義新的市場狀態研究模型。
>
> 確認狀態：本文件所列功能範圍已由使用者於 2026-07-29 確認；程式退版與功能恢復尚未開始，不得標記為完成。
>
> 開發方式：一次到位完成，不做 MVP、骨架、暫時相容層或只接通 UI／API 的半成品。下列順序只是降低風險的實作順序，不代表可分段宣稱完成。

## 一、背景與目的

既有參數搜尋在加入「市場內涵資料區間、區間組合、每個組合的完整參數」及後續逐層格點搜尋後，出現下列根本問題：

- 候選結構與搜尋空間急遽膨脹。
- 文件與實作對判定值數量、區間組合、搜尋上限及參數對應方式反覆漂移。
- 介面顯示演化中，但部分欄位實際沒有進入候選。
- 冠軍繼承、跨任務去重、進度與錯誤狀態不可靠。
- 逐層格點搜尋沒有形成可驗證、可持續的完整搜尋狀態。
- 部分效能優化與新市場區間結構綁定，難以證明結果完全一致。

本次不繼續修補上述結構。正確方向是先退回市場區間升級前的穩定參數搜尋，以既有 GA 為唯一可運作搜尋核心，再逐項重做真正有價值且可以獨立驗證的功能。

## 二、退版邊界

### 2.1 程式來源邊界

退版執行前必須保存當前程式碼快照，以便日後查閱問題來源，但不得把失敗實作繼續留在正式主線。

目前已確認的 Git 邊界如下：

- `7674fe0`：市場內涵資料區間參數搜尋升級前的穩定基線。
- `8190c7d`：市場內涵資料區間參數搜尋的第一個提交；其後相關實作不直接沿用。
- `3cc6487`：與本次參數搜尋升級無關的 SOXL 緊急試算功能，退版時應保留。

實際執行退版前仍須重新核對提交圖與工作目錄，避免把後來新增但與本功能無關的修改一併移除。

### 2.2 資料庫邊界

- 不回滾資料庫。
- 不建立資料庫備份。
- 不刪除已存在但退版後不再使用的資料表、欄位或紀錄。
- 不建立 SQL migration。
- 退版後的程式不得因舊資料存在而誤載失敗候選、誤繼承冠軍或改變新任務的搜尋身分。
- 未使用的舊資料先保留；未來若確有清理需求，再另行確認。

### 2.3 結果相容邊界

- 退版前由失敗市場區間結構產生的候選，不得自動轉成一般 GA 候選。
- 不以填預設值、刪除判定值或抽取其中一份參數的方式偽造相容。
- 舊任務可保留為歷史紀錄，但不得成為新任務冠軍、起始候選或跨任務去重來源。
- 新任務只能使用目前有效搜尋 schema 所產生的候選。

## 三、明確不恢復的功能

下列功能不屬於本次恢復範圍，退版後不得殘留於有效候選、搜尋控制、格點圖或任務狀態：

- 市場內涵資料的多判定值搜尋。
- 多項市場資料的笛卡爾區間組合。
- 每個區間組合對應一整份策略參數的結構。
- 只為訓練資料曾出現的區間建立參數，以及未來缺少參數時的補值或 fallback。
- 判定值、窗口及區間組合的演化。
- 市場區間啟用時停用 Beta 或以其他值取代 Beta 的規則。
- 區間組合數、參數份數的 `512` 或其他擅自上限。
- 判定值過多時的自動刪除、裁切、壓縮或只保留第一個判定值。
- 市場區間專用的候選快取、區間索引快取與相關記憶體結構。
- 目前的逐層格點搜尋實作。
- 沒有實際系統基礎的實盤待執行狀態、次開盤排程或 LocalAgent 擴充。

「有序擴張並完整枚舉新切片」仍可作為未來獨立研究題目，但必須重新討論搜尋狀態、有限搜尋空間、計算量與停止條件；不得從目前失敗實作直接續修，也不得阻擋穩定 GA 恢復。

## 四、恢復後的搜尋核心

### 4.1 唯一搜尋核心

- 先恢復既有 GA 的抽樣、交叉、變異、菁英保留與冠軍繼承。
- GA 直接產生合法、可評估的候選，不得依賴市場區間參數。
- 每個候選仍由既有共用回測核心評估。
- 回測頁與參數搜尋必須使用同一套策略計算與成交語義。
- 在下列全部功能驗收前，不加入第二套搜尋演算法。

### 4.2 合法候選事前產生

強制滿倉與強制空倉的結構關係必須在候選誕生前成立：

```text
強制滿倉門檻 >= 強制空倉門檻
```

此規則須同時適用於：

- 初始抽樣。
- 冠軍附近抽樣。
- 交叉。
- 變異。
- 連續搜尋的新一輪候選。
- 從保存設定重新建立的任務。

不得先產生非法候選，再於回測、驗證或任務執行時大量攔截。

## 五、條件式演化

搜尋空間必須由「本次設定下是否真的會影響策略結果」決定。停用不是固定一個仍會影響策略的值，而是對應邏輯完全不參與策略計算。

### 5.1 純浮動倉位

純浮動倉位模式下，下列欄位不得抽樣、交叉、變異或消耗候選差異：

- 微觀保留比例。
- 再平衡門檻。
- 額外投入比例。
- 緩釋月數。
- 緩釋比例。
- 硬釋放上限。
- 偏多、偏空倍率。
- 舊微觀最小單觸發條件。
- 幾何變化門檻。
- 幾何活動門檻。

上述邏輯在純浮動模式下必須直接停用，不能只固定為任務建立時碰巧取得的值。

### 5.2 零交易成本

當手續費與滑價／價差皆為零時：

- 最小交易金額不參與演化。
- 最小交易金額不得影響交易或回測結果。
- 不得用不同的無效最小交易金額製造不同候選 fingerprint。

### 5.3 透明顯示

低負載格點圖仍須列出所有既有核心參數，以便確認系統沒有偷偷演化不該演化的欄位。每個欄位必須明確標示：

- `演化中`：候選會產生不同值。
- `固定`：使用者明確固定，仍可能影響策略。
- `停用`：在本次模式不參與策略，也不參與候選身分。

停用欄位應只有一個中性顯示點或空白軸，並清楚標示停用；不得標成演化中。

## 六、0.05 直接格點

### 6.1 格點規則

- 所有可演化的浮點核心參數，最小間隔固定為 `0.05`。
- 可演化值必須能被 `0.05` 整除。
- 抽樣、冠軍附近搜尋、交叉與變異都必須直接產生格點值。
- 不得先產生任意連續值，再四捨五入、壓縮、攔截或去重。
- 整數欄位維持整數語義，不強制套用 `0.05`。
- 固定欄位保持使用者設定的原值，不因格點規則被改寫。
- 所有連續搜尋選項與起始方式都必須遵守同一格點規則。

### 6.2 參數合法邊界

每個核心參數的最小值、最大值及其他結構限制，必須來自既有正式策略 metadata 或真源規格。不得在抽樣器、前端或圖表中另藏一套未揭露上限。

若合法邊界不是 `0.05` 的整數倍，只能使用落在合法範圍內的格點，不得擴張超出原邊界。

## 七、跨任務不重複搜尋

### 7.1 同設定身分

相同設定的不同任務不得重新評估已經誕生並完成評估的同一候選。搜尋身分必須包含會改變績效語義的資料：

- 策略與有效候選結構版本。
- 單行情或多行情模式。
- 實際行情集合。
- 每張行情的資料內容版本。
- 每張行情各自的起訖範圍。
- K 線週期。
- 執行模式。
- 初始資金與定期投入設定。
- 手續費、滑價／價差及其他有效成本。
- 固定核心參數及其值。
- 有效演化欄位集合。
- 回測與評分語義版本。

下列工作控制設定不構成不同研究語義：

- 族群數量。
- 世代數。
- 是否連續搜尋。
- 連續搜尋執行方式。
- 起始方式。
- 是否開啟原始追蹤。
- 是否開啟格點圖或舊參數分佈圖。
- 前端更新頻率及其他純顯示設定。

### 7.2 候選身分

- 候選 fingerprint 只包含真正生效的搜尋欄位與固定欄位。
- 停用欄位不得造成候選差異。
- 浮點欄位以格點索引或等價精確表示建立 fingerprint，不得受浮點字串誤差影響。
- 同設定跨任務的已評估候選必須在產生前排除，不得產生後才大量判定重複。
- 候選預約必須具備原子性，避免多個 worker 同時取得同一候選。
- 已失敗或因系統故障中斷的候選是否可重試，必須與「已完成評估」分開記錄。

### 7.3 已知區域耗盡

GA 原有的「在優秀參數附近搜尋」行為必須保留。當附近合法格點已經全部評估：

- 不得反覆產生相同候選。
- 不得只因附近耗盡而停止整個任務。
- 應改從其他尚未評估的合法區域產生候選。
- 仍須保留菁英與既有選擇壓力，不能退化成完全無方向的隨機搜尋。

## 八、穩定任務狀態

### 8.1 建立與執行

- 前端送出任務後，必須收到明確的成功任務 ID 或結構化錯誤。
- 表單不得在建立失敗時假裝成功後自行收合。
- 後端任務狀態至少清楚區分：待執行、執行中、取消中、已取消、失敗、完成。
- 服務重啟後不得把已中斷任務誤顯示為仍在執行。
- worker panic、資料缺失、候選耗盡或評分無效都必須留下可理解的失敗原因。

### 8.2 進度與計算量

- 代數、已評估候選數、有效候選數、跳過的既評估候選數及失敗候選數分開統計。
- 速度與剩餘時間只能依實際完成評估的候選計算。
- 未開啟原始追蹤時，進度仍必須正常回報。
- 計算量監控只能降低追蹤與計數負載，不得關閉真正回測、捏造 counter 或讓任務永遠停在零。
- 任務取消須由後端實際停止後再顯示已取消。

### 8.3 評分

- 不得以 `0`、`-9999999` 或其他魔術數字偽裝尚未計算、無效數值或系統錯誤。
- 尚未產生有效候選時顯示「尚無有效評分」。
- 無效績效必須有原因並按正式淘汰規則處理。
- 任務的當前最佳與最終最佳必須來自實際完成評估的候選。

## 九、獨立低負載格點覆蓋圖

格點覆蓋圖是獨立功能，不得依賴舊參數分佈地圖開關。

- 每張圖只對應一個核心參數。
- 只使用候選誕生時已保存的格點與累計次數，不重新載入完整回測軌跡。
- 圓點大小可表示該格點的候選累計數。
- 每完成一代更新一次；不得每個候選或每秒重算整張圖。
- 開啟新一輪相同設定搜尋時，須載入同設定歷史格點，不得清空。
- 固定、停用、演化中的欄位均顯示，並標明狀態。
- 圖表查詢使用聚合資料與固定點數上限，不得恢復舊參數分佈地圖的高記憶體做法。
- 關閉圖表只停止圖表資料累積與查詢，不得改變候選、去重或搜尋結果。

## 十、記憶最近使用設定

- 參數搜尋頁記住最近一次成功送出任務的表單設定。
- 重新整理或重新進入頁面後自動恢復表單，但不得自動開始任務。
- 單行情與多行情選擇須完整恢復。
- 多行情各自日期與「使用全部資料」設定須完整恢復。
- 若先前行情已不存在或資料版本不再可用，須顯示缺失項並要求重新選擇，不得偷偷改成預設行情。
- 純顯示設定可以一併保存，但不得進入跨任務搜尋身分。

## 十一、多行情參數搜尋

### 11.1 行情選擇

- 使用者明確勾選「採用多行情」後，至少選擇兩張行情。
- 多行情模式只使用多行情清單內實際勾選的行情。
- 上方單行情「研究標的」完全不參與計算、任務身分、冠軍繼承或資料檢核。
- 多行情清單預設空白，不自動帶入上方研究標的或比特幣。
- 取消多行情模式後，上方研究標的才恢復為單行情來源。

### 11.2 各行情資料範圍

- 每張已選行情都有自己的開始與結束日期。
- 選中行情後，前端依實際數量動態顯示對應日期欄位。
- 「每張行情使用全部資料」預設勾選。
- 勾選使用全部資料時，日期欄位收合隱藏；後端使用該行情實際可用資料的頭到尾。
- 未勾選時，後端只能使用該行情自己的指定範圍。
- 任一行情缺資料、範圍無效或無法形成完整回測時，整個任務不得開始，並列出缺失行情。

### 11.3 共用設定

目前既有的下單、成本、資金、定期投入、執行模式與策略設定，套用到每一張行情。每張行情不另設一套成本或資金條件。

每個候選以完全相同的核心參數，分別在所有已選行情的完整訓練區間回測。不得對不同行情生成不同候選參數。

### 11.4 整體分數

每張行情先計算既有現金流調整後年化報酬率 `r_i`，多行情整體分數定義為：

```text
整體候選分數 = Σ ln(1 + r_i)
```

規則如下：

- `r_i` 使用小數，不是百分比字面值。
- 不對各行情加權。
- 不加入窗口權重。
- 不直接相加總報酬或年化報酬率。
- 不設置人工最低分數或裁切負報酬。
- `r_i = -1` 時該行情分數為負無限；若回測產生數學上無法定義的年化成長倍數，候選按無效／最劣處理並保留原因，不以魔術數字替代。

### 11.5 保存與顯示

計算總分前本來就會取得各行情績效，因此保存與顯示下列資料不得觸發第二次回測：

- 整體候選分數。
- 每張行情總報酬。
- 每張行情現金流調整後年化報酬率。
- 每張行情最大回撤。
- 整體最大回撤，定義為所有行情最大回撤中的最大值。

運算中的當前最佳、任務完成結果及保存候選都必須依本次行情數量動態顯示上述欄位。

任一行情最大回撤觸及既有 `88%` 淘汰門檻時，整個候選淘汰。不得用其他行情的高報酬抵銷該淘汰條件。

### 11.6 繼承與去重

- 多行情冠軍只可由完整行情集合、各行情資料內容版本、各自資料範圍及其他有效設定相同的任務繼承。
- 不得只用第一張行情或上方單行情欄位判定同標的冠軍。
- 多行情候選的跨任務去重使用完整多行情身分。

## 十二、結果完全一致的效能優化

效能優化可以重做，但只能在參數搜尋與回測的結果完全一致前提下啟用：

- 重用不可變的行情與已確認不依候選改變的中間資料。
- 平行處理彼此獨立的候選或行情回測。
- 減少熱路徑記憶體配置與重複序列建立。
- 批次保存進度、候選與聚合格點。
- 前端只取摘要；完整軌跡按需讀取。
- 限制快取記憶體，避免用不受控記憶體換速度。

禁止：

- 降低浮點精度。
- 抽樣代替原本應完整計算的資料。
- 改變交易順序、成交價、費用、定期投入、目標權重或回撤算法。
- 使用近似績效提前淘汰。
- 以市場區間專用快取重新包裝成通用優化。

每項優化都必須以同一輸入逐項比較交易、持倉、權益、費用、報酬、回撤及最終評分；任一結果不同即不得啟用。

## 十三、實作順序

以下為一次完整恢復內的風險順序：

1. 回到穩定 GA 與既有回測基線。
2. 修正候選事前合法生成。
3. 完成條件式演化與中性停用語義。
4. 完成 `0.05` 直接格點。
5. 完成同設定跨任務去重與原子候選預約。

## 十四、測試與驗收

### 14.1 基線回歸

- 以退版前穩定版本保存的固定行情與固定參數，比較逐根目標權重、交易、費用、權益、報酬及回撤。
- 不啟用新增功能時，單行情 GA 結果語義與穩定基線一致。
- 回測頁 JSON 載入與參數搜尋保存候選都能使用同一核心參數結構。

### 14.2 候選測試

- 大量抽樣、交叉與變異均不產生滿倉門檻低於空倉門檻的候選。
- 所有可演化浮點值都在 `0.05` 格點。
- 固定與停用欄位不產生無效候選差異。
- 純浮動與零成本條件下，不該演化的欄位完全不消耗搜尋空間。

### 14.3 去重測試

- 同設定、不同任務不重算已完成候選。
- 只改族群、世代、追蹤或圖表設定時，仍視為同設定。
- 改變行情內容、資料範圍、成本、固定參數或評分版本時，不得誤用舊結果。
- 多 worker 不會同時評估同一候選。
- 任務中斷後，已完成與未完成候選狀態可正確恢復。

### 14.4 多行情測試

- 上方單行情欄位在多行情模式完全不參與後端請求語義。
- 每張行情使用自己的資料範圍；使用全部資料時正確展開頭到尾。
- 任一行情缺資料會在任務建立前拒絕並列名。
- 手工計算的 `Σ ln(1+r_i)` 與後端總分一致。
- 每張行情的總報酬、年化報酬率及最大回撤只由同一次回測結果保存。
- 任一行情觸及最大回撤淘汰門檻時，候選被淘汰。

### 14.5 UI 與任務測試

- 建立失敗不會讓表單假裝成功收合。
- 執行中頁面不會閃現後消失。
- 原始追蹤關閉時進度仍會前進。
- 未有有效候選時不顯示假 `0` 或魔術分數。
- 新一輪相同設定搜尋仍看得到累積格點。
- 最近設定可恢復，但不會自動開始任務。
- 格點圖開關與舊參數分佈圖完全獨立。
