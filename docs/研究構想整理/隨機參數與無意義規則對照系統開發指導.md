# 隨機參數與無意義規則對照系統開發指導

> 狀態：P11 已完成；六類對照、M 候選整合、K 動態候選同結構隨機參數與 N 唯讀比較契約均已實作
>
> 用途：定義「隨機參數與無意義規則對照系統」的完成品行為。此文件不是三份真源文件，不取代既有穩定系統規格。

## 一、系統定位

隨機參數與無意義規則對照系統是一個獨立研究工具，用來檢驗一組選定參數包或 M 穩健候選是否真的優於：

- 隨機參數
- 無意義規則
- 曝險序列打散結果

此系統不屬於正式策略核心，不改寫策略 `Step()`，不把無意義規則寫入正式參數庫，也不讓無意義規則進入參數搜尋。

隨機參數可以保存於獨立的隨機參數庫，但不得保存為正式參數庫的 candidate、champion 或 retired gene。

## 二、前置依賴

本系統開發前，必須先完成每日實際持倉比例計算。

每日實際持倉比例的完整定義、計算方式與完成判準見：

```text
docs/研究構想整理/每日實際持倉計算機制開發指導.md
```

此依賴是必要條件，原因是「曝險序列打散對照」必須取用正式回測產生的每日實際持倉比例序列。若只有 `model_target_weight` 或 `practical_target_weight`，無法正確代表實際成交後曝險，也不能用來做曝險打散。

本系統同時依賴下列基礎模組：

```text
docs/研究構想整理/回測核心模組開發指導.md
docs/研究構想整理/標準化回測結果保存機制開發指導.md
docs/研究構想整理/報酬分析共用模組開發指導.md
docs/研究構想整理/計算任務與快取掃描工具開發指導.md
```

原因：

- 隨機參數、無意義規則與曝險序列打散都必須透過回測核心產生一致 NAV。
- 對照任務需要引用與重用標準化回測結果。
- 對照結果比較需要使用同一套報酬分析定義。
- 對照任務屬於大量計算，必須支援總計算量、進度、取消與快取。

本系統可被 M 作為候選驗證工具調用：

```text
docs/研究構想整理/參數績效地形研究與穩健候選產生系統開發指導.md
```

M 只建立候選與本對照任務的雙向引用，不得把 H 的隨機參數、無意義規則或曝險打散演算法複製到 M。

若受測候選使用 K，任務必須連同模型 artifact、預測 schema、動態政策與參數空間 schema 一起載入：

```text
docs/研究構想整理/動態適應參數機制開發指導.md
```

K 動態候選的隨機參數對照固定使用「同一動態結構下，只隨機有效研究維度」的規格，完整定義見第 7.1 節。不得只隨機化舊核心參數，也不得把不同控制模式或不同模型結構混成同一個隨機分佈。

本系統的隨機參數紀錄與完成／部分完成的結果 snapshot 會被 N 唯讀比較工具讀取：

```text
docs/研究構想整理/通用研究結果與參數比較工具開發指導.md
```

H 不依賴 N 才能執行對照；N 是下游觀察工具，不得從比較頁啟動、追加或續跑 H 任務。

## 三、頁面位置

此功能必須做成獨立頁面。

在前端導覽順序中，此頁面放在「回測」頁的下一個位置。

## 四、對照組範圍

系統只包含下列六種對照組：

1. 隨機參數 N 組
2. 奇數日買、偶數日賣
3. 偶數日買、奇數日賣
4. 固定 N 日切換持倉
5. 每天開盤買、收盤賣
6. 曝險序列打散對照 N 組

不包含永遠滿倉、永遠空倉、定投、隨機持倉或其他未列出的規則。

## 五、共同回測條件

每次對照分析都綁定一組正式回測條件：

- 標的
- 資料源
- 週期
- 起訖時間
- execution mode
- 初始資金
- 每月投入
- 手續費
- 滑價
- 選定參數
- M 候選 ID 與來源研究設定，如由 M 啟動
- 參數空間 schema、K 模型與動態政策 hash，如有

所有對照組都使用同一組條件。除了「每天開盤買、收盤賣」有自己的開盤/收盤執行語義，其餘規則都遵守該次分析指定的 execution mode。

## 六、保存結構

系統分成四層保存：

1. 隨機參數庫
2. 對照分析任務
3. 對照結果摘要
4. 對照詳細結果

這四層各自解決不同問題，不得只保存其中一部分而導致後續無法重算、無法追蹤或無法重開報表。

### 6.1 隨機參數庫

隨機參數庫保存隨機參數本身，也就是對照測試的「考卷題目」。

隨機參數庫保存：

- 隨機參數批次 ID
- seed
- N
- 生成時間
- 參數生成版本
- 參數範圍版本
- 參數空間 schema hash
- 綁定模型 / 動態政策 hash，如該批次適用於 K
- 每一組隨機參數完整內容

用途：

- 同一批隨機參數可以重複使用。
- 未來新增測驗項目時，可以拿同一批隨機參數補算。
- 不同正式參數可以面對同一批隨機參數。
- 避免每次重新抽樣導致比較基準不同。

隨機參數庫只屬於對照系統，不屬於正式參數庫。

### 6.2 對照分析任務

一次完整檢驗就是一個對照分析任務。

任務保存：

- 任務 ID
- 名稱
- 備註
- 標籤
- 建立時間
- 狀態
- 選定參數 ID
- M 候選 ID 與來源研究設定 ID，如有
- 標的
- 資料源
- 週期
- 起訖時間
- execution mode
- 初始資金
- 每月投入
- 手續費
- 滑價
- 隨機參數批次 ID
- 隨機參數目標數量
- 曝險打散 seed
- 曝險打散目標數量
- 固定 N 日切換的 N
- 規則版本
- 統計版本
- 參數空間 schema hash
- K 模型 artifact 與動態政策 hash，如有

核心回測條件固定。若要改參數、標的、區間、費用或 execution mode，必須複製成新任務。

### 6.3 對照結果摘要

每個任務可以有多份不可變 `ControlAnalysisSnapshot`；每份 snapshot 保存一份快速讀取的摘要，任務另行指向目前最新完成或部分完成 snapshot。補算、追加或續跑建立新 snapshot，不覆寫舊 snapshot。

每份 snapshot 至少固定：

- 任務 ID、snapshot ID、完整度、統計版本與內容 hash。
- 實際納入的隨機參數紀錄範圍。
- 實際納入的曝險打散序號範圍。
- 四種無意義規則版本與完成狀態。
- 納入的 BacktestResult 與既有 G 引用。
- 缺漏、失敗、取消與快取命中計數。

摘要包含：

- 受測參數的期末淨值比、log 期末淨值比、MaxDD、Sortino、最長水下期
- 正式參數在隨機參數分佈中的百分位
- 正式參數在曝險打散分佈中的百分位
- 無意義規則結果摘要
- 隨機參數分佈的中位數與分位數
- 曝險打散分佈的中位數與分位數
- 任務結論標籤

此層給列表、搜尋、排序、快速比較使用。

### 6.4 對照詳細結果

詳細結果綁定精確 `ControlAnalysisSnapshot` 並按需讀取。

詳細結果包含：

- 正式參數 NAV
- 正式參數每日實際持倉比例
- 隨機參數每組摘要
- 無意義規則 NAV
- 曝險打散每組摘要
- 代表性隨機參數 NAV
- 代表性曝險打散 NAV
- 報酬分佈資料

完整 NAV 不對所有隨機組預設全存，避免資料爆量。

預設保存：

- 正式參數 NAV
- 無意義規則 NAV
- 代表性隨機參數 NAV
- 代表性曝險打散 NAV
- 所有隨機組摘要
- 所有曝險打散摘要

## 七、隨機參數 N 組

系統使用受測參數包所屬的合法參數空間 schema 與研究範圍生成 N 組隨機參數。

每一組隨機參數都是完整有效的策略參數包，必須經過現有參數邊界與合法性檢查。

隨機參數不演化、不交叉、不突變、不選拔。

流程：

```text
生成或載入 N 組隨機參數
→ 每組跑一次正式策略回測
→ 產生 N 條 NAV 或 N 組摘要
→ 統計 N 組結果分佈
→ 比較選定參數落在隨機分佈的哪個百分位
```

隨機產生使用 seed。

同一個 seed、同一組參數生成版本、同一組參數範圍版本、同一個參數空間 schema hash、同一個 N，必須生成完全相同的隨機參數批次。

若相同隨機參數批次已存在，系統優先載入既有批次，不重新抽樣。

### 7.1 K 動態候選的同結構隨機參數

K 動態候選的隨機參數對照回答：在相同預測模型與相同動態結構下，受測候選的數值組合是否優於從同一合法參數空間隨機抽出的數值組合。它不比較不同模型路線、不同控制模式或不同啟用結構；這些結構差異由 M 的不同 `ResearchConfiguration` 與 `ResearchSeries` 比較。

每個隨機參數批次必須固定：

- 模型 artifact 與預測 schema。
- 市場狀態規則與動態政策版本。
- 每個核心參數的控制模式。
- 已啟用的預測輸入、一次項、二次項、方向效果、波動效果與交互作用。
- 未列為研究維度的固定值。
- 資料、期間、交易成本、DCA、execution mode 與其他回測條件。

只隨機抽取來源 M 研究設定中實際存在的有效數值研究維度，包括：

- 單一全域基準值。
- 已啟用的一次項與二次項係數。
- 已啟用的方向、波動與交互作用效果。
- 被明確列為研究維度的狀態門檻、遲滯或其他 K 數值。

未啟用的係數或效果不屬於參數空間，不得以隨機值或 `0` 值假裝存在。固定模式、連續動態、六狀態切換等控制模式本身不得隨機切換。

抽樣規則：

1. 依 `DynamicParameterSpaceSchema` 的 canonical 研究座標，從每個維度的合法離散格點均勻抽樣。
2. 使用 seed、參數生成版本與固定的維度順序，確保相同輸入生成相同批次。
3. `sum-to-zero` 等可識別性限制以獨立座標抽樣，再依既定公式推導其餘值，不把冗餘欄位當成額外隨機維度。
4. 違反跨欄結構限制，或在完整受測期間產生無法合法執行之每日有效參數的組合，直接拒絕並繼續抽樣；不得修補後冒充原始抽樣值。
5. 保存抽樣嘗試數、拒絕數與原因，直到取得 N 組完整、合法且可正式回測的參數包。

同一批次只能供下列內容完全一致的候選重用：

```text
模型 artifact hash
+ 預測 schema 與動態政策 hash
+ 參數空間 schema hash
+ 研究範圍與固定設定 hash
+ seed
+ 參數生成版本
```

頁面與結果必須明列哪些設定被固定、哪些維度被隨機，並標示為「同結構條件下的隨機參數比較」。結果只顯示候選在隨機分佈中的位置，不建立及格線，也不自動採用或淘汰候選。

## 八、無意義規則

無意義規則不需要獨立規則庫，因為規則是系統固定定義。

但每次任務必須保存：

- 規則類型
- 規則參數
- 規則版本
- 回測結果摘要
- NAV 曲線

### 8.1 奇數日買、偶數日賣

判斷基準是 K 線開盤時間換算到該標的市場時區後的月中日期。

規則：

```text
1 號、3 號、5 號：目標持倉 100%
2 號、4 號、6 號：目標持倉 0%
```

若當天目標是 100%，系統買到滿倉。

若當天目標是 0%，系統賣到空倉。

若目標與目前狀態相同，不交易。

### 8.2 偶數日買、奇數日賣

這是「奇數日買、偶數日賣」的反向規則。

規則：

```text
偶數日：目標持倉 100%
奇數日：目標持倉 0%
```

其他交易邏輯完全相同。

### 8.3 固定 N 日切換持倉

使用者輸入一個正整數 N。

系統從回測第一根 K 線開始，以交易 K 線數量計算，不用日曆天。

規則固定為：

```text
前 N 根 K 線：目標持倉 100%
接下來 N 根 K 線：目標持倉 0%
再接下來 N 根 K 線：目標持倉 100%
如此循環
```

例如 N = 5：

```text
第 1-5 根：持倉
第 6-10 根：空倉
第 11-15 根：持倉
第 16-20 根：空倉
```

固定 N 日切換的 N 存在任務條件中。

### 8.4 每天開盤買、收盤賣

這條規則不使用一般 execution mode。

每根 K 線都固定執行：

```text
開盤價買到滿倉
收盤價賣到空倉
```

因此它只持有單根 K 線內的開盤到收盤期間，不持有隔夜部位。

每日 NAV 使用收盤賣出後的現金資產計算。

手續費與滑價會在開盤買入、收盤賣出各套用一次。

此規則的日終 `actual_exposure_weight` 為 0%，但必須額外輸出 `intraday_exposure_weight = 100%`，以呈現盤中曝險。

## 九、曝險序列打散對照 N 組

曝險序列打散對照用來檢驗選定參數的擇時能力。

它不是隨機持倉，而是保留選定參數本身的曝險特徵，只打亂曝險出現的日期。

它要回答：

```text
這組參數把倉位放在那些日期，是否比隨機放日期更好？
```

### 9.1 輸入

系統先用選定參數與共同回測條件跑一次正式回測。

正式回測必須產生每日實際持倉比例序列：

```text
date_1: 0%
date_2: 50%
date_3: 100%
date_4: 20%
date_5: 0%
...
```

此序列必須使用 `actual_exposure_weight`，也就是成交後實際持倉比例，不得使用目標權重。

### 9.2 打散方式

系統取出完整的每日實際持倉比例序列，只打亂日期順序。

原序列：

```text
[0%, 0%, 50%, 100%, 25%, 0%, 80%]
```

打散後：

```text
[25%, 0%, 100%, 0%, 80%, 50%, 0%]
```

此方法保留：

- 持倉天數
- 總曝險量
- 平均實際倉位
- 每日倉位大小分佈
- 倉位粒度

只改變：

- 哪一天持有多少倉位

### 9.3 回測方式

每一組打散曝險序列都走專用回測器。

此回測器不呼叫策略 `Step()`，因為每日目標曝險已由打散後序列決定。

每日流程：

```text
讀取當日指定曝險比例
→ 依照目標曝險比例調整持倉
→ 套用 execution mode
→ 套用手續費與滑價
→ 計算每日 NAV
```

與無意義規則不同，曝險序列打散對照允許 0% 到 100% 的部分持倉，因為它必須保留原參數的實際倉位比例。

### 9.4 隨機性與可重現性

曝險序列打散使用 seed。

同一個：

- 參數
- 標的
- 區間
- 費用設定
- execution mode
- seed
- 打散次數 N

必須得到完全相同結果。

若要增加打散數量，系統用同一 seed 繼續產生後續打散，不重新換一批。

### 9.5 保存方式

每次任務保存：

- 曝險打散 seed
- 曝險打散目標數量
- 已完成數量
- 每組打散結果摘要
- 代表性打散 NAV
- 正式參數在打散分佈中的百分位

### 9.6 輸出與比較

曝險序列打散 N 組會形成一個分佈。

系統顯示：

```text
正式參數 log 期末淨值比贏過多少 % 的曝險打散結果
正式參數 MaxDD 優於多少 % 的曝險打散結果
正式參數 Sortino 贏過多少 % 的曝險打散結果
正式參數最長水下期優於多少 % 的曝險打散結果
```

## 十、共同交易引擎

無意義規則不進入策略核心，不呼叫策略 `Step()`。

它們使用獨立的對照規則回測器：

```text
規則產生每日目標持倉
→ 對照回測器依目標持倉交易
→ 套用費用與滑價
→ 產生 NAV 與統計結果
```

無意義規則目標持倉只允許：

```text
0% 或 100%
```

不支援隨機持倉，不支援其他部分持倉規則。

曝險序列打散對照使用獨立的曝險序列回測器，允許 0% 到 100% 的部分持倉，僅用於重放打散後的 `actual_exposure_weight` 序列。

## 十一、任務執行流程

建立任務時：

```text
選定參數與回測條件
或由 M 選定穩健候選
→ 選擇或建立隨機參數批次
→ 設定隨機參數 N
→ 設定曝險打散 N
→ 設定固定切換 N
→ 建立對照分析任務
```

執行時：

```text
跑正式參數回測
→ 產生正式 NAV 與每日實際持倉比例
→ 跑隨機參數 N 組
→ 跑無意義規則
→ 跑曝險序列打散 N 組
→ 統計分佈與百分位
→ 保存摘要與詳細結果
```

## 十二、整體架構

完成後架構為：

```text
選定參數 + 回測條件
        ↓
正式參數回測
        ↓
產生正式 NAV + 每日實際持倉比例序列
        ↓
隨機參數與無意義規則對照系統
        ├─ 隨機參數 N 組
        ├─ 無意義規則
        └─ 曝險序列打散對照 N 組
        ↓
統一比較報表
```

## 十三、重用與去重

建立任務前，系統檢查是否已有相同任務。

相同任務條件包含：

- 選定參數
- M 候選與來源研究設定，如有
- 標的
- 資料源
- 週期
- 起訖時間
- execution mode
- 初始資金
- 每月投入
- 手續費
- 滑價
- 隨機參數批次 ID
- 隨機參數目標數量
- 曝險打散 seed/N
- 固定切換 N
- 規則版本
- 統計版本
- 參數空間 schema、K 模型與動態政策 hash，如有

若已有完成任務，系統提示使用者開啟既有任務或重新計算。

同一回測條件與同一隨機參數批次下，若已存在隨機參數回測結果，系統應優先重用既有結果，避免重複計算。

## 十四、任務內可延伸測試

任務不是跑完就封死的報表。使用者可以打開任務後繼續展開測試。

任務內可以：

- 查看既有結果
- 補算新增統計項目
- 增加隨機參數數量
- 增加曝險打散數量
- 重算失敗項目
- 新增備註
- 新增標籤
- 保存更多代表性 NAV

增加隨機參數數量時，同一隨機參數批次向後擴充：

```text
原本第 1-100 組
追加第 101-500 組
```

增加曝險打散數量時，用同一 seed 繼續產生後續打散結果。

每次延伸完成或形成可查看的部分結果時，都建立新的 `ControlAnalysisSnapshot`。舊 snapshot 保留原本納入範圍、統計與內容 hash，供既有 N 工作區、M 連結或人工研究紀錄繼續重開；不得讓任務最新結果靜默改寫舊引用。

## 十八、完整比較邏輯

一個任務完成後，使用者看到的是：

```text
正式參數
vs
同一批隨機參數
vs
同一組無意義規則
vs
同一批曝險打散結果
```

重點不是只看誰最高，而是看正式參數在各分佈中的位置：

```text
正式參數 log 期末淨值比贏過多少 % 隨機參數
正式參數 MaxDD 優於多少 % 隨機參數
正式參數 Sortino 贏過多少 % 隨機參數
正式參數 log 期末淨值比贏過多少 % 曝險打散
正式參數最長水下期優於多少 % 曝險打散
```

無意義規則逐條列出，作為固定對照。

## 十九、與 N 通用比較工具的關係

### 19.1 參數比較來源

H 隨機參數庫中的每一筆隨機參數都是可加入 N「參數比較」的獨立來源。唯讀比較資料至少包含：

- 隨機參數紀錄 ID 與內容 hash。
- 所屬批次、seed、N、生成版本及參數範圍版本。
- 參數空間 schema、合法步長與完整參數內容。
- K 模型 artifact、預測 schema、結構與動態政策 hash，如適用。
- 已參與的 H 任務及回測結果連結。

隨機參數仍屬於 H 的隨機參數庫，不因加入 N 而成為正式參數庫紀錄、M 候選或可 Promote 參數。

### 19.2 研究結果比較來源

H 以精確的任務結果 snapshot 作為 N「研究結果比較」來源，至少提供下列區塊：

- 共同回測條件、受測參數 canonical 來源與 snapshot 完整度。
- 受測參數的既有回測與 G 引用。
- 隨機參數分佈及受測參數在分佈中的位置。
- 四種無意義規則的既有結果。
- 曝險序列打散分佈及受測參數位置。
- 缺漏、失敗、取消、補算與快取狀態。

受測參數若已來自正式參數庫或 M 候選，N 參數分頁只引用該 canonical 來源；H 任務只提供 lineage，不另建一份重複參數。

### 19.3 固定版本與唯讀限制

- N 固定引用 H task、result snapshot、統計版本與內容 hash。
- H 增加隨機參數數量、曝險打散數量、補算統計或續跑後建立新版 snapshot；舊 N 工作區不自動更新。
- 完整分佈與代表 NAV 只在 N 展開區塊時讀取。
- N 不得從 H adapter 建立、補算、增加 N、改 seed、改固定切換天數或重算失敗項目。
- N 只保存 H 引用與畫面狀態，不複製隨機參數庫、回測或分佈 payload。

## 二十、資料清理

系統提供人工清理，不自動亂刪。

可以：

- 刪除任務
- 刪除詳細 NAV，只保留摘要
- 刪除失敗任務
- 封存舊任務
- 清理未被任何任務引用的隨機參數批次

刪除或清理前必須列出受影響的 N 工作區。若 H 自身規則允許硬刪，N 必須保留缺失 placeholder；不得靜默移除比較項目。

## 二十一、完成判準

使用者選一個參數與回測條件後，可以一次產生上述六類對照結果，並在同一畫面比較正式參數、隨機參數分佈、無意義規則表現、曝險序列打散分佈。

M 穩健候選可以建立並雙向連結同一種對照任務；對照結果不得因由 M 啟動而改用另一套回測或統計定義。

使用者可以重開任務查看既有結果，並能在同一任務中補算新增統計、增加隨機參數數量、增加曝險打散數量或重算失敗項目。

若系統尚未能從正式回測取得每個 NAV point 的 `actual_exposure_weight`，本功能不得視為完成。

H 的單筆隨機參數與結果 snapshot 必須能透過固定版本、schema 與內容 hash 提供給 N 按需唯讀比較；N 的讀取不得建立、追加或續跑 H 任務。
