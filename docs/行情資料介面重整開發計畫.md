# 行情資料介面重整開發計畫

狀態：已實作；登入後的瀏覽器互動驗收待進行。
文件定位：介面重整開發計畫；只調整前端資訊架構與互動呈現，不改變行情資料、不可變版本、資料血緣、權限或回測語義。

## 一、背景與目標

目前「行情資料」頁同時承擔資料更新總覽、價格圖表、手動匯入、資料維護、商品設定與排序等工作。所有資訊依序堆在同一頁，正常資料也會佔用大量畫面，使使用者難以快速回答兩個最常見的問題：

1. 哪些行情資料需要處理？
2. 目前選取的行情資料長什麼樣子、是否可用？

本次改版目標是讓日常使用以「查看資料狀態與行情」為中心；匯入、修復與設定等管理操作僅在需要時出現，但仍有清楚且固定的入口。

## 二、確認中的介面結構

「行情資料」維持單一路由與單一頁面，桌面版採左右兩欄，窄螢幕改為上下排列。

### 2.1 頁首

- 商品搜尋。
- 市場篩選。
- 狀態篩選：全部、需處理、已更新、異常。
- 固定保留「更新全部」按鈕。
- 以簡短摘要顯示整體結果，例如「24 組資料皆為最新」或「3 組資料待更新」。

### 2.2 左側：資料清單

資料清單改用緊湊列式呈現，不再以大量週期卡片作為主要資訊架構。每列至少顯示：

- 商品名稱與代號。
- 市場。
- 可用週期。
- 最新狀態：已更新、待更新或異常。
- 最後更新時間。

預設排序為：異常、待更新、最近使用、其他。點選任一商品後，在右側顯示其詳細內容。

清單上方以固定切換控制資料類別：

- 原始行情。
- 參考指標。
- 研究行情。

研究行情需延續既有使用者可見分類，分組為倍數產生行情、片段重組行情、局部擾動行情與其他研究行情；不得混入原始行情或參考指標。每筆研究行情需保留查看與可回測資格的既有規則。

### 2.3 右側：選取資料工作區

右側上方為行情圖表與既有圖表控制項。使用者選取商品、研究版本或週期後，圖表、日期範圍與資料狀態同步切換。切換「收盤價走勢」或「K 線」時，所有已疊合資料必須同步改用相同呈現方式；多組 K 線以主要行情完整顯示、其餘較低透明度顯示，全部維持綠漲紅跌，僅以色階的明度與飽和度區分不同資料。

圖表下方使用三個可展開區塊：

1. **資料狀態**：週期、筆數、資料起訖、最後更新、價格口徑與必要警示；預設展開。
2. **資料操作**：手動匯入、週期與日期範圍、收盤前快照選項；預設收合。
3. **維護與進階**：檢查、修復、完整重匯、新增或編輯商品、排序與停用等操作；預設收合。

「維護與進階」不得只以圖示呈現，需有可辨識文字入口。任何可能改變既有回測結果的完整重匯或修復，延續既有確認提示與影響說明。

### 2.4 行情產生器的關係

行情產生器維持既有獨立頁面與路由，不併入本頁。於研究行情清單或空狀態提供明確的「建立研究行情」入口，導向既有行情產生器，避免使用者在查看資料時找不到建立入口。

## 三、實作邊界

### 本次會做

- 重整 `行情資料` 前端頁面的版面、元件拆分與響應式呈現。
- 保留所有既有資料讀取、更新、匯入、維護、商品管理與排序能力。
- 保留現有路由、後端 API、資料來源分類及研究行情可回測限制。
- 加入清楚的空狀態、無權限／已停用資料提示與管理入口。

### 本次不做

- 不新增或變更行情資料表、不可變版本、內容雜湊、血緣、權限與資料更新規則。
- 不改變研究行情的分類契約或回測請求語義。
- 不改變回測、策略、參數搜尋或資料產生器的數學與計算邏輯。
- 不將行情產生器併入行情資料頁。

## 四、風險與防護

| 風險 | 防護方式 |
|---|---|
| 功能被收合後難以找到 | 「資料操作」與「維護與進階」維持固定文字入口；新增商品與產生器入口亦需可見。 |
| 商品、週期、圖表和匯入設定不同步 | 以同一份選取資料與週期狀態驅動各區塊；切換後統一重設或保留既有日期規則。 |
| 搬移元件後操作成功但畫面未刷新 | 沿用既有 API 與查詢刷新流程；每個成功操作後驗證清單、詳情與圖表同步更新。 |
| 研究行情和原始行情混淆 | 沿用既有來源分類與可回測資格，並在清單上固定分流。 |
| 已停用、封存或無權限資料造成空白頁 | 顯示明確提示並退回可選清單，不得產生白畫面或失效選取狀態。 |
| 窄螢幕兩欄擁擠 | 在窄螢幕改為上下排列；清單與選取內容均可完整操作。 |

## 五、驗收方式

完成後至少驗證下列操作：

1. 搜尋、依市場／狀態篩選與排序資料清單。
2. 切換原始行情、參考指標與各類研究行情，分類與可回測資格正確。
3. 點選商品、切換週期與日期範圍後，圖表、資料狀態與資料操作設定正確同步。
4. 更新全部、單筆匯入、檢查、修復、完整重匯、商品新增／排序等既有操作均可完成，成功後畫面更新。
5. 完整重匯與修復仍有既有警示與確認流程。
6. 行情產生器入口可正確導向既有頁面。
7. 已停用或不再可用的選取資料有可理解提示，不出現白畫面。
8. 桌面與窄螢幕版面皆可操作。
9. 前端正式建置通過，並以登入後瀏覽器實際操作驗收。

## 六、完成定義

本項目採一次到位，不做 MVP。只有在上述資訊架構、既有操作保留、分類規則、響應式行為與驗收項目均完成後，才可稱為「已完成」。若只完成新排版但尚未驗證既有操作，狀態必須回報為「部分完成」。
