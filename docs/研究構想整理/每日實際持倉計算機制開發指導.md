# 每日實際持倉計算機制開發指導

> 狀態：已完成；原「待討論」標記為文件誤植
>
> 用途：定義回測結果中「每日實際持倉比例」的計算方式、語義、輸出欄位與使用場景。此文件不是三份真源文件，不取代既有穩定系統規格。

## 一、功能定位

每日實際持倉比例用來表示：

```text
當天 NAV 點成立時，帳戶實際持有風險資產的市值，占總資產的比例。
```

此欄位反映實際成交後的帳戶狀態，不是模型目標，不是理論權重，也不是實務模型目標權重。

## 二、欄位名稱

後端欄位名稱：

```text
actual_exposure_weight
```

前端顯示名稱：

```text
實際持倉比例
```

## 三、核心公式

任一 NAV 點的每日實際持倉比例為：

```text
actual_exposure_weight = 風險資產市值 / 總資產
```

以目前回測內部資料結構表示：

```text
asset_qty = DeadBTC + FloatBTC + ColdSealedBTC

asset_value = asset_qty * price

total_equity = USDTBalance + asset_value

actual_exposure_weight = asset_value / total_equity
```

雖然目前欄位名稱含有 `BTC`，但在 SOXL、SOX_3X 或其他非 BTC 標的回測中，這些欄位代表該回測標的的資產數量。

計算結果必須限制在：

```text
0 <= actual_exposure_weight <= 1
```

若 `price <= 0` 或 `total_equity <= 0`，則該點實際持倉比例為 0。

## 四、與既有權重欄位的差異

系統中至少存在三種不同權重語義：

```text
model_target_weight
```

基準模型目標權重。代表模型理論上想要多少總倉位。

```text
practical_target_weight
```

實務模型目標權重。代表套用強制滿倉/空倉與調倉門檻後，實務模型採用的目標。

```text
actual_exposure_weight
```

實際持倉比例。代表交易真正執行後，帳戶實際持有多少資產。

`model_target_weight` 與 `practical_target_weight` 是目標；`actual_exposure_weight` 是結果。

系統必須允許下列狀態被正確呈現：

```text
practical_target_weight = 100%
actual_exposure_weight = 0%
```

這代表模型目標是滿倉，但實際上沒有成交或沒有持倉。

## 五、計算時間點

每日實際持倉比例必須和 NAV 使用同一個時間點計算。

每個 NAV point 的流程為：

```text
依 execution mode 套用應執行的交易
→ 使用該 NAV point 的計價價格計算 total_equity
→ 使用成交後持倉計算 actual_exposure_weight
→ 寫入 NAV point
```

`actual_exposure_weight` 不得提前反映尚未成交的目標。

## 六、close_same_bar 語義

當 execution mode 為 `close_same_bar`：

```text
當日收盤產生訊號
→ 當日收盤成交
→ 當日 NAV 使用成交後持倉與當日收盤價計算
→ actual_exposure_weight 使用成交後持倉與當日收盤價計算
```

因此此模式下，當日 NAV point 的實際持倉比例反映當日收盤成交後的帳戶狀態。

## 七、close_next_open 語義

當 execution mode 為 `close_next_open`：

```text
第 T 日收盤產生訊號
→ 第 T+1 日開盤成交
→ 第 T+1 日 NAV 使用成交後持倉與第 T+1 日收盤價計算
→ 第 T+1 日 actual_exposure_weight 使用成交後持倉與第 T+1 日收盤價計算
```

第 T 日不得因尚未成交的 pending 訊號提前改變 `actual_exposure_weight`。

## 八、每天開盤買、收盤賣規則的特殊處理

「每天開盤買、收盤賣」對照規則每天固定：

```text
開盤價買到滿倉
收盤價賣到空倉
```

該規則的每日 NAV 使用收盤賣出後的現金資產計算，因此日終：

```text
actual_exposure_weight = 0%
```

但該規則當天曾經有盤中曝險，所以此規則必須額外輸出：

```text
intraday_exposure_weight
```

此欄位代表該 NAV point 對應期間內的盤中曝險。對「每天開盤買、收盤賣」規則而言：

```text
intraday_exposure_weight = 100%
```

正式參數回測與一般對照規則主要使用 `actual_exposure_weight`；每天開盤買、收盤賣規則同時顯示 `actual_exposure_weight` 與 `intraday_exposure_weight`。

## 九、月投入對實際持倉比例的影響

若回測設定包含每月投入，投入後現金增加，實際持倉比例會被稀釋。

例如：

```text
投入前：
資產 1000
現金 0
實際持倉比例 = 100%

投入 100 現金後：
資產 1000
現金 100
實際持倉比例 = 1000 / 1100 = 90.9%
```

此結果正確，因為帳戶真的多了一部分未投入現金。

## 十、費用、滑價與最小交易額

每日實際持倉比例必須使用成交後結果計算。

若買入時因手續費或滑價導致實際買到的資產少於目標，`actual_exposure_weight` 必須反映實際買到的資產市值。

若目標滿倉，但現金低於 Dust 或最小交易額而沒有產生買單，則：

```text
沒有成交 → 沒有增加持倉 → actual_exposure_weight 不變
```

不管目標權重如何顯示，實際持倉比例都必須忠實反映成交後持倉。

## 十一、主要用途

每日實際持倉比例用於：

1. 回測圖表顯示
   - 觀察目標權重與實際持倉是否脫鉤。

2. 參數診斷
   - 計算平均實際倉位。
   - 計算持倉天數比例。
   - 計算曝險調整報酬。

3. 曝險序列打散對照
   - 取出每日實際持倉比例序列。
   - 打散日期順序。
   - 重新回測以檢驗擇時能力。

4. 錯誤排查
   - 快速看出「目標滿倉但實際沒有持倉」等問題。

## 十二、完成判準

任一正式回測結果，每個 NAV point 都必須包含：

```text
actual_exposure_weight
```

此欄位必須與同一 NAV point 的 `total_assets`、`price` 與成交後持倉在數學上相容：

```text
actual_exposure_weight = actual_asset_value / total_assets
```

且它反映的是成交後實際持倉，不是模型目標。
