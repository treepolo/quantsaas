# 參數績效地形研究與穩健候選產生系統開發指導

> 狀態：P14 已完成完整驗收、N 唯讀固定快照介面與舊搜尋退場；M 已完成
>
> 對應大點：M. 參數績效地形研究與穩健候選產生系統
>
> 用途：定義 M「參數績效地形研究與穩健候選產生系統」的完成品行為、資料契約、計算流程、頁面、遷移、測試與完成判準。本文件不是三份穩定真源；M 完整實作、測試並經使用者核准前，不得把本規格寫回穩定真源。

## 一、提出背景

既有參數搜尋的主要操作是反覆執行搜尋，從每次結果中取得歷史績效最高的參數。搜尋過程保存每代出現過的參數，並以平行座標圖與降維散點圖觀察參數族群。

未來研究流程要改為：

```text
建立一份完整研究設定
→ 完成該設定下預先規劃的參數空間研究
→ 取得績效地形與穩健區域
→ 從不同合格連通區域與穩健候選前緣產生數組候選
→ 對候選執行不同可用性檢驗
→ 由使用者比較與採用
```

主要研究產物不再是「某次搜尋的最高分個體」，而是：

- 可重現的研究設定。
- 已實際計算的參數評估點。
- 一維、二維及多維績效地形資料。
- 合格連通區域、績效等高帶與連續平坦度指標。
- 區域內的穩健候選前緣與中心候選。
- 候選的各項驗證結果。
- 完整人工採用紀錄。

## 二、研究目的

M 要回答：

```text
在固定資料、回測語義與研究設定下，
哪些參數區域能持續維持合理績效，
哪些候選能同時兼顧績效、區域內部距離與鄰域穩定性，
以及這些候選通過了哪些額外驗證？
```

M 不以找出單一歷史最高點為完成目標。

## 三、字母大點與模組分工

已確認責任分工：

| 模組 | 責任 |
|---|---|
| A | 抗過擬合研究的總目標與研究治理 |
| I | 原子計算、進度、取消、快取與複合任務基礎設施 |
| J | 績效地形、合格連通區域、連續穩健性與中心提案 |
| K | 市場預測、結構狀態、動態政策與動態參數空間 |
| M | 研究設定、分階段探索、候選生命週期、驗證鏈與人工採用 |

M 不重複實作 I、J、K 的底層能力。

## 四、M 與 J 的邊界

J 負責：

- 接收已完成的參數評估點。
- 計算一維曲線、二維 heatmap、3D 曲面與多維鄰域統計。
- 辨識合格連通區域，計算績效等高帶與連續平坦度。
- 建立同時保留績效與穩健性目標的候選 Pareto 前緣。
- 計算區域內部距離，並從不同合格連通區域輸出中心提案。

M 負責：

- 決定哪一份研究設定正在執行。
- 建立參數空間與計算計畫。
- 調用 I 執行評估點。
- 把評估點交給 J。
- 把 J 的中心提案保存為候選。
- 管理候選的驗證、比較、備註、標籤與採用狀態。

J 不管理採用；M 不自行重算 J 的地形幾何。

## 五、M 與 K 的邊界

K 輸出：

- 凍結模型 artifact。
- OOF 預測資料。
- 狀態規則。
- 動態政策 schema。
- 可研究變數、合法範圍、步長與結構限制。
- 每日有效參數提供器。

M 使用這些契約研究固定、全域、連續動態或六狀態切換參數。

K 不指定 M 使用 GA、格點或其他取樣器；M 也不得修改 K 的預測模型或以策略 P&L 重新訓練 K。

## 六、一份研究設定

一份研究設定必須不可變，至少綁定：

- 名稱、備註與標籤。
- 商品、資料源、週期與 dataset hash。
- 研究起訖時間與 warmup 規則。
- execution mode。
- 初始資金、現金流、手續費與滑價。
- position structure。
- 長週期濾網設定。
- 參數空間 schema 與版本。
- 哪些欄位是本次研究變數、哪些是本次研究常數。
- 每個研究參數的範圍、步長與精度。
- K 模型、預測與動態政策設定，如有。
- 回測核心、策略、分析與取樣版本。
- 預定產出的地形、統計及驗證項目。

任何會改變回測語義、參數空間或資料內容的設定變更，都必須複製成新研究設定，不得在既有結果上靜默覆寫。

### 6.1 結構設定不形成同一張地形的座標軸

下列項目屬於一份研究設定的結構，不是同一張連續績效地形中的相鄰值：

- 模型路線或凍結模型。
- K 的核心參數控制模式。
- D 濾網是否啟用及 N 月線設定。
- execution mode。
- 商品、資料、區間與週期。
- 策略、回測核心與分析版本。

改變上述設定時必須建立另一份研究設定。多份設定未來可以放進同一研究系列並排比較，但評估點不得混成同一張地形，也不得共同計算合格連通區域、候選前緣或中心。

### 6.2 研究變數與研究常數

M 統一使用：

- `研究變數`：數值在同一研究設定的不同評估點之間改變，因此形成參數空間維度。
- `研究常數`：數值或政策在該研究設定的所有評估點都相同，因此不形成維度，但仍是每次回測的完整輸入。

「研究常數」只描述評估點之間是否改變，不代表每日執行時一定不變，也不得與 K 的「固定值模式」混用。

例如 Beta 採 K 連續動態模式，但本次 M 研究只改變 Gamma：Beta 的動態政策仍會使每日有效 Beta 改變；若該政策在所有評估點都相同，它在本次 M 任務中仍屬研究常數。

同一個核心參數可在不同研究設定中分別作為研究變數或研究常數，並非永久鎖定。

### 6.3 研究變數範圍模式

每個數值研究變數支援三種範圍模式：

1. 完整合法範圍。
2. 以中心值加指定半徑或格數。
3. 使用者直接指定最小值與最大值。

規則：

- 研究範圍不得超出合法範圍。
- 範圍端點與每個評估值都必須對齊參數空間 schema 的合法步長。
- 核心參數沿用 J 已確認的預設顯示精度與步長。
- K 動態係數使用 K schema 各自定義的精度與步長，不強迫套用核心參數的 `0.05`。

### 6.4 地形碰到研究邊界

若合格區域、等高帶或候選前緣碰到使用者指定的研究範圍邊界：

- 標記為「地形被截斷」。
- 指出碰到哪個參數及哪一側邊界。
- 提示可建立擴大範圍的後續研究設定或補充階段。
- 在邊界外尚未確認前，不得宣稱已找到完整合格連通區域或穩健中心。
- 不得把被截斷區域的表面中心直接宣稱為穩健中心。

## 七、「完整結果」的定義

完整結果不代表窮舉連續數學空間，也不代表窮舉所有高維笛卡兒積。

例如 6 個參數各取 21 格：

```text
21^6 = 85,766,121 個評估點
```

因此 M 的「完整結果」定義為：

```text
該研究任務預先宣告的計算階段與評估點均已完成，
每個階段的資料、版本、缺漏與取消狀態都可追溯。
```

不得以插值或代理模型未經標示的預測點冒充已實際回測點。

## 八、已確認的高階執行流程

```text
建立不可變研究設定
→ 顯示第一階段計算計畫與計算量
→ 使用者明確啟動
→ 執行全域分散探索
→ 找出潛力區域
→ 逐區提出局部細化計畫與計算量
→ 使用者啟動細化
→ J 計算地形、穩健區域與中心提案
→ M 保存多組候選
→ 候選連結各項驗證任務
→ 使用者比較並人工採用
```

每個階段都必須：

- 在執行前顯示計算量。
- 由使用者明確啟動。
- 可取消。
- 保留已完成有效點。
- 可在之後補算。
- 優先重用相同 hash 的標準化回測結果。

M 不因開啟頁面而自動執行完整研究。

## 九、參數空間與評估點

每個研究變數必須有穩定 schema：

- 變數 ID。
- 顯示名稱。
- 合法範圍。
- 研究範圍。
- 最小有效步長。
- 顯示精度。
- 連續、離散或類別型態。
- 本次作為研究變數或研究常數。
- 結構限制。

所有評估點在回測前先正規化到合法步長，避免以小數點後大量無意義位數製造不同 fingerprint。

概念上的 `ResearchEvaluationPoint` 至少包含：

- 研究設定 ID。
- 階段與取樣批次 ID。
- 完整標準化參數向量。
- 參數向量 hash。
- 標準化回測結果 ID。
- 報酬分析報告 ID，如已計算。
- J 指標與合格狀態。
- 實際計算或代理估計標記。
- 狀態、錯誤與建立時間。

評估點只引用標準化回測結果，不重複保存完整 NAV。

### 9.1 預設全域探索取樣

M 的預設全域探索使用 Sobol 低差異序列，不使用普通獨立隨機抽樣，也不使用完整高維格點窮舉。

第一批全域點由下列部分組成：

```text
基準參數點
+ 每個研究維度單獨到達最小值的軸向邊界點
+ 每個研究維度單獨到達最大值的軸向邊界點
+ Sobol 低差異序列點
```

軸向邊界點只改變一個研究變數，其餘研究變數維持基準值；不預設計算所有 `2^d` 個角落組合。

Sobol 點的轉換流程：

```text
每維 [0,1] 座標
→ 映射到該研究變數的合法格點索引
→ 對齊 schema 步長
→ 套用結構限制
→ 參數向量去重
→ 執行實際回測
```

規則：

- 每個維度依自己的合法格點數映射，不按原始數值絕對大小分配抽樣權重。
- 序列版本、起始索引、已使用索引範圍與映射版本必須保存。
- 量化後重複的參數向量跳過，並繼續向後取得 Sobol 點，直到形成該批預定的唯一點數。
- 無效或違反結構限制的向量不得送入回測；其原因與 Sobol 索引必須保存。
- Sobol 只負責安排要計算的參數點，不屬於已取消的 Monte Carlo、bootstrap 或隨機行情測驗。
- 全域 Sobol 點集合是稀疏高維探索資料，不得冒充完整曲面。
- Sobol 階段只提出局部細化候選點，不得把稀疏全域點直接宣稱為合格連通區域、穩健候選前緣或完整曲面；區域判定必須交由後續 J 的局部實測完成。

### 9.2 第一批點數與逐批追加

令 `d` 為本次研究變數數量。第一批 Sobol 唯一點數預設為：

```text
N0 = nextPowerOfTwo(max(64, 16 * d))
```

`N0` 不包含基準點與 `2*d` 個軸向邊界點。

例如：

| 研究維度 d | 第一批 Sobol 唯一點數 |
|---:|---:|
| 2 | 64 |
| 5 | 128 |
| 8 | 128 |
| 10 | 256 |
| 20 | 512 |

此公式是初始探索的工程預設，不是充分覆蓋或不存在其他合格區域的統計保證。

若研究空間所有合法離散組合的總數小於或等於第一批規劃點數，系統直接完整枚舉所有合法組合，不使用 Sobol 抽樣。

後續全域批次延伸同一條 Sobol 序列，累積唯一點數依序加倍：

```text
N0 → 2*N0 → 4*N0 → 8*N0 ...
```

不得丟棄前一批或重新生成一套無法接續的全域點。

每批開始前必須先完成量化、結構驗證、去重與快取查詢，產生精確 manifest，至少顯示：

- 累積唯一評估點數。
- 本批新增唯一點數。
- 基準點與軸向邊界點數。
- 快取命中數。
- 實際新增回測數。
- 預估時間與磁碟用量。
- 計算硬上限與取消方式。

使用者可以改選其他 `2^m` 點數，但 UI 預設推薦上述公式。是否需要繼續加倍，不以「最高分是否增加」單獨判定，並依第 9.4 節的批次檢查點機制處理。

### 9.3 全域評估點保存與局部細化候選

所有基準點、軸向邊界點與 Sobol 點只要已完成實際回測，就必須完整保存其參數向量、研究設定引用、回測結果引用、分析指標、來源批次與序列位置。是否符合細化條件只是一個可重算的分類，不是資料保存條件；不得丟棄未合格點。

每個全域評估點依 J 已確認的兩項條件分類：

```text
總報酬贏過 DCA
且
最大回撤小於 DCA
```

同時符合兩項條件的既有評估點，額外標記為「自動細化候選點」。此標記只引用原始評估點，不複製回測資料，也不代表該點已是穩健中心或正式候選參數。

未符合條件的評估點仍然：

- 保留在完整全域資料集中。
- 顯示不合格原因與各項績效指標。
- 可在分類規則或分析版本改變後重新分類，不必重新回測。
- 可由使用者手動選為局部細化中心。
- 可列入未合格 Pareto 點檢視，但不得自動稱為潛力區域。

自動細化候選點的建議優先順序使用兩項彼此分離的指標建立 Pareto 層級：

- `log(策略期末 NAV / DCA 期末 NAV)`，越大越好。
- `log((1 - 策略 MaxDD) / (1 - DCA MaxDD))`，越大越好。

績效回撤綜合指標可以顯示與排序，但不得單獨決定評估點是否合格、是否保存或是否可細化。所有合格候選點均保留；Pareto 層級只安排建議檢視與細化順序。

局部細化使用 J 的實際回測點與既定多尺度半徑。只有當局部資料足以判定離散連通關係後，才可以辨識合格連通區域、連續平坦度、針尖風險、候選前緣與穩健中心。不得以稀疏 Sobol 點、未標示插值或代理估計直接做上述結論。

若不同細化任務包含相同參數點，必須由 I 的 manifest、快取與去重機制共用既有結果。位於研究範圍邊界的細化候選仍保留，但必須標示遭邊界截斷的維度、方向與建議擴張範圍。若一批全域探索沒有任何自動細化候選，系統只能提出延伸同一 Sobol 序列或由使用者手動細化未合格點，不得捏造潛力區域。

### 9.4 全域探索與局部細化停止規則

只有完整枚舉研究空間內全部合法離散組合，才可以把全域探索標記為「完整探索」。任何有限 Sobol 抽樣都不得宣稱已證明未知區域不存在其他合格點或合格連通區域。

預設不採用下列自動停止方式：

- 最高績效連續數批沒有增加。
- 合格率或 Pareto 前緣變化低於任意預設門檻。
- 代理模型自行判定已收斂。

全域探索採逐批檢查點。每批完成後，系統必須保存當前狀態並顯示：

- 本批與累積唯一評估點數。
- 本批與累積合格點數、合格率。
- 本批新增的自動細化候選點。
- Pareto 第一層新增、被取代與保留的評估點。
- `log 期末淨值比` 與 `log 最大回撤殘值比` 各自的分佈變化。
- 位於研究邊界的合格點與建議擴張方向。
- 下一批新增點數、快取命中、實際回測量、預估時間與磁碟用量。

每個檢查點提供三個明確動作：

```text
追加下一批
結束全域探索並進入局部細化
暫停
```

「結束」與「暫停」都不得刪除資料或中斷同一 Sobol 序列的可續跑性。任務日後必須能從已保存的下一個 Sobol 索引繼續。

全域探索狀態至少區分：

- `完整探索`：全部合法離散組合已枚舉。
- `部分探索已結束`：使用者主動結束，但未完整枚舉。
- `已暫停`：可從同一序列繼續。
- `達硬上限暫停`：達到回測數、時間或儲存上限，並非收斂。
- `已取消`：依 I 的取消語義保存已完成結果與未完成 manifest。

局部細化不使用績效收斂停止。每次局部細化先由 I 產生有限且精確的 manifest；全部指定實際評估點完成時，該次細化才標記為完成。擴大半徑、擴張遭截斷邊界或補算缺漏點，均建立可追溯的延伸任務並重用既有結果，不在原任務中暗中增加範圍。

## 十、地形與候選

已確認原則：

- 一維曲線與二維曲面只是高維空間切片。
- 不得分別選取各張一維圖的最佳值再拼成一組參數。
- 多維交互作用必須由實際多維評估資料檢查。
- 最終候選必須同時考慮績效與穩健性，不是只選孤立最高點。
- 不同合格連通區域可以各自保留候選。
- 候選不因被產生就自動成為正式採用參數。

正式分類不增加第二道「高績效高原」二元門檻，也不得保存 `is_high_plateau` 一類欄位。原因是固定絕對門檻無法合理跨商品與期間共用，而相對最高點或固定分位數會受針尖影響，或在不存在高原時仍強迫切出一塊高原。

J 與 M 改以四種不同產物表達：

- `合格連通區域`：由「總報酬贏過 DCA 且最大回撤小於 DCA」及離散連通規則形成的正式二元分類。
- `績效等高帶`：使用者在已計算績效上調整顯示門檻的視圖；只改變視覺化，不重新回測，也不改變正式分類。
- `連續平坦度與穩健性指標`：保存鄰近變化、多尺度衰退、區域內部距離、合格穩定程度與鄰域離散程度，不強迫切成平坦或不平坦。
- `穩健候選前緣`：以 Pareto 關係保留同時兼顧績效與穩健性的點。

候選前緣至少保留彼此分離的目標：

- `log 期末淨值比`，越大越好。
- `log 最大回撤殘值比`，越大越好。
- 未受資料缺口或研究邊界截斷的保證合格方盒半徑，越大越好。
- 多尺度鄰域合格程度與其穩定性，越高越好。
- 鄰域績效離散程度，越低越好。

績效回撤綜合指標仍可顯示、排序與疊圖，但不得單獨決定正式分類、候選前緣或中心。尚未完成某項按需分析時，基於不完整目標形成的前緣必須標記為暫定，不得冒充完整候選前緣。

### 10.1 正式離散連通規則

合格連通區域用來分辨一整片具有參數容錯能力的合格點、斜向細線與彼此分離的孤立點。正式連通採軸向相鄰，不採對角線相鄰、距離猜測或插值連接。

兩個評估點之間建立正式相鄰邊，必須同時符合：

1. 屬於同一份不可變 `ResearchConfiguration` 與相同分析版本。
2. 兩點都是合法、已實際回測且符合 J 合格條件的評估點。
3. 恰好只有一個研究變數不同。
4. 該研究變數在自己的合法離散值序列中剛好相差一個格點索引。
5. 其他研究變數及全部研究常數一致。
6. 參數 schema、步長與結構版本一致。

合法值不等距時，以排序後的合法格點索引是否相鄰判定，不用原始數值差。固定參數不形成研究維度，也不參與相鄰判定。K 動態政策若是 M 研究常數，不形成連通維度；若其係數被選為研究變數，則依該係數 schema 的合法格點判定。

兩點若同時改變兩個以上研究變數，即使各自只差一格，也不得直接以對角線連接。若兩點之間存在一條每次只改一個研究變數一格、且沿途評估點全部合格的路徑，仍會經由該路徑歸入同一連通分量。

每個評估座標至少區分三種分析狀態：

```text
合格
不合格
未知或尚未計算
```

未知點不得被當成合格點連接，也不得假裝成不合格點。區域邊界必須分別標記：

- 已實測不合格邊界。
- 研究設定範圍邊界。
- 未知或尚未計算造成的資料缺口邊界。

在存在資料缺口時，只能稱為「已觀測合格連通區域」或「已觀測連通片段」，不得宣稱已取得完整區域幾何。稀疏 Sobol 點與高維抽樣同樣受此限制；完整區域邊界必須由足以覆蓋目標範圍的規則格點實測支持。

多尺度半徑 `1、2、3、5、8、13` 只決定統計觀察視窗，不建立不同的連通定義。所有尺度共用相同的基礎合法格點與軸向相鄰圖，各尺度只截取不同範圍計算指標。

後續補算新點可能擴張或合併既有連通分量。每次區域分析必須保存評估點集合 hash、合格分類版本、連通演算法版本與結果版本；新結果不得靜默覆寫舊報告，並需保存區域延續、擴張或合併的 lineage。只有合格分類或連通規則版本改變時，才可能產生區域分裂，並必須另建分析版本。

### 10.2 距離單位、容錯深度與邊界截斷

不同研究變數不得直接以原始數值距離混算。每個研究變數 `i` 先依自己的合法離散值序列轉為格點索引 `g_i`；一個索引單位代表該變數 schema 定義的一個最小有意義步長。固定參數不形成距離維度。

距離計算不得：

- 直接混用不同參數的原始數值單位。
- 除以使用者本次指定的研究範圍後當成主要穩健距離，避免只因擴張掃描範圍就改變同一點的穩健性。
- 依本次歷史績效敏感度替距離加權，避免把待檢驗資料反向寫入幾何定義。

每個合格評估點至少保存下列三組量。

#### 10.2.1 各方向容錯格數

對每個研究變數分別計算向下與向上的連續合格格數。其他研究變數保持不變，沿該軸逐格移動；在抵達實測不合格點、未知點、研究邊界或真正合法邊界時停止，並保存停止原因。

抵達未知點或可擴張的研究邊界時，結果只是目前已保證的下界並標記為截斷。抵達真正合法邊界時，不把不存在的值當成失敗，而是標記為單側合法容錯。

#### 10.2.2 軸向內部深度

`axis_failure_depth` 定義為從目前合格點出發，每次只改一個研究變數一格，沿已知合格點移動後，抵達已實測不合格點所需的最少步數。與不合格點直接相鄰的合格點深度為 `1`。

若在任何已知失敗邊界之前先遇到未知點或研究範圍邊界，深度只能保存為下界並標記截斷，不得捏造精確值。

#### 10.2.3 保證合格方盒半徑

主要穩健距離為 `guaranteed_box_radius`。對中心點 `p` 與整數半徑 `r`，考慮所有合法格點 `q`：

```text
對每個研究變數 i，皆滿足 |g_i(q) - g_i(p)| <= r
```

若上述範圍內每一個合法參數組合都已實際回測且合格，該半徑才被保證。`guaranteed_box_radius` 是符合此條件的最大 `r`。

這代表所有研究變數可以同時在正負 `r` 格內任意變動，而不是只存在一條合格路徑。真正合法邊界以可行參數集合截斷方盒並標記單側狀態；未知點或可擴張研究邊界會使結果成為下界，不能視為完整半徑。

#### 10.2.4 邊界資訊與可比較性

距離結果必須分別保存：

- 到已實測不合格點的資訊。
- 到未知或尚未計算點的資訊。
- 到可擴張研究範圍邊界的資訊。
- 到真正參數合法邊界的資訊。

每項需帶有維度、方向、格數、是否精確、是否截斷及截斷原因。遭未知點或研究邊界截斷的方盒半徑只能參與暫定候選前緣，且不得僅憑該下界支配具有完整精確半徑的點。

距離分析預設只讀取已有評估點，不暗中啟動回測。缺少必要格點時，J 交由 I 產生補算 manifest，先顯示總量、快取命中、預估時間與儲存量，使用者啟動後才補算。高維方盒需要的點數會快速增加；未完整計算時必須顯示下界，或只對使用者選定的一維、二維切片給出完整保證，不得以抽樣點冒充完整方盒。

### 10.3 穩健中心正式選擇規則

穩健中心不使用最高績效單點，也不把不同單位的績效與穩健性指標加權相加。每個合格連通區域分開建立中心，並使用字典式優先規則：只有前一層指標相同時，才進入下一層比較。

正式流程：

1. 只使用實際回測點及已完成全部必要按需指標的結果。
2. 先依第十章已確認的彼此分離目標建立完整穩健候選 Pareto 前緣。若 A 在所有目標都不差於 B，且至少一項更好，B 不進入中心池。
3. 將未截斷雙側點、真正合法邊界造成的單側點，以及未知或研究邊界造成的截斷點分成不同中心池，不直接混比方盒半徑。
4. 在未截斷雙側中心池中，保留 `guaranteed_box_radius` 最大的點。
5. 半徑相同時，保留 `axis_failure_depth` 最大的點。
6. 仍相同時，計算區域 medoid 成本並保留成本最小的點。
7. 仍有多點時，只保留在 `log 期末淨值比` 與 `log 最大回撤殘值比` 上互不支配的點。
8. 若仍有多點，全部保存為同級穩健中心，不再發明加權總分強迫唯一化。

令合格連通區域為 `C`，軸向合格圖上的最短路徑距離為 `d_graph`，則區域 medoid 成本為：

```text
medoid_cost(p) = sum(d_graph(p, q)), q in C
```

它只在方盒半徑與失敗深度相同時使用，用來選擇到整片已知合格區域總路徑距離較小的代表位置，不凌駕主要容錯半徑。

中心完整性分級：

- `正式雙側中心`：區域、方盒、已知失敗邊界及必要指標完整，且未碰到合法邊界。
- `正式單側中心`：資料完整，但方盒被真正合法參數邊界截斷；與雙側中心分池比較。
- `暫定中心`：遭未知點、研究範圍邊界或尚未執行的按需指標截斷。

若某個合格區域沒有可形成正式中心的點，只能輸出暫定中心與精確缺漏 manifest，不得把暫定結果改名為正式中心。補算或分析版本改變後建立新版中心結果，不靜默覆寫舊版。

同級中心可依完整參數格點索引做穩定顯示排序，但排序只為重現 UI 順序，不代表排序第一者更優。每項中心提案必須保存來源研究設定、評估點集合 hash、區域版本、前緣版本、中心演算法版本、完整性分級及截斷原因。

### 10.4 角色式候選與去重

每個合格連通區域不預設固定取前 `N` 名，也不把整條 Pareto 前緣全部建立成正式候選。系統從完整候選前緣自動提出下列角色：

1. `robust_center`：依第 10.3 節穩健中心規則產生。
2. `return_leader`：`log 期末淨值比`最高的前緣點。
3. `drawdown_residual_leader`：`log 最大回撤殘值比`最高的前緣點。
4. `performance_drawdown_composite_leader`：績效回撤綜合指標最高的前緣點。

績效回撤綜合指標沿用 J 已確認公式：

```text
log(策略期末 NAV / DCA 期末 NAV)
*
((1 - 策略 MaxDD) / (1 - DCA MaxDD))
```

此綜合角色只是可解釋的前緣代表，不取代穩健中心，也不影響其他點是否屬於 Pareto 前緣。

角色同分依下列順序處理：

- 報酬領先同分：先比較 `log 最大回撤殘值比`，再套用第 10.3 節容錯順序。
- 回撤控制領先同分：先比較 `log 期末淨值比`，再套用第 10.3 節容錯順序。
- 綜合指標同分：套用第 10.3 節容錯順序。
- 所有正式比較值仍相同：保留同級角色點；格點索引只提供穩定顯示順序，不代表優劣。

角色數量不是硬性 `1` 到 `4`：同一評估點可以同時取得多個角色，只建立一項候選並保存角色集合；不同角色若由不同點取得則分別保留；多個真正同級穩健中心全部保留。使用者仍可從完整 Pareto 前緣或任一已保存評估點手動建立候選，不受自動角色限制。

候選去重與身分規則：

1. 同一研究設定與同一評估點取得多個角色時，合併角色，不複製候選。
2. 參數向量不同時，不因數值接近而近似去重。
3. 不同合格連通區域的候選不得依距離合併。
4. 不同 `ResearchConfiguration` 即使參數向量相同，仍是不同研究候選；UI 可依參數 fingerprint 分組檢視，但不得合併語義。
5. K 動態候選身分包含完整動態政策、模型、控制模式與係數 hash，不以單日有效核心參數判定相同。
6. 新版區域、前緣或中心分析透過 lineage 連結舊候選；保留歷史，UI 預設顯示最新版。
7. 暫定前緣只能產生暫定角色候選，不得和正式角色候選混成同一完成狀態。

角色產生只讀取既有分析結果。因各角色共用同一組已存在指標，使用者啟動「產生角色候選」時可一次推導全部角色，不需要分別建立重複計算任務，也不得觸發新回測。

### 10.5 代理模型只有提案權，沒有證據權

代理模型是使用同一研究設定下已完成的真實評估點，估計尚未回測參數點可能表現的研究工具。它不是 K 的市場預測模型，也不得使用相似歷史行情檢索。

代理模型可以：

- 讀取同一份不可變 `ResearchConfiguration` 下的實際評估點。
- 預測尚未計算合法格點的大致績效與模型不確定程度。
- 提出可能高績效、資訊不足或接近合格邊界的待回測格點。
- 建立與實測地形完全分離且明確標示的預測視圖。
- 產生下一批建議回測 manifest，交由使用者確認後實際計算。

代理模型不得：

- 把預測點存成 `EvaluationPoint` 或標準化回測結果。
- 以預測值判定合格、不合格或連接合格區域。
- 以預測值計算方向容錯、軸向深度、方盒半徑、邊界、平坦度或連通幾何。
- 讓預測點進入正式或暫定 Pareto 前緣、中心、角色候選或 G/H/L 等候選驗證。
- 依代理預測宣稱全域探索收斂或自動停止 Sobol。
- 將預測曲面與實際曲面混成無法分辨的單一資料層。

正式流程固定為：

```text
實際評估點
→ 訓練代理模型
→ 產生待回測建議點
→ 對齊合法格點、驗證、去重與快取查詢
→ 由 I 產生精確 manifest
→ 使用者啟動真實回測
→ 真實結果成為 EvaluationPoint
→ J / M 才可用於正式分析
```

代理執行至少保存：

- 來源研究設定與實際評估點集合 hash。
- 模型種類、版本、超參數、隨機種子與訓練程式版本。
- 訓練與樣本外驗證指標。
- 每個預測點的預測值、不確定程度與提案原因。
- 哪些建議點被使用者啟動、實際回測結果及預測誤差。
- 任務 manifest、總量、進度、取消、錯誤與完成狀態。

UI 與資料型別至少明確區分：

```text
實際回測點
代理預測點
待回測建議點
```

預測圖層預設關閉，使用不同圖例與視覺樣式；開啟後也不能影響實測圖的統計值。若樣本外驗證顯示模型品質不足，結果仍可供診斷，但提案只能標為「模型探索提案」，不得標為推薦。

代理模型不是 M 必經階段，且預設關閉。未啟用代理時，Sobol、使用者手動點、局部規則格點與可選 GA 仍可提供真實評估點。

#### 10.5.1 預設模型與目標

使用者主動啟動代理補點工具時，預設訓練兩個彼此獨立的隨機森林迴歸模型：

```text
模型一：預測 log 期末淨值比
模型二：預測 log 最大回撤殘值比
```

不直接訓練績效回撤綜合指標，也不把兩個目標混成單一訓練標籤。輸入只包含本次研究變數的合法格點索引；研究常數不形成特徵，完整研究設定 hash 則用來隔離模型。

隨機森林與訓練流程屬於 Lab / Research 離線模組，不得進入策略核心、`Step()`、SaaS 線上 tick 或 LocalAgent。模型超參數由版本化 schema 固定，不能在同一代理執行中偷偷自我搜尋；樹數、深度、葉節點限制、特徵抽樣、bootstrap、種子及實作版本均需保存。

#### 10.5.2 訓練資格與資料來源

至少完成兩批全域 Sobol 實測，累積唯一 Sobol 點數達 `2*N0` 後，才可訓練預設代理模型。此條件只提供最基本的訓練與樣本外檢查資料，不代表樣本已充分。

預設全域模型使用：

- 同一份不可變研究設定。
- 已完成的全域 Sobol 實測點。
- 基準點與軸向邊界點可加入最後正式訓練。

局部細化形成的密集格點預設不混入全域模型，避免局部過度取樣扭曲全域資料分佈。若未來建立局部代理，必須是另一個明確模型種類與資料集 hash，不得暗中混用。

#### 10.5.3 批次隔離樣本外驗證

驗證依 Sobol 來源批次分組，不隨機把相鄰點拆進訓練與驗證。至少兩批時，先以一批訓練並預測另一批，再交換角色，收集樣本外預測；批次更多時採保留完整批次的交叉驗證。最後才使用全部通過結構與資料驗證的實際訓練點建立提案模型，包含績效合格與不合格點。

每個目標分別保存與顯示：

- MAE。
- RMSE。
- 絕對誤差中位數與第 90 百分位。
- 預測與實測的排序相關性。
- 森林內各棵樹的預測分歧。
- 依樣本外殘差形成的經驗預測區間及其實際覆蓋情形。

經驗預測區間不是市場機率、嚴格信賴區間或正式穩健保證。

每個驗證 fold 同時建立只預測該 fold 訓練資料中位數的基準模型。隨機森林某一目標的樣本外 MAE 必須優於該基準，該目標才可標成「可引導提案」；否則只能標成「探索用途」。只有兩個目標都優於各自基準時，才可產生保守績效提案。此判定不影響使用者查看模型診斷，也不會把模型升格為正式證據。

#### 10.5.4 四類獨立提案

代理工具不建立混合加權取得函數。UI 提供四種獨立操作，每次由使用者輸入希望取得的唯一點數，先預覽 manifest 與成本，再決定是否真實回測：

1. `conservative_performance`：使用兩個目標的經驗預測下界，在候選池中保留互不支配點；只有兩個模型都可引導提案時才能標成保守績效提案。
2. `qualification_boundary`：尋找任一目標經驗區間跨越合格界線 `0` 的點，用實測釐清合格邊界。
3. `model_uncertainty`：分別依兩個模型的預測分歧與經驗區間寬度找資訊不足點，不把兩個不確定程度加權成單一分數。
4. `pure_coverage`：直接使用同一 Sobol 序列尚未實測的後續合法點，完全不採用模型預測，避免探索被代理模型鎖在既有判斷中。

四類不預設硬性比例，也不要求一次全部執行。使用者點選哪一類才產生哪一類提案；若同一合法格點被多類選中，只建立一個待回測建議並保存全部提案原因。

#### 10.5.5 待評估候選池

提案只能從可追溯且能對齊 schema 的合法格點產生：

- 同一 Sobol 序列尚未實測的後續點。
- 已觀測合格與不合格邊界附近尚未計算的軸向格點。
- 使用者明確指定的合法候選池。

不得在連續空間任意生成無法重現的超長浮點參數。候選池生成版本、Sobol 索引範圍、合法格點映射、去重與快取結果必須保存。代理提案點經真實回測後，保留其預測值、區間、提案角色及實際誤差，以供後續重新評估模型品質。

### 10.6 研究系列與跨設定比較

不同 `ResearchConfiguration` 永遠維持各自的評估點、地形、合格連通區域、候選前緣與中心，不得為了比較而合併。需要比較多種設定時，建立 `ResearchSeries`，明確保存共同背景、刻意改變因素、成員設定、共同參數 schema、共同評估 manifest 及比較版本。

例如同一系列可以固定商品、資料、期間、成本與回測語義，只改變：

- 是否啟用 D 長週期濾網及其設定。
- K 固定值、連續模式或六狀態模式。
- K 模型路線或其他明確研究結構選項。
- 其他被列入系列變更因素的研究常數。

未列入系列變更因素的欄位若不同，系統不得靜默忽略。

#### 10.6.1 四級比較資格

每次比較快照必須標記下列其中一級：

1. `paired_direct`：共同背景完全相同、參數 schema 相容，且使用同一組標準化參數向量 manifest；可以逐點比較。
2. `context_matched_unpaired`：共同背景相同但評估點集合不同；只能並排比較各自地形、區域與候選，不計算偽配對差值。
3. `descriptive_only`：商品、資料期間、基準或其他重要背景不同；只能顯示各自在自身背景下的標準化指標與驗證狀態，不產生共同勝負排名。
4. `incompatible`：回測核心、指標公式、資料語義或結果 schema 不相容；阻止數值比較，要求重算或重新分析。

#### 10.6.2 直接比較共同背景

`paired_direct` 至少要求一致：

- instrument、dataset hash、週期與日期區間。
- 策略、回測核心與每日實際持倉語義版本。
- execution mode、成交價規則、初始資金與現金流設定。
- 手續費、滑價及其他成本。
- DCA 基準與資料對齊、缺值處理規則。
- 報酬、回撤及比較指標版本。

上述欄位不因被使用者列為系列變更因素就自動取得直接比較資格；若改變會破壞共同回測語義，系統降級為描述比較或不相容。允許直接配對的結構因素必須由版本化白名單明確定義。

#### 10.6.3 共同評估 manifest

若成員設定共用相同研究變數 schema，M 可以先建立一組共同 Sobol、軸向或局部格點向量，再對每份成員設定分別形成實際回測任務。每個共同向量保存各設定的結果引用、缺漏狀態與快取命中。

逐點比較至少可以輸出：

- `log 期末淨值比`差。
- `log 最大回撤殘值比`差。
- 績效回撤綜合指標差。
- 合格狀態是否改變。
- 同一參數點在不同設定中的角色、區域與候選狀態。

某設定缺少共同點時標記未配對並提出補算 manifest，不以插值或代理預測補值。若不同設定參數 schema 不相容，只能分別研究並進行描述比較。

#### 10.6.4 顯示與限制

- 比較頁必須列出所有實際不同欄位及比較資格原因。
- 「各自最佳候選」只能標成獨立研究結果，不得冒充控制變因實驗。
- 不建立跨商品、跨期間或不同回測語義的全域冠軍排行榜。
- 比較不改變任何來源設定、候選或人工狀態。
- 系統不因比較結果自動採用、Promote 或淘汰候選。
- 比較快照保存共同背景 hash、成員設定 hash、共同 manifest hash、指標版本與產生時間；來源延伸後另建新版，不靜默改寫。

#### 10.6.5 與 N 通用研究比較的關係

M 向 N 提供兩類來源：

1. 「參數比較」讀取精確 `RobustCandidate` 版本。
2. 「研究結果比較」讀取精確 `ResearchAnalysisSnapshot` 或 `ResearchComparisonSnapshot`。

`RobustCandidate` 的唯讀參數資料必須包含來源 configuration、point、region、analysis snapshot、候選角色、完整參數 schema 與 lineage。K 動態候選必須保留完整模型 artifact、預測 schema、狀態規則、動態政策與核心參數包，不得為 N 轉換成裸靜態數值。

`ResearchAnalysisSnapshot` 至少提供：

- 不可變研究背景、評估點集合與內容 hash。
- 一維曲線、二維地形與可選 3D 曲面所需既有資料。
- 合格區域、候選前緣、中心、邊界、缺漏及完整度。
- 評估點的標準化回測結果與既有 G/H/L/C 引用。

`ResearchComparisonSnapshot` 可以作為 N 的受控比較摘要與背景，但 M 保存的比較資格、共同 manifest、缺漏及逐點配對是權威資料。N 不得升級比較資格、補造共同點、重新計算差值，或遞迴把一份 M 比較快照當成新的通用排名對象。

N 固定引用 M source ID、版本、snapshot ID 與內容 hash；M 追加評估點、重跑 J 分析或建立新版系列比較後，舊 N 工作區不自動更新。完整地形與點位資料只在 N 展開區塊時讀取。

N 只保存來源引用與顯示狀態，不複製 M evaluation points、regions、candidates、series 或 comparison payload。N 不得啟動 M、追加研究點、執行 J、改候選狀態、寫入參數庫或 Promote。

M 不依賴 N 才能研究、比較或產生候選；N 是下游唯讀觀察工具。完整 N 規格見：

```text
docs/研究構想整理/通用研究結果與參數比較工具開發指導.md
```

概念上的 `RobustCandidate` 至少綁定：

- 來源研究設定。
- 來源合格連通區域與候選前緣版本。
- 中心參數向量。
- 中心回測結果。
- 各尺度鄰域統計。
- 距離邊界資訊。
- 候選產生演算法版本。
- 後續驗證任務與結果。
- 人工狀態、備註、標籤與採用紀錄。

### 10.7 參數庫與人工採用銜接

M 的研究候選與既有參數庫紀錄分開保存，並以雙向引用銜接。`RobustCandidate` 是研究真源，保存地形、區域、候選角色、來源設定與分析關係；既有 `GeneRecord` 繼續作為參數庫及執行端載入 `challenger`、`champion`、`retired` 的真源。不得建立第二套目前已採用參數，也不得讓執行端直接把 M 研究狀態當成 champion。

候選產生後不自動寫入參數庫。每個 M 候選提供兩個人工動作：

1. `存入參數庫`：建立一筆與該候選版本雙向綁定的 `challenger`。
2. `設為已採用參數`：若尚無綁定的參數庫紀錄，先建立 `challenger`，再於同一資料庫交易中執行既有 Promote。

Promote 仍是全系統唯一能改變已採用參數的操作。它依 `strategy_id + instrument_id + interval + data_source + execution_mode` 隔離，在交易內將同範圍舊 `champion` 改為 `retired`、把指定的 `challenger` 或 `retired` 改為 `champion`，並使對應快取失效。M 任務完成、候選產生、比較結果或分析結果都不得自動觸發 Promote。

銜接規則固定如下：

- 同一 M 候選版本重複存入時必須沿用既有雙向連結，不得建立重複 `challenger`。
- M 候選修改研究內容時建立新版本；新版本不得靜默改寫既有參數庫紀錄或已採用歷史。
- M 候選封存後，已建立的參數庫紀錄、角色歷史與採用紀錄仍保留；參數庫紀錄被封存或退役也不得刪除來源研究證據。
- M 與參數庫頁面都必須能跳轉到對方，並顯示來源候選版本、參數庫角色與歷次 Promote 關係。
- 既有 GA 產生的 `challenger`、`champion` 與 `retired` 原樣保留；未經 M 研究的舊紀錄不得被補造穩健區域、候選前緣或分析證據。
- M 上線與舊資料遷移不得自動替換目前 `champion`。
- K 動態候選匯入參數庫時，採用單位是 K 文件定義的完整模型 artifact、預測 schema、狀態規則、動態政策、核心參數包與回測 metadata；不得只投影成一組靜態核心參數。參數庫紀錄必須引用可重建且不可變的完整版本化採用單位。

## 十一、候選驗證鏈

M 可以連結但不重複實作：

- G 報酬分析。
- H 隨機參數、無意義規則與曝險打散對照。
- L 擾動行情資料測試。
- C 參數可獲利 K 線樣貌反推。

E 後續已確認為 K 線片段重組行情產生器，不是候選驗證類型。M 研究 E 行情時，建立引用精確 E 完成版本與內容 hash 的普通 `ResearchConfiguration`；不得為 E 建立 `CandidateAnalysisLink`。不同 E 版本的結果若要事後並列觀察，由 N 通用研究結果與參數比較工具讀取既有 M／Backtest 成果；M 自己的受控 `ResearchSeries` 與共同 manifest 機制仍完整保留。

B 後續已確認不建立獨立候選驗證模組。跨商品泛化以同一參數分別執行既有回測；多商品共同研究則由 E 建立同週期跨商品拼接行情，再作為普通不可變 dataset 交給 M。M 不建立 B 專用共同評分器或 `CandidateAnalysisLink`；N 只負責依逐區塊相容規則讀取與並排既有結果。

每項驗證保存獨立任務與版本，並回連候選。M 顯示某候選的各項分析為未計算、計算中、部分完成、已完成、失敗、已取消或不適用，不得只保存一個模糊的「已驗證」布林值。

候選分析狀態固定為：

```text
not_calculated
running
partially_completed
completed
failed
cancelled
not_applicable
```

- `partially_completed` 表示已有可查看結果，但原任務 manifest 尚未完整。
- `cancelled` 表示使用者主動取消；可以引用取消前建立的 partial snapshot。
- `failed` 只表示非使用者主動造成的錯誤。
- 續跑時回到 `running`；只有原 manifest 全部完成後才可標記 `completed`。

已確認：這些分析結果只供使用者自行查看與評估。M 不建立 `ValidationPolicy`，不設定採用前強制驗證、系統及格線或自動淘汰門檻；未執行某項分析也不阻止使用者保存、採用或捨棄候選。代理模型預測與實際回測仍須清楚區分，所有已執行結果繼續保存設定快照、版本與雜湊，以確保研究可重現，但不得介入使用者決策。

K 動態候選交由 H 產生隨機參數對照時，固定模型、狀態規則、控制模式與啟用結構，只隨機同一 `DynamicParameterSpaceSchema` 中實際存在的有效數值研究維度。不同動態結構由 M 的 `ResearchSeries` 比較，不得混入同一隨機參數分佈；完整規格引用 H 與 K 文件，不在 M 重複實作。

M 候選交由 L 執行擾動行情資料測試時，M 只保存每個候選 subject 對應的 `CandidateAnalysisLink`；來源快照、擾動版本、批次回測、統計快照與續跑 manifest 全由 L 擁有。同一批測試含多個候選時，每個候選分別投影自己的狀態，不以整批狀態覆蓋個別候選。L 結果不得形成通過布林值、自動淘汰、自動存入參數庫或自動 Promote。完整規格引用：

```text
docs/研究構想整理/擾動行情資料產生器開發指導.md
```

C 與 M 整合時，M 候選頁只建立 C 研究草稿及 `CandidateAnalysisLink`。C 自己擁有生成路徑、CVT-MOME 搜尋、A/B 覆蓋、局部失敗邊界、永久保存與續跑 manifest；M 不複製 C 演算法，也不把 C 結果加入候選評分、排序或 Promote。C 可獨立測試參數庫中的既有參數，因此只有候選來源預填與雙向狀態投影依賴 M。完整規格引用：

```text
docs/研究構想整理/參數可獲利K線樣貌反推系統開發指導.md
```

## 十二、既有 GA 的定位

已確認：

- M 取代「反覆按搜尋、以單一最高分個體為主要結果」的主要操作流程。
- GA 可以保留為高維空間中的可選內部取樣或提案方法。
- GA 最佳個體不得直接成為 M 的最終答案。
- GA 產生的點必須進入相同評估點、地形、穩健區域與候選驗證流程。
- K 不綁死使用 GA。

預設全域探索已確認使用 Sobol。GA 不取代 Sobol 的全域覆蓋角色，只能由使用者額外啟動作為提案來源。

- 驗證鏈。

底層評估點仍須保存，以支援重現、快取、補算與延伸研究。

實際舊資料 model 名稱是 `GeneObservation`。它只代表既有 GA 每代個體觀察，缺少 M 的不可變研究設定、標準化回測結果與分析版本，因此不得直接轉成 `ResearchEvaluationPoint` 或冒充 M 地形證據。舊 `GeneRecord` 候選、已採用參數、歷史參數、進化任務摘要與最終結果不在清理範圍。

退場不採固定保留天數，也不建立長期清理 UI，而以 M 正式驗收作為事件邊界：

```text
M 完整實作並通過驗收
→ 建立完整備份
→ 驗證 GeneObservation 筆數、匯出內容與 hash
→ 停止新增 GeneObservation
→ 移除舊圖表、前端輪詢與查詢 API
→ 以明確的一次性維護入口清除 GeneObservation 資料
```

清理不得在服務啟動或 AutoMigrate 中自動發生，不建立 SQL migration。M 驗收前保留舊資料與可回復能力；驗收後只清除逐代個體觀察。舊參數若要進入 M，必須重新正式回測。M 內可選 GA 提案的去重改由 M 評估點 hash、manifest 與 I 快取負責，不再依賴 `GeneObservation`。空的舊資料表可暫留以兼容既有備份格式，但正式系統不再讀寫。

三份穩定真源在 M 完整實作、測試與核准前仍不修改；正式切換時才依重大更新守則同步更新真源。

## 十四、正式資料模型與不變性

### 14.1 所有權原則

M 只保存研究編排、評估點引用、分析版本、候選及比較關係。底層 NAV、每日路徑與回測摘要仍由標準化回測結果模組保存；J 擁有地形幾何與穩健統計演算法；I 擁有計算任務、manifest、進度、取消與快取生命週期。M 不複製三者的資料真源。

正式關係：

```text
ResearchConfiguration
  1 → N ResearchRun
  1 → N ResearchEvaluationPoint
  1 → N ResearchAnalysisSnapshot
  1 → N RobustCandidate

ResearchRun
  1 → N ResearchStage

ResearchEvaluationPoint
  N → 1 StandardizedBacktestResult
  1 → N ResearchPointOrigin

ResearchAnalysisSnapshot
  1 → N RobustRegion

RobustRegion
  N ↔ N ResearchEvaluationPoint
  1 → N RobustCandidate

RobustCandidate
  1 → N CandidateAnalysisLink
  1 → 0..1 CandidateGeneLink

ResearchSeries
  1 → N ResearchSeriesMember
  1 → N ResearchComparisonSnapshot

SurrogateModelSnapshot
  1 → N SurrogateProposal
```

### 14.2 GORM model

下列名稱是 M 的正式領域 model。實作使用 GORM model 與 AutoMigrate，不建立 SQL migration。

| Model | 必要內容 | 主要唯一性或限制 |
|---|---|---|
| `ResearchConfiguration` | 完整 scope、dataset 與日期、策略／回測版本、成本、DCA、濾網、結構設定、參數空間 schema、K artifact／政策引用、canonical JSON 與 hash | `config_hash` 唯一；內容建立後不可變 |
| `ResearchConfigurationMetadata` | 顯示名稱、備註、標籤、封存狀態 | 與不可變設定分離，可人工修改 |
| `ResearchRun` | configuration、根 I 任務、取樣器、seed、下一個 Sobol index、全域探索狀態、開始與結束時間 | 不得改綁其他 configuration |
| `ResearchStage` | run、順序、階段種類、manifest hash、I 任務引用、狀態、計數與錯誤摘要 | 同一 run 的 ordinal 唯一；已啟動 manifest 不可改 |
| `ResearchEvaluationPoint` | configuration、canonical 格點索引、標準化向量、vector hash、合法性、狀態、標準化回測結果 ID | `(configuration_id, vector_hash)` 唯一 |
| `ResearchPointOrigin` | point、run、stage、來源種類、Sobol index、軸向錨點或提案原因 | 同一來源不得重複；一點可有多個來源 |
| `ResearchAnalysisSnapshot` | configuration、評估點集合 hash、指標版本、J 演算法版本、完整性與結果引用 | 新資料或版本一律建立新版 |
| `RobustRegion` | analysis snapshot、分量 ID、區域完整性、邊界分類、lineage | 不得跨 configuration 合併 |
| `RobustRegionPoint` | region 與 evaluation point 關聯 | `(region_id, point_id)` 唯一 |
| `RobustCandidate` | configuration、point、region／snapshot 引用、角色集合、正式／暫定／手動來源、演算法版本與 lineage | 同一 snapshot 與 point 合併角色，不近似去重 |
| `CandidateAnalysisLink` | candidate、G/H/L/C 類型、任務與結果引用、未計算／計算中／部分完成／完成／失敗／已取消／不適用、partial snapshot 引用、版本 | 只表示分析狀態，不保存通過布林值；B 不新增分析類型，E 是 dataset |
| `CandidateGeneLink` | candidate 版本、`GeneRecord`、匯入與 Promote 稽核資料 | 同一 candidate 版本最多一筆有效參數庫投影 |
| `ResearchSeries` | 名稱、共同背景、刻意變更因素、共同 schema 與版本 | 不直接持有合併地形 |
| `ResearchSeriesMember` | series、configuration、顯示順序與因素值 | `(series_id, configuration_id)` 唯一 |
| `ResearchComparisonSnapshot` | series、成員版本、比較資格、共同 manifest、缺漏、差值與版本 | 來源延伸後建立新版 |
| `SurrogateModelSnapshot` | configuration／run、目標、訓練點集合、批次 fold、模型設定、OOF 指標、基準比較、artifact hash | 與 K 模型完全分離 |
| `SurrogateProposal` | surrogate snapshot、提案類型、vector、預測值與不確定度、後續實測 point 引用 | 預測不得直接成為 evaluation point |

### 14.3 Canonical hash

所有 hash 輸入都必須先 canonicalize：

- JSON key 使用固定排序，缺省值展開為版本化正式值。
- 浮點研究值先轉成合法格點索引，不以未量化的二進位浮點字串作身分。
- 日期統一成 UTC 時間戳，市場時區另存正式欄位。
- 集合使用穩定排序；不得依 Go map 或資料庫回傳順序產生 hash。
- config hash 必須涵蓋 dataset、策略、回測、成本、DCA、濾網、參數 schema、K 模型／政策及所有會改變 NAV 的設定。
- 分析 snapshot hash 必須再涵蓋評估點集合、指標公式與演算法版本。

### 14.4 不變性與刪除

- 研究設定需要修改時使用「複製為新設定」，不得更新原內容。
- 已完成評估點的向量、回測結果引用及來源版本不可改；重算建立新 attempt 或新版結果引用並保留舊紀錄。
- 區域、前緣、中心、代理模型與比較結果不得被新資料靜默覆寫。
- 候選名稱、備註、標籤與封存狀態可修改；來源點、角色版本與研究證據不可改。
- 被任務、候選、比較、分析或參數庫引用的資料只可封存，不可硬刪除。
- GORM 關聯必須使用限制刪除或明確封存，不允許 cascade 刪掉回測、候選或採用歷史。

## 十五、計算、快取與任務契約

### 15.1 任務分層

M 必須使用 I 的兩層任務：

- 原子任務：單點回測、固定格點批次、分析補算、代理訓練、比較補算。
- 複合研究任務：協調全域探索、局部細化、J 分析、代理提案與系列比較等有明確邊界的階段。

任何大量計算在開始前都必須先產生精確 plan，顯示：

- 請求點數與量化後唯一點數。
- 非法或重複點數及原因。
- 快取命中數。
- 實際新增回測或分析數。
- 預估時間與儲存量。
- manifest hash、取樣器版本與下一個序列索引。
- 硬上限或前置依賴阻擋原因。

使用者明確啟動後才可執行。開啟頁面、切換圖層、拖曳滑桿或改變純顯示門檻都不得暗中建立回測任務。

### 15.2 評估點去重與快取

去重分兩層：

```text
ResearchConfiguration + canonical vector hash
→ 唯一 ResearchEvaluationPoint

完整 Backtest Spec hash
→ 唯一可重用 StandardizedBacktestResult
```

不同研究任務遇到同一 configuration 與向量時重用同一 point；不同 configuration 若形成相同完整回測 key，仍可引用同一底層回測結果，但不得合併 M 的地形、區域或候選語義。

K 候選的向量身分包含模型、控制模式、啟用輸入、政策與係數 schema。代理預測、插值或舊 GA 評分永遠不能命中「實際回測完成」快取。

### 15.3 取消、失敗與續跑

- 取消只阻止尚未開始的工作並傳遞到執行中的原子任務；已完成結果必須保留。
- 部分完成、失敗、取消與等待下一階段必須分開顯示。
- 重試只補失敗或缺漏項，不重算已完成且 key 相同的項目。
- 全域探索保存下一個 Sobol index；暫停、結束或取消都不得破壞同一序列的續跑能力。
- 局部細化只在其有限 manifest 全部處理完後標記完成。
- 代理、J 分析與系列比較失敗不得讓既有真實回測點失效。

### 15.4 按需分析

除非多個輸出必然由同一運算同時得到，否則各分析項目都由使用者分別啟動。不得要求使用者先勾選一大包分析，也不得為了看另一項結果重跑已有回測。未計算是正式狀態，不等於失敗或不合格。

## 十六、依賴關係與開發順序

### 16.1 硬依賴

```text
每日實際持倉計算機制
→ 回測核心模組
→ 標準化回測結果保存機制
→ 報酬分析共用模組
→ I 計算任務與快取
→ J 績效地形與穩健區域
→ M 研究工作流
```

D 長週期濾網若被設定使用，必須已能作為完整回測設定與結果 metadata。K 的模型與動態政策可以先建立，但 K 的完整參數研究整合依賴 M。H、L、C 由 M 以分析連結接入，不把其演算法複製進 M。B 不新增分析類型；E 完成版本只經由不可變 dataset 身分與內容 hash 進入研究設定，不屬於候選分析連結。

L 的擾動數學核心、來源快照、版本產生與獨立測試工作區可以在 M 前完成；L 與 M 的完整雙向候選連結必須在 M 的候選及 `CandidateAnalysisLink` 已完成後接入。M 不依賴 L 才能建立候選，L 也不依賴 M 才能測試一般參數；只有「以 M 候選啟動 L 並回寫七種分析狀態」屬於雙方整合步驟。

### 16.2 實作順序

1. 完成並驗證上述硬依賴，鎖定回測與指標版本。
2. 建立 M model、canonical hash、不可變設定與 point 去重服務。
3. 串接 I 的 plan、manifest、進度、取消、重試與快取。
4. 完成 Sobol 全域探索、軸向錨點、完整枚舉切換及有限局部細化。
5. 串接 J 的一維、二維、多維、區域、距離、前緣與中心分析。
6. 完成候選角色、手動候選、分析連結及參數庫雙向橋接。
7. 完成代理模型的 OOF 驗證與四種獨立提案。
8. 完成 `ResearchSeries`、四級比較資格與共同 manifest。
9. 接入 K 動態參數 schema 與 H 同結構隨機參數對照。
10. 接入 L 的候選 subject 預填、雙向跳轉、七種狀態及續跑投影。
11. 接入 C 的候選預填、雙向跳轉及七種分析狀態投影，不在 M 重做 C 搜尋。
12. 完成前端研究工作區、低功耗圖形與完整重開流程。
13. 執行遷移驗收、舊資料備份與舊 UI 退場。
14. 全部完成後才更新三份穩定真源。

上述是依賴順序，不是可對外宣稱完成的 MVP 階段。任何只完成資料表、API 通道、空頁面或局部圖形的狀態，都不得回報為 M 已完成。

## 十七、後端服務與 API 契約

### 17.1 服務邊界

| Service | 責任 | 禁止事項 |
|---|---|---|
| `ResearchConfigurationService` | 驗證、canonicalize、建立與複製不可變設定 | 不執行回測 |
| `ResearchPlanningService` | 產生 Sobol、錨點、格點、局部補算與比較 manifest | 不把預測點當實測點 |
| `ResearchRunService` | 協調 I 任務、續跑、取消與階段狀態 | 不在策略核心加入 I/O |
| `ResearchAnalysisService` | 將實測 point 集合交給 J，保存版本化引用 | 不重寫 J 演算法 |
| `ResearchCandidateService` | 角色候選、手動候選、lineage 與分析連結 | 不自動採用或淘汰 |
| `ResearchSurrogateService` | 訓練、OOF 驗證與提案 | 不產生正式績效證據 |

所有預測模型、資料庫、網路、時間、快取與任務 I/O 都留在 Lab／Research 外圈。策略核心與每日有效參數提供器維持純、確定性計算。

### 17.2 API namespace

M API 統一置於：

```text
/api/v1/lab/parameter-research
```

必要端點族：

| 方法與路徑 | 行為 |
|---|---|
| `POST /configurations` | 驗證並建立不可變研究設定 |
| `POST /configurations/:id/clone` | 以既有設定建立可修改的新草稿，確認後形成新設定 |
| `GET /configurations`、`GET /configurations/:id` | 列表與完整重開 |
| `POST /configurations/:id/archive` | 只封存，不刪除引用資料 |
| `POST /configurations/:id/runs/plan` | 預覽第一批或指定全域批次 |
| `POST /configurations/:id/runs` | 以已確認 plan 建立 run |

| `POST /runs/:id/stages/plan` | 預覽追加、細化、補算或分析階段 |
| `POST /runs/:id/stages` | 啟動已確認且 hash 相同的 manifest |
| `POST /runs/:id/pause`、`POST /runs/:id/cancel` | 依 I 語義暫停或取消 |
| `GET /runs/:id/points` | 分頁取得實測、非法、失敗與缺漏點，不混入代理點 |
| `GET /runs/:id/landscape` | 依一軸／二軸、固定切片與指標取得視圖資料 |
| `POST /runs/:id/analyses/:kind/plan` | 預覽 J 或其他按需分析補算 |
| `POST /runs/:id/analyses/:kind` | 啟動指定分析 |
| `POST /runs/:id/surrogates/plan`、`POST /runs/:id/surrogates` | 訓練資格預覽與代理模型建立 |
| `POST /surrogates/:id/proposals/plan`、`POST /surrogates/:id/proposals` | 四種獨立提案與實測 manifest |
| `POST /analysis-snapshots/:id/candidates/derive` | 一次推導全部角色候選，不重跑回測 |
| `POST /points/:id/candidates` | 從任一已保存實測點建立手動候選 |
| `GET /candidates/:id`、`POST /candidates/:id/archive` | 重開與封存候選 |
| `POST /candidates/:id/export-to-library` | 冪等建立 linked challenger |
| `POST /candidates/:id/promote` | 建立投影後調用唯一 Promote transaction |
| `POST /series`、`GET /series/:id` | 建立與重開研究系列 |

路徑命名可依現有 router 結構做等價調整，但資源邊界與行為不得合併成單一黑盒端點。

### 17.3 API 共通要求

- 建立任務、階段、候選投影與 Promote 必須支援 idempotency key。
- 執行端點必須提交先前 plan hash；設定、版本或快取狀態改變時回傳 plan stale，要求重新預覽。
- 列表與 points 必須分頁，禁止一次把所有高維點送到瀏覽器。
- 錯誤回應必須區分輸入非法、依賴缺失、硬上限、任務失敗、版本不相容與權限問題。
- API 不回傳模糊的單一 `verified` 或 `complete`；必須回傳各階段與各分析狀態。
- 任何 Promote 衝突必須回滾整個交易，不得留下半完成的 challenger／champion 關係。

## 十八、前端研究工作區

### 18.1 頁面定位

既有「參數搜尋」導覽位置保留，但內容改為 M 的實際研究工作區，不建立行銷式首頁。頁面需支援密集、可掃描、可重開的長期研究流程，主要視圖為：

- 研究設定與系列。
- 計算階段與任務。
- 評估點。
- 一維／二維地形。
- 多維穩健性。
- 區域、前緣與候選。
- 代理提案。
- 候選分析與參數庫連結。

### 18.2 研究設定編輯

- 清楚分開結構設定、研究常數與研究變數。
- 每個核心參數可設固定單值或研究範圍；固定值不形成維度。
- 範圍提供完整合法範圍、中心加半徑及自訂起訖三種模式。
- 顯示量化後格點、步長、總維度、理論組合數與結構限制。
- 已建立設定只讀；修改操作實際建立新設定。
- K 設定顯示模型、控制模式、啟用輸入及有效研究維度，但不得在使用者可見 UI 暴露策略內部禁用術語。

### 18.3 計算操作

- 每個大量計算按鈕先開啟 plan，顯示總量、快取、實算量、預估時間、儲存量與警告。
- 使用者確認後才開始；執行中提供進度、取消與錯誤明細。
- 全域批次完成後固定提供「追加下一批」、「結束全域探索並進入局部細化」及「暫停」。
- 按需分析各自具有獨立按鈕與狀態，不做一次全選面板。
- 重開頁面必須恢復同一 run、階段、選取切片、圖層與任務狀態。

### 18.4 視覺化

- 選一個核心參數顯示一維曲線；選兩個顯示 2D heatmap 與可選 3D 曲面。
- 其他參數的固定切片值必須始終可見，不得把不同切片混圖。
- 2D 分析必須支援 J 定義的疊圖；各圖層只讀已完成資料，未計算圖層清楚標示。
- Z 軸可切換 `log 期末淨值比`、`log 最大回撤殘值比`、績效回撤綜合指標、MaxDD 與合格狀態等 J 已定義輸出。
- 實測、未知、非法、失敗、代理預測、合格區域與資料缺口使用不同圖例，不得以插值遮住未知點。
- 預設使用 2D heatmap；3D 不自動動畫，切換與拖曳只讀快取，不重新回測。
- 分頁隱藏時停止高頻重繪與圖形運算；代理預測圖層預設關閉。
- 圖形與固定格式控制必須有穩定尺寸，桌面與行動版不得重疊或因 hover 改變版面。

### 18.5 候選操作

- 同一點可顯示多個角色，不複製候選。
- 正式、暫定及手動候選清楚區分。
- 候選頁顯示來源設定、實測回測、區域／前緣／中心版本、各分析狀態及 lineage。
- 分析結果只供使用者判斷，不顯示系統及格、強制驗證或自動淘汰。
- 提供「存入參數庫」與「設為已採用參數」兩個人工動作，並可雙向跳轉參數庫紀錄。
- Promote 前顯示作用範圍與目前將被退役的已採用參數；確認後才執行。

## 十九、完成品操作流程

### 19.1 單一設定研究

```text
建立不可變研究設定
→ 預覽並啟動基準點、軸向錨點與第一批 Sobol／完整枚舉
→ 批次檢查點決定追加、暫停或進入局部細化
→ 對選定點或邊界建立有限細化 manifest
→ 按需執行一維、二維與多維 J 分析
→ 形成版本化區域、前緣與中心
→ 一次推導角色候選或手動保存任意實測點
→ 視需要連結 G/H/L/C 分析
→ 使用者自行比較、存入參數庫或 Promote
```

若研究對象是 E 重組行情，第一步建立研究設定時即選定精確 E 版本；後續流程與其他普通行情相同，不在候選產生後追加 E 分析。

### 19.2 代理提案

```text
至少完成兩批全域 Sobol 實測
→ 建立兩個獨立隨機森林目標
→ 依完整 Sobol 批次做 OOF 驗證
→ 各目標與訓練中位數基準比較
→ 使用者個別選擇四種提案之一並輸入點數
→ 預覽合法、去重、快取後的實測 manifest
→ 正式回測
→ 保存預測、實際值與誤差
```

任何步驟都不得把代理結果直接送進 J 的正式區域、前緣、中心或候選。

### 19.3 跨設定系列

```text
建立 ResearchSeries
→ 明列共同背景與刻意變更因素
→ 判定 paired_direct / context_matched_unpaired / descriptive_only / incompatible
→ 相容時建立共同參數向量 manifest
→ 各設定分別回測並保存自身地形
→ 建立版本化比較 snapshot
```

系列比較只協助觀察，不產生跨商品、跨期間或不同回測語義的全域排行榜。

## 二十、併發、錯誤與可恢復性

- 同一 configuration 與 vector 的並行建立必須由唯一索引與交易收斂成一個 point。
- 同一 manifest 的重複提交只建立一組任務；重複 HTTP 請求回傳原資源。
- 多個瀏覽器同時追加 Sobol 批次時，必須鎖定並核對 next index，禁止序列重疊或跳號。
- 分析執行時固定 evaluation set hash；執行期間新增點不進入該 snapshot。
- 候選產生固定 analysis snapshot；新 snapshot 不改寫既有候選。
- 代理訓練中途取消不得留下可提案的模型狀態。
- Promote 使用資料庫交易與唯一 champion 約束；任何一步失敗都完整回滾。
- 服務重啟後，running 任務必須依 I 的恢復規則轉成可續跑、失敗或取消，不能永久卡住。
- 所有不可重試錯誤保存明確原因；使用者補正設定時建立新設定或新階段，不修改歷史輸入。

## 二十二、測試矩陣

### 22.1 單元測試

- canonical JSON、格點索引、hash 與不同 map 順序的穩定性。
- 固定值不形成維度，三種範圍模式產生正確合法格點。
- `N0 = nextPowerOfTwo(max(64, 16*d))`、Sobol 延伸、seed、錨點與完整枚舉切換。
- 量化後去重、非法點拒絕、跨欄結構限制及 full enumeration 計數。
- 三態格點、軸向相鄰、禁止對角線、連通分量與 lineage。
- 各方向容錯、軸向失敗深度、保證合格方盒半徑與四種邊界分類。
- Pareto 支配、中心字典序、graph medoid、同分保留與角色合併。
- 正式／單側／暫定中心及未知點不被誤判為失敗。
- 代理模型資料資格、批次 OOF、基準 MAE、四種提案與預測／實測隔離。
- 四級跨設定比較資格與不同背景降級規則。
- linked challenger 冪等、Promote 交易及 K 完整採用單位。

### 22.2 整合測試

- 相同 point 跨 run 重用，相同 Backtest Spec 跨 configuration 重用底層結果。
- plan 顯示精確總量、快取命中與實算量，stale plan 被拒絕。
- 暫停、取消、服務重啟、失敗重試與 Sobol 續跑不遺失結果。
- J 分析固定 evaluation set hash，新點只形成新版 snapshot。
- G/H/L 等分析連結的七種狀態不阻止人工採用；L 的部分完成、已取消、續跑及完成狀態依 manifest 正確投影。
- `ResearchSeries` 共同 manifest 缺漏可補算，失敗成員不污染其他成員。
- M 候選、分析 snapshot 與比較 snapshot 可由 N 依固定版本／hash 唯讀；N 無法升級 M 比較資格或觸發研究、J 分析與 Promote。
- K 固定、全域、連續及六狀態參數空間都能走完相同 M 流程。
- K 候選匯入參數庫後可由回測與市場狀態載入完整模型包。
- 既有 champion 在 M 部署與資料清理前後保持不變。

### 22.3 前端測試

- 開頁、切 tab、切 Z 軸、疊圖、拖滑桿不會自動回測。
- 一軸只顯示曲線，二軸顯示 heatmap／3D，其他固定參數永遠可見。
- 未知、非法、失敗、實測與代理點不混色、不互相取代。
- 所有大量計算都有 plan、總量、進度、取消與錯誤明細。
- 重開任務可恢復階段、圖層、切片與既有結果。
- 隱藏分頁停止高頻渲染；3D 無自動動畫且不造成持續 GPU 空轉。
- 桌面與行動 viewport 無文字截斷、控制重疊或圖形溢出。
- 使用者可從候選跳到參數庫，也能從參數庫回到來源研究。
- 正式切換後不再請求 gene observations，也不渲染舊兩張圖。

### 22.4 效能與資料量測試

- 大量 points 使用後端分頁、前端虛擬化或分批繪製，不一次載入全部資料。
- 快取命中時不啟動回測 worker。
- 圖形資料轉換不得阻塞主要操作；不可見圖層不計算。
- 取消大型 manifest 後，worker、資料庫連線與 goroutine 正常釋放。
- 備份與還原包含 M 全部不可變設定、point 引用、分析、候選、系列與採用連結。

## 二十三、驗收情境

## 三十、研究來源切換與使用者可見用詞（2026-07-19）

「研究結構」與「來源參數」改為「要研究哪一類參數」及「以哪組參數為中心」。固定與動態來源切換時，前端必須先清除舊來源的研究軸與未送出的預覽；建立參數空間時，只能使用同時存在於目前 schema 且有有限基準值的欄位，不得以 non-null assertion 讀取舊欄位而造成整頁白屏。

「以哪組參數為中心」進一步改為「參數研究起點」，並明確說明：標的決定回測行情，研究起點提供基準點、各軸展開中心及未勾選參數的固定值。頁面必須提供「全選可測參數」與「全部取消」；不得另設八維前端限制。現行版本化 Sobol 取樣器最多支援二十維，固定策略目前全部可測參數可在同一研究設定中全選。全選代表所有參數都納入有限高維取樣，不得宣稱已窮舉全部組合；高維局部細化若在建立座標清單前已超過系統硬上限，必須直接拒絕並引導改用追加全域探索或縮小細化格數，不得配置爆量記憶體後才失敗。

全選參數後，軸向錨點或 Sobol 點可能違反參數間的結構限制。規劃器必須在建立計算 manifest 前略過這些無效組合並繼續取樣，直到取得預定數量的唯一合法點；不得讓第一個無效組合中止整批預覽。計算階段需顯示略過數量，且預覽、啟動、追加與細化的 API 錯誤都必須在按鈕附近顯示，不得出現按鈕看似沒有反應。

動態研究不存在或尚未完成時，頁面顯示可操作的空狀態並引導到「預測與動態參數」，不得崩潰或顯示空白背景。其他可見文字使用「勾選要測試的參數」、「每個方向往外測幾格」、「保存研究設定」與「最多幾組」；immutable configuration、axis、dimension、radius 等仍保留為內部資料契約。
