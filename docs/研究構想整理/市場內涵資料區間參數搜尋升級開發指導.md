# 市場內涵資料區間參數搜尋升級開發指導

> 狀態：已由使用者確認，尚未實作。
>
> 文件定位：既有參數搜尋系統的重大升級開發指導。本文件不是三份既有穩定系統真源；完整實作、測試、驗收並經使用者核准前，不得寫回三份真源文件。
>
> 開發方式：一次到位完成，不分第一版、第二版，不做 MVP、骨架、暫時公式或只接通資料通道的半成品。

## 一、目的

本功能把「市場內涵資料落在哪個數值區間」直接納入既有參數搜尋，使同一個候選可以依當下已完成行情計算出的市場內涵資料，選取對應的一整份策略核心參數包。

核心流程固定為：

```text
已完成行情
→ 計算當下市場內涵資料
→ 以候選內的判定值判斷各資料所在區間
→ 取得該區間組合對應的完整核心參數包
→ 使用該參數包呼叫既有同一套策略核心
→ 依研究設定的 execution mode 執行倉位調整
```

本功能不預設市場資料與核心參數之間存在單調關係。不得寫死「波動增加時 Beta 必須增加或減少」之類方向，也不得以一次項、二次項、sigmoid 或人工加權公式把市場資料換算成參數。

參數搜尋直接決定：

- 每項市場內涵資料實際使用幾個判定值。
- 每個判定值是多少。
- 每個需要窗口的市場內涵資料使用哪個窗口。
- 每一種區間組合對應的完整核心參數包。

## 二、功能邊界

本功能屬於既有參數搜尋／進化系統，直接升級其候選結構、回測評估、結果保存與人工採用流程。

本功能不屬於「預測與動態參數」工作流，且不依賴下列項目：

- 不訓練任何預測模型。
- 不使用 1 日或 20 日上漲機率。
- 不使用未來上下行空間預測。
- 不使用未來活動程度預測。
- 不使用模型校準、預測正確率、模型 artifact 或 OOF 預測。
- 不建立或引用動態政策公式。
- 不建立上升、下降、高波動、低波動等命名狀態。
- 不建立狀態機、狀態持續天數、遲滯或前一日狀態記憶。

既有「預測與動態參數」頁面、模型、政策、任務、artifact、已保存結果與歷史回測均保持不變。本功能不得將其改名、遷移或當成新功能的技術入口。

## 三、市場內涵資料契約

### 3.1 完整納入原則

本功能直接納入目前「預測與動態參數」功能已實作、且不需預測模型即可由截至當下的行情計算出的全部市場內涵數值，再加入走勢幾何計算與集合窗口收盤價回歸直線斜率。

不得提供逐項勾選市場內涵資料的設定。所有已列入版本化市場內涵資料 schema 的資料都會進入候選結構；某項資料在某個候選中實際使用零個判定值時，等同該候選沒有用它切分參數包。

### 3.2 既有行情活動數值

完整納入下列既有因果行情活動數值：

- TR 平均數。
- TR 標準差。
- High-Low 波幅平均數。
- High-Low 波幅標準差。
- Parkinson 波動率。
- Yang-Zhang 波動率。

同時納入上述六項數值目前既有、以當下已完成歷史資料計算的歷史相對值。其公式、資料不足、無效值與可用時間語義沿用既有正式實作，不在本功能重新發明另一套版本。

上述資料只取自當下及過去已完成行情，不包含任何模型預測出的未來活動值或正常活動量模型輸出。

### 3.3 走勢幾何數值

完整納入既有走勢幾何定義中的觀察窗口 High／Low 點集合凸包覆蓋面積。

凸包面積、共線點處理、鞋帶公式、無效資料及資料不足規則，沿用：

```text
docs/研究構想整理/走勢幾何預測模型訓練開發指導.md
```

本功能只使用當下已算出的凸包覆蓋面積；同一開發指導中的收盤價回歸斜率由下一節統一定義並只保存一份，不建立重複特徵。本功能不訓練、不讀取也不產生走勢幾何預測模型或未來幾何聯合分布。

### 3.4 集合窗口回歸直線斜率

對每個允許的觀察窗口，以窗口內全部 Close 與窗口序號作最小平方回歸：

```text
Close[i] = alpha + beta * i
```

該窗口的 `beta` 是可供區間判定使用的市場內涵資料。不得對斜率再套用預測模型、狀態公式或參數調整公式。

### 3.5 版本化資料 schema

每項市場內涵資料必須有穩定、版本化的 schema，至少保存：

- 穩定 ID。
- 維護名稱。
- 使用者可見名稱。
- 計算公式版本。
- 所需 OHLCV 欄位。
- 窗口是否可搜尋。
- 合法整數窗口範圍。
- 資料不足規則。
- 無效值規則。
- 資料可用時間。
- 數值精度與 canonical 編碼方式。

資料 schema 只描述已確認的市場內涵資料，不得在實作時臨場增加 z-score、百分位、投票、加權平均、主成分或其他未經使用者確認的轉換。

## 四、窗口搜尋

所有需要觀察窗口的市場內涵資料，其窗口大小不得固定為單一常數；窗口大小必須成為候選中可採樣、交叉、變異、保存與顯示的正式搜尋參數。

窗口大小是整數搜尋參數，不限定為任何預先列出的固定候選集合。從合法最小值到合法最大值之間的每一個整數窗口都可被 Sample、Mutate、Crossover 產生。

每項市場內涵資料的合法最小窗口由其既有數學定義決定；例如需要回歸直線或凸包面積的資料至少需要 2 根 K 線。不得為了統一介面，擅自把所有資料的最小窗口寫成同一個人工常數。

一次任務的合法最大窗口由該任務實際行情範圍、各評分窗口及既有 warmup 可共同支援的最大根數決定。規劃器必須在建立任務前算出並顯示每項資料的合法最小及最大窗口；超出範圍的候選由 Clamp 修復，無法修復者由 Validate 拒絕。

窗口以目前研究週期的 K 線根數計算，不寫死為日數。商品、資料源、週期與 execution mode 仍依既有研究 scope 隔離。

每個需要窗口的市場內涵資料各自保存實際採用窗口；全域判定值上限不等於全域共同窗口。不同資料可以在同一候選中搜尋出不同窗口。

若某項資料實際使用零個判定值，其窗口不影響該候選的每日參數包判定。Fingerprint 與 canonical 編碼必須把這種未生效窗口正規化，避免產生行為相同但 fingerprint 不同的重複候選。

## 五、全域判定值上限

### 5.1 唯一全域設定

使用者在一次參數搜尋任務中只設定一個全域整數 `X`：

```text
每項市場內涵資料最多可使用的判定值數量 = X
```

`X` 套用到所有市場內涵資料。不得讓使用者分別設定資料 A 的上限、資料 B 的上限，也不得為不同核心參數設定不同判定值上限。

### 5.2 候選內的實際判定值數量

對每項市場內涵資料，候選可實際使用 `0..X` 個判定值：

- 0 個判定值形成 1 個區間，表示該資料不切分參數包。
- 1 個判定值形成 2 個區間。
- 2 個判定值形成 3 個區間。
- `k` 個判定值形成 `k+1` 個區間。

實際數量由參數搜尋決定，不由使用者逐項指定。

### 5.3 判定值規則

同一資料的多個判定值必須：

- 使用該資料 schema 定義的數值精度。
- 全部為有限值。
- 嚴格由小到大排序。
- 不得重複。
- 保存原始數值與 canonical 表示。

若判定值為 `v1 < v2`，區間固定為：

```text
x < v1
v1 <= x < v2
x >= v2
```

邊界歸屬必須全系統固定，不得由前端、回測與實盤各自解釋。

Clamp 必須修復排序及合法精度；無法修復成嚴格遞增的候選由 Validate 拒絕。不得以靜默刪除判定值改變候選結構。

## 六、區間組合與完整核心參數包

### 6.1 區間組合

每項市場內涵資料在當下會得到一個區間索引。所有資料的區間索引依 schema 穩定順序組成唯一組合鍵：

```text
CombinationKey = [interval_index_1, interval_index_2, ...]
```

某候選若第 `j` 項資料使用 `k_j` 個判定值，其完整區間組合數為：

```text
CombinationCount = product(k_j + 1)
```

每個合法組合鍵必須有且只有一份完整核心參數包。不得讓多個組合鍵意外共用可變參數物件，也不得在缺少組合鍵時用鄰近區間、平均值、插值或預測值補出參數。

### 6.2 完整核心參數包

每個區間組合直接對應既有策略的一整份核心參數包，不建立「某項市場資料只能控制某個參數」的人工設定。

完整參數包沿用當前策略及 position structure 下正式有效的核心參數契約，包含：

- MicroReservePct。
- Beta。
- Gamma。
- WMean。
- WMomentum。
- WBreakout。
- DustUSD。
- RebalanceThreshold。
- ForceFullThreshold。
- ForceEmptyThreshold。
- WedgeDeltaThreshold。
- WedgeVolRatioThreshold。
- MacroBearMultiplier。
- MacroBullMultiplier。
- ExtraDeployPct。
- SoftReleaseMonths。
- SoftReleasePct。
- HardReleaseMaxPct。

既有結構設定仍生效：

- `Gamma` 是否參與搜尋，沿用既有明確開關；未啟用時不得因本功能靜默啟用。
- 純浮動模型中不生效的宏觀及釋放參數，沿用既有固定與不參與搜尋規則。
- 既有可停用訊號的權重為 0 語義保持不變。

不得要求使用者替每一項市場內涵資料、每一個區間或每一個核心參數另外設定動態上下限。所有核心參數使用既有 canonical 合法範圍、步長、精度與預設值。

### 6.3 結構限制

每一個區間組合的完整參數包都必須獨立通過既有 Validate 與跨欄結構限制，至少包含：

```text
ForceFullThreshold >= ForceEmptyThreshold
MacroBearMultiplier >= MacroBullMultiplier
```

交易所最小名義金額、比例上下限、position structure 及其他既有約束全部保持有效。任何一格的參數包無效，整個候選即無效，不得只在回測碰到該格時才拒絕。

## 七、候選與進化契約

### 7.1 候選身分

新版候選的完整身分至少包含：

- 市場內涵資料 schema 與版本。
- 全域判定值上限 `X`。
- 每項資料的實際窗口。
- 每項資料的實際判定值數量及判定值。
- 全部區間組合鍵。
- 每個組合鍵的完整核心參數包。
- strategy、position structure 與 execution mode。
- 商品、資料源、週期與 dataset hash。
- 候選 schema、計算及回測版本。

上述任一有效內容不同，都必須形成不同 fingerprint。map 順序、JSON 欄位順序或未生效窗口等非行為差異不得形成不同 fingerprint。

### 7.2 通用進化引擎邊界

通用 Evolution 引擎仍只看不透明 Gene，不得認識市場內涵資料名稱、判定值、區間組合或核心參數欄位。

具體策略的 EvolvableStrategy 實作負責：

- Sample：產生合法判定結構及所有組合參數包。
- Clamp：修復窗口、判定值排序、參數邊界及跨欄限制。
- Validate：驗證完整組合覆蓋及每格參數包。
- Mutate：可變異窗口、實際判定值數量、判定值與任一組合參數包。
- Crossover：產生語義完整、可驗證的子代，不得交叉出缺格或重複格。
- Fingerprint：涵蓋完整候選行為。
- Evaluate：在同一共用回測核心逐根 K 線判定參數包並評分。
- EncodeResult／DecodeElite：完整保存與重建新版候選。

結構變異或父代結構不同時，不得把兩份長度不同的扁平陣列硬做欄位對位交叉。具體結構操作必須版本化並接受確定性測試。

### 7.3 計算量預覽

建立任務前必須依市場資料數、各資料實際或最大區間數、組合參數包數、候選數、世代數與回測窗口，提供計算量及候選大小預覽。

預覽至少顯示：

- 市場內涵資料數。
- 全域判定值上限。
- 單一候選最大區間組合數。
- 單一候選最大核心參數值數量。
- 預計個體評估數。
- 預計回測數與快取命中。
- 記憶體及儲存量估計。

系統不得暗中減少市場內涵資料、判定值或組合參數包。若超過既有計算硬上限，必須在建立任務前明確拒絕並顯示實際數量；不得配置爆量記憶體後才失敗。

## 八、每日判定與純計算邊界

市場內涵資料計算、區間判定與參數包選取必須是純、確定性計算：

```text
相同行情快照
+ 相同候選
+ 相同 schema 版本
= 相同 CombinationKey 與完整核心參數包
```

它不得讀取資料庫、網路、檔案、系統時間或不可控隨機。

行情載入、窗口建構與資料對齊留在 SaaS／Lab 外圈；選出的完整參數包透過既有 StrategyInput 契約提供給同一個 `Step()`。不得建立回測專用策略分支，也不得讓 LocalAgent 計算市場內涵資料或自行選參數。

資料不足或數值無效時不得偽造為 0、沿用鄰近區間或重新解釋門檻。研究回測在評分區間前使用既有 warmup；正式執行若最新已完成資料仍不足以形成完整判定，該次不產生新的倉位調整決策並記錄明確原因。

## 九、倉位調整執行時間

本功能必須完整沿用研究任務選定的 `execution_mode`。市場內涵資料、區間判定、參數包、策略輸出與成交價不得跨模式混用。

### 9.1 今日收盤、同日收盤執行

`close_same_bar` 固定為：

```text
今日已完成 close
→ 計算今日市場內涵資料
→ 選出今日完整參數包
→ 呼叫 Step() 算出今日目標持有權重
→ 以同一根 K 線 close 的既有研究假設執行調整
```

### 9.2 今日收盤、次一開盤執行

`close_next_open` 固定為：

```text
今日已完成 close
→ 計算今日市場內涵資料
→ 選出今日完整參數包
→ 呼叫 Step() 算出對應的目標持有權重
→ 凍結本次決策的行情時間、CombinationKey、參數包 hash 與目標持有權重
→ 下一個交易日 open 執行倉位調整
```

次一開盤不得使用新開盤價重新判定市場內涵區間、重新選參數包或重新計算一份不同的目標權重。新開盤價只依既有執行與成交語義用於完成上一個收盤決策。

若下一個交易日開盤執行失敗、缺少價格或服務重啟，必須以既有 pending 決策與冪等規則恢復或明確失敗；不得悄悄改用下一根收盤資料覆蓋。

### 9.3 收盤前快照執行

`preclose_10m` 只能使用實際存在的收盤前快照：

```text
收盤前快照
→ 計算該快照可得的市場內涵資料
→ 選參數包並計算目標持有權重
→ 依既有接近收盤執行假設調整
```

不得以正式日 K close 冒充歷史收盤前快照。

### 9.4 回測與實盤一致

回測與正式執行必須共用：

- 同一市場內涵資料 schema。
- 同一窗口與資料可用時間。
- 同一區間邊界歸屬。
- 同一 CombinationKey 產生器。
- 同一完整參數包驗證器。
- 同一 `Step()`。
- 同一 execution mode 時序。

LocalAgent 仍只執行 SaaS 下發的交易命令，不取得候選、判定值、CombinationKey 或策略邏輯。

## 十、參數搜尋、結果與人工採用

本功能沿用既有進化生命週期：

```text
建立搜尋設定
→ 預覽計算量
→ 初始化種群
→ 回測評估
→ 選擇、交叉、變異與精英保留
→ 產生 challenger
→ 使用者查看研究結果
→ 人工 Promote 後才成為 champion
```

不得因任務完成、分數最高或區間結構產生就自動採用、Promote 或改變實盤參數。

每一筆候選及結果至少保存：

- 完整候選 JSON 與 schema version。
- canonical hash 與 fingerprint。
- 全域判定值上限。
- 每項市場資料的窗口、判定值數量與判定值。
- 區間組合到完整參數包的完整映射。
- 每個評分窗口的回測摘要。
- execution mode、成本、出生點、資料範圍與 dataset hash。
- 策略、回測核心及市場內涵資料公式版本。
- 候選來源任務、世代與個體。

使用者可展開查看判定值、區間與對應參數包，但 UI 不得用內部代號或裸公式取代可理解名稱。

## 十一、既有資料與相容性

### 11.1 既有靜態參數搜尋

既有靜態參數候選、任務、challenger、champion、retired、回測與誕生觀察資料保持可讀、可回測、可 Promote。

新版候選使用獨立 schema version。不得把舊靜態參數包偽造補齊成新版區間候選，也不得在載入舊 champion 時改變其歷史行為。

未採用新版區間候選模式時，既有參數搜尋與回測結果必須逐位元或在既有容許精度內保持不變。

### 11.2 與 M 優化實驗室

本功能升級的是既有參數搜尋，不取代 M 優化實驗室。

新版完整候選若後續進入 M，必須以完整不可變採用單位保存市場內涵資料 schema、窗口、判定值、組合映射與全部參數包；不得只抽出某一天生效的單一參數包冒充完整候選。

M 是否把此結構展開為研究維度，必須另有相容 schema；本功能不得為了接入 M 而改寫既有 M 地形、區域、候選或人工採用語義。

### 11.3 與預測及幾何研究

本功能可重用既有因果行情活動與幾何數學實作，但不引用其預測結果或模型生命週期。

不得因本功能完成而修改、刪除或自動重訓：

- 既有可解釋預測模型。
- TCN 預測模型。
- 走勢幾何預測模型。
- 動態政策。
- 已保存模型、預測、狀態、搜尋或回測結果。

## 十二、資料模型與保存

所有持久化資料使用 GORM model 與 AutoMigrate，不建立 SQL migration。

正式資料模型至少要能表示：

- 任務層全域判定值上限。
- 市場內涵資料 schema version。
- 候選 schema version。
- 每項資料的窗口及判定值。
- 完整 CombinationKey 集合。
- 每個 CombinationKey 的完整核心參數包。
- canonical hash、fingerprint 與 lineage。
- 回測、候選角色及 Promote 引用。

候選內容建立後不可變；重新搜尋、公式版本改變、合法窗口範圍改變或判定值改變都建立新候選，不覆寫舊資料。

備份與還原工具必須包含新版候選完整引用閉包。還原後 canonical hash、fingerprint、組合映射、參數包、任務及 Promote 關係必須一致。

## 十三、前端工作區

既有參數搜尋頁新增本功能所需設定與結果，不建立另一個「預測與動態參數」式工作流。

設定區至少提供：

- 是否使用市場資料區間參數包候選。
- 全域「每項資料最多幾個判定值」。
- 市場內涵資料清單及其公式說明，只讀顯示，不逐項勾選。
- 每項資料的可搜尋整數窗口範圍，只讀顯示。
- execution mode。
- position structure 及既有搜尋設定。
- 建立前計算量預覽。

結果區至少提供：

- 實際使用判定值的市場資料。
- 每項資料的實際窗口。
- 每項資料的判定值數量及判定值。
- 可展開的區間組合與完整參數包。
- 各評分窗口績效、回撤與既有基準比較。
- 任務、候選、參數庫與 Promote 關係。

大量組合不得一次展開或一次送到前端。使用分頁、虛擬化或按需載入；收合時停止資料轉換與渲染。

## 十四、測試要求

### 14.1 市場內涵資料

- 六項既有行情活動數值與歷史相對值和原實作一致。
- 幾何凸包面積、共線處理及回歸斜率和既有定義一致。
- 每項資料從合法最小窗口到合法最大窗口的所有整數值都可進入搜尋，不存在固定候選窗口清單。
- 任務預覽正確顯示每項資料依公式、行情、評分窗口及 warmup 算出的合法窗口範圍。
- 每項窗口只使用截至當下已完成的 K 線。
- 窗口不足、無效 OHLCV、NaN 與 Infinity 不偽造為 0。
- 不得載入或呼叫任何預測模型。

### 14.2 判定值與組合

- 全域 `X` 正確套用到所有市場內涵資料。
- 每項資料可實際使用 `0..X` 個判定值。
- `k` 個判定值形成 `k+1` 個區間。
- 判定值嚴格遞增，等於邊界時歸屬一致。
- CombinationKey 順序穩定且完整。
- 組合數等於 `product(k_j+1)`。
- 每個組合有且只有一份完整參數包。
- 缺格、重複格或任一無效參數包會拒絕整個候選。

### 14.3 進化操作

- Sample、Clamp、Validate、Mutate、Crossover 產生的候選皆結構完整。
- 不同 JSON／map 順序產生相同 fingerprint。
- 行為不同的窗口、判定值或參數包必須產生不同 fingerprint。
- 結構變異後不殘留不可達、重複或缺失組合。
- Epoch 快取只重用完整 fingerprint 相同的評估。
- 取消與 Early Stop 正確保存或不保存候選，沿用既有規則。

### 14.4 回測與執行時序

- `close_same_bar` 使用同日 close 決策及執行。
- `close_next_open` 使用今日 close 決策、凍結參數包及目標持有權重，次一 open 執行。
- 次一 open 不重新判定區間或重算目標持有權重。
- `preclose_10m` 只使用真實歷史快照。
- 回測與正式執行使用同一 `Step()`、同一參數包選取及同一 execution mode。
- 服務重啟與重試不會重複執行或覆寫 pending 決策。

### 14.5 相容性與保存

- 未啟用新版候選時，既有參數搜尋結果不變。
- 舊 GeneRecord、challenger、champion 與 retired 可正常載入及回測。
- 新版 challenger 不會自動 Promote。
- 商品、資料源、週期與 execution mode 隔離保持有效。
- 備份還原後完整候選、hash、任務及採用關係一致。
- 前端在桌面及行動 viewport 可操作大量區間組合，不白屏、不一次載入全部資料。

## 十五、完成定義

本功能只有同時完成下列全部項目，才可標記為 `已完成`：

1. 所有已確認市場內涵資料、幾何面積及集合窗口回歸斜率均已接入。
2. 所有需要窗口的資料，其窗口均可由參數搜尋處理。
3. 單一全域判定值上限、每項 `0..X` 實際判定值及固定邊界語義均已完成。
4. 完整區間組合與每格完整核心參數包的 Sample、Clamp、Validate、Mutate、Crossover、Fingerprint 全部完成。
5. 新版候選可走完整既有參數搜尋、回測、challenger、人工 Promote 及 champion 載入流程。
6. 三種 execution mode 的決策與執行時序完整，尤其今日收盤決策／次一開盤執行不得重算。
7. 回測與正式執行共用同一 `Step()` 與同一參數包選取契約。
8. 計算量預覽、進度、取消、快取、錯誤與大型結果按需載入完成。
9. 舊靜態候選、既有模型、動態政策、M 研究與所有歷史結果保持相容。
10. 單元、整合、前端、效能、備份還原及端到端驗收全部通過。
11. 逐項比對本文件、三份穩定真源、重大更新開發守則及相關研究文件，完成必要的相容註記。
12. 使用者完成驗收並明確核准後，才同步更新三份穩定真源。

只有資料欄位、UI 開關、候選骨架、單一市場資料、單一窗口、單一判定值、只接 Beta、只跑 happy path 或只完成回測而未接實際採用，全部只能標記為 `部分完成`，不得宣稱本功能完成。

## 十六、禁止事項

- 不得拆成 MVP、第一版或第二版後把部分能力回報為完成。
- 不得把預測模型輸出混入市場內涵資料。
- 不得建立市場狀態名稱、狀態機、遲滯或持續日數。
- 不得使用公式把市場資料連續換算成核心參數。
- 不得讓使用者逐項設定每個市場資料可控制哪些核心參數。
- 不得為各市場資料分別設定判定值數量上限。
- 不得為每個區間另設人工核心參數上下限。
- 不得缺格時使用鄰近值、平均、插值或預測補值。
- 不得在次一開盤重新判定今日收盤已凍結的決策。
- 不得在策略核心加入行情載入、資料庫、網路、模型、時間或任務 I/O。
- 不得讓 Agent 取得候選或自主計算策略參數。
- 不得建立 SQL migration。
- 不得自動 Promote、淘汰或替使用者決定是否採用。

## 十七、精確效能與資源控制

本功能的效能優化不得改變任一市場內涵資料、區間邊界、參數包選取、策略 `Step()`、成交時序或回測窗口的數學語義。

- 同一任務內，對相同 K 線序列與相同整數窗口重複需要的活動度、歷史比值、幾何凸包面積及趨勢斜率，必須共用原始公式已算出的不可變結果。
- 快取必須是任務內記憶體資料，不得成為資料真源或跨商品、資料版本、使用者任務的隱性共用狀態。
- 快取使用惰性建立與明確 LRU 記憶體上限；超出上限時可淘汰並於需要時依原公式重算，但不得降低精度、改用近似值或刪減候選。
- 參數包選取可將既有區間組合預先轉為每根 K 線對應的完整參數包索引；其輸出必須與原本組合鍵比較完全一致。
- 回測的獨立評分窗口可平行執行，但每個窗口的資料、暖機、初始資金、execution mode 與完整策略路徑必須保持獨立；不得用主回測結果替代需要獨立重跑的窗口。
- 任何優化都必須有未快取／快取的逐根比較：有效參數包、結構組合、交易、目標權重、淨值、回撤、成本及最終績效必須完全一致。若未能證明一致，不得啟用該優化。

## 十八、核心參數格點與未重複候選

參數搜尋的每一份可演化核心參數包使用固定數值格點：

```text
搜尋格點 = 0.05
```

- 所有可演化的浮點核心參數只能取 `0.05` 的整數倍；原有硬邊界仍有效，不能取超出邊界的格點。
- 整數核心參數維持整數語義；整數本身亦符合 `0.05` 的倍數要求。
- 未被本次搜尋選用的固定欄位保持使用者／既有參數包的原值，不因格點規則被偷偷改寫。
- 抽樣、交叉、變異與區間組合中的每一份核心參數包必須直接在格點空間產生，不能先產生連續值再於回測前攔截。
- 候選進入回測前必須先取得任務範圍的唯一保留權；已保留或已評估的完整候選不得再次進入回測。
- 變異仍以績效較佳親代附近的小步格點移動為優先。若鄰近可用格點已全部保留，才擴大到尚未保留的其他合法格點，不得重跑已評估候選。
- 無限連續搜尋的所有 iteration 必須共用同一份任務內候選保留集合，不能每輪重置而重新回測舊候選。
- 不同任務亦適用未重複規則：以「會改變候選績效」的策略、資料、訓練區間、執行／成本／資金條件、核心結構與固定值形成持久化比對鍵；族群數、世代數、起始種子、追蹤與進度設定、一般／連續／無限連續控制選項不得影響該比對鍵。
