# 通用研究結果與參數比較工具開發指導

> 字母大點：N
>
> 狀態：N-01 至 N-06 全部規格已確認，待依賴完成後排程開發
>
> 文件定位：本文件是 N 的正式開發指導，定義如何在不重新計算、不修改來源成果的前提下，比較既有參數與研究結果。它不是三份穩定真源文件，不取代既有參數庫、回測、報酬分析或研究模組規格。
>
> 開發方式：N 不做 MVP。只有本文件所列來源、保存、相容判定、頁面、效能、錯誤處理與測試全部完成，才可回報 N 已完成。

## 一、研究目的

N 用來回答：

```text
這些已經存在的參數有哪些數值與結構差異？
這些已經存在的研究成果，在各自背景下呈現哪些相同或不同現象？
哪些資料可以直接共圖，哪些只能並排，哪些根本不能作數值比較？
```

它解決的是「集中讀取與觀察」問題，不是新的參數研究、回測、報酬分析、驗證或自動決策系統。

N 可以比較不同片段、商品、期間、研究設定或來源類型的既有成果，但必須忠實顯示背景差異與相容限制，不得把並排觀察包裝成受控實驗。

## 二、完成品邊界

N 的完成品固定為：

- 一個獨立頂層「研究比較」頁面。
- 同一工作區內彼此分離的「參數比較」與「研究結果比較」兩個分頁。
- 可保存、重開、複製、改名、封存及刪除的比較工作區。
- 各來源頁可把精確版本的參數或研究成果加入指定工作區。
- 逐資料區塊判定比較相容性。
- 按需讀取來源的完整既有資料與圖表，而非只讀少量摘要。

N 明確不做：

- 不執行或補算回測。
- 不建立或補算 G 報酬分析。
- 不訓練 K 模型，不產生預測或市場狀態。
- 不執行 M、H、L、C 或其他研究任務。
- 不修改參數、研究設定、研究結果或來源狀態。
- 不自動評分、排名、選優、淘汰或 Promote 參數。
- 不建立跨商品、跨期間或跨研究類型的總冠軍榜。
- 不取代 M 的 `ResearchSeries`、共同 manifest 或受控比較快照。
- 不把缺少的資料猜成零值、插值、代理值或自行推算值。

## 三、核心名詞

### 3.1 比較工作區

`ComparisonWorkspace` 是使用者保存的一組來源引用及畫面狀態。它不是研究結果，不擁有來源成果內容。

### 3.2 比較項目

比較項目分成兩類：

- `parameter`：一份可識別的完整參數或參數快照。
- `research_result`：一份可識別的既有回測、分析或研究成果版本。

兩類項目分別出現在兩個分頁，不壓成同一張通用數值表。

### 3.3 唯讀比較資料介面

每個來源模組提供的 `ReadOnlyComparisonData` 或等價介面，稱為「唯讀比較資料介面」。它可以按需提供完整既有資料，但只能讀取，不得藉由此介面觸發來源計算或改寫來源。

「唯讀」描述操作權限，不代表只有摘要。

### 3.4 比較資料區塊

一份來源成果由多個 `ComparisonBlock` 組成，例如：

- 回測背景。
- 績效與風險指標。
- NAV 路徑。
- 報酬分佈。
- 曝險資料。
- M 績效地形。
- H 對照分佈。
- L 擾動敏感度。
- C 行為特徵與路徑地圖。
- K 樣本外驗證、校準、預測與狀態報告。

相容性以區塊為單位判定，不以整份來源一次判死。

## 四、依賴關係與開發順序

### 4.1 來源依賴

N 依賴下列既有或已規劃模組的不可變成果、版本與唯讀比較資料介面：

```text
既有正式參數庫
docs/研究構想整理/標準化回測結果保存機制開發指導.md
docs/研究構想整理/報酬分析共用模組開發指導.md
docs/研究構想整理/參數績效地形研究與穩健候選產生系統開發指導.md
docs/研究構想整理/隨機參數與無意義規則對照系統開發指導.md
docs/研究構想整理/擾動行情資料產生器開發指導.md
docs/研究構想整理/參數可獲利K線樣貌反推系統開發指導.md
docs/研究構想整理/動態適應參數機制開發指導.md
```

N 只依賴來源的已保存結果，不依賴來源的計算 worker 才能顯示既有成果。

### 4.2 與 I 的關係

N 不依賴 I 計算任務與快取系統。原因是 N 不建立任何研究計畫、回測、報酬分析或大量補算任務。

矩陣轉置、差值顯示、排序、篩選與相容 metadata 判定是一般同步介面操作，不得包裝成 I 任務。

### 4.3 固定開發順序

1. 各來源先具備不可變 ID、版本或 snapshot ID、內容 hash 與封存語義。
2. 各來源實作本文件要求的唯讀比較資料介面與契約測試。
3. 建立 N 共用來源描述、區塊描述、相容規則與 canonical 參數身分規則。
4. 建立工作區、項目引用、畫面狀態與相容結果保存。
5. 建立來源搜尋、來源頁「加入研究比較」與完整 deep-link。
6. 建立參數矩陣與研究成果面板。
7. 完成延遲載入、虛擬化、錯誤狀態、權限、備份及所有測試。

某個來源尚未提供正式介面時，可以先完成其他來源的契約，但不得以臨時複製資料、假 payload 或空白 adapter 宣稱 N 完成。

## 五、所有權與資料真源

### 5.1 N 擁有的資料

N 只擁有：

- 工作區名稱、備註與狀態。
- 比較項目的精確來源引用與顯示順序。
- 基準參數選擇。
- 矩陣方向、顯示欄位與只看差異設定。
- 已開啟的成果區塊。
- 圖表 metric、X/Y、疊圖或並排方式。
- 使用者指定的識別色。
- 相容規則版本及該工作區目前保存的相容判定結果。

### 5.2 來源擁有的資料

完整參數內容、NAV、報酬分佈、曝險、M 地形、H 分佈、L seed/alpha 結果、C 路徑與特徵、K 模型報告都由各自來源模組持有。

N 不複製這些 payload 成為第二份成果真源。N 只保存來源定位資料，開啟區塊時再按內容 hash 讀取來源。

### 5.3 允許的暫時計算

下列只屬於畫面顯示，可在記憶體即時計算：

- 兩個數值的有號差。
- 合法且相同格點 schema 下的步數差。
- 矩陣轉置、欄位交集、只看差異、排序與篩選。
- 由來源 metadata 套用本文件規則得到的相容等級。

這些值不保存成新的參數評分、回測指標或研究結果。

## 六、頁面與導覽

N 建立獨立頂層頁面「研究比較」，放在「K 線樣貌反推」之後：

```text
優化實驗室
回測
隨機對照
K 線樣貌反推
研究比較
```

第一層直接顯示可搜尋、篩選及重開的工作區清單，不建立介紹或行銷首頁。

進入工作區後固定有兩個分頁：

```text
參數比較
研究結果比較
```

兩個分頁共用同一份工作區名稱、備註、項目管理與來源選擇流程，但各自保存順序、基準與畫面狀態。

## 七、參數比較來源

### 7.1 正式來源

參數分頁只接受下列來源：

| 來源 | 比較單位 | 規則 |
|---|---|---|
| 正式參數庫 | 單一 `challenger`、`champion` 或 `retired` 紀錄版本 | 保留角色、scope、參數 schema 與來源 lineage |
| M | 單一不可變 `RobustCandidate` 版本 | 顯示來源 configuration、region、analysis snapshot 與候選角色 |
| H | 隨機參數庫中的單一隨機參數紀錄 | 必須綁定批次、seed、生成版本與參數空間 schema |
| 標準化回測結果 | Backtest Spec 中的凍結參數快照 | 只在找不到正式參數庫或 M canonical 來源時作 fallback |

K 動態候選若由 M 或正式參數庫保存，仍使用上述 canonical 來源；比較單位必須包含完整模型 artifact、預測 schema、狀態規則、動態政策與有效參數結構，不得降成一組裸靜態數值。

### 7.2 不建立重複參數項目

H、L 或 C 的研究結果若只是引用一份已存在的正式參數或 M 候選，該引用只作為 lineage 與跳轉，不再建立新的參數比較項目。

canonical 身分優先順序固定為：

1. 正式參數庫紀錄版本。
2. M `RobustCandidate` 版本。
3. H 隨機參數紀錄版本。
4. 無 canonical 來源時才使用 Backtest Spec 凍結參數快照。

同一完整參數內容可能因人工目的而存在於不同 canonical 紀錄；N 可以同時顯示，但必須標明內容 hash 相同，不得自動刪除使用者選取的 lineage 差異。

## 八、研究結果比較來源

研究結果分頁接受下列不可變來源版本：

| 來源 | 可讀取內容 |
|---|---|
| 標準化回測結果 | Backtest Spec、摘要、按需完整路徑及既有 G 報告引用 |
| G 報酬分析 | 精確 `PerformanceReport` 版本的日／週／月分佈、累加、最長水下期、Sortino、Beta 與曝險分析 |
| M | `ResearchAnalysisSnapshot`、地形、穩健區域、候選前緣與中心；`ResearchComparisonSnapshot` 的受控比較結論 |
| H | 精確對照任務／結果 snapshot 的正式參數位置、隨機參數分佈、無意義規則及曝險打散分佈 |
| L | 精確 analysis snapshot 的 alpha/seed 分佈、敏感度、逐筆結果及缺漏狀態 |
| C | 精確 study/archive snapshot 的 A/B 地圖、特徵分佈、覆蓋率、路徑距離與失敗邊界 |
| K | 精確 artifact/report snapshot 的樣本外驗證、校準、聯合預測分佈、結構狀態與有效參數診斷 |

BacktestResult 與 PerformanceReport 使用獨立精確引用，因為同一回測結果可以有多份 Beta 基準、無風險利率、聚合方式或分析版本不同的 G 報告。加入 BacktestResult 時只列出既有 G 報告，不自動猜選其中一份；使用者選定哪份報告後，工作區才保存該 PerformanceReport 的精確引用。需要比較同一回測的多份 G 設定時，可以分別加入。

### 8.1 只作背景、不作獨立成果的項目

- E dataset 版本是資料來源與 lineage，不是 N 的獨立研究結果；使用 E 的 BacktestResult 或 M 結果會顯示其精確版本。
- D 濾網是回測或研究設定的一部分，不建立 D 專用研究結果項目。
- J 的地形與穩健統計以 M `ResearchAnalysisSnapshot` 表示，不建立第二份 J 成果。
- M `ResearchSeries` 與 `ResearchComparisonSnapshot` 可以作為來源背景及受控比較摘要，但 N 不遞迴展開成「比較另一個比較」的新評分，也不取代 M。

## 九、唯讀比較資料介面

### 9.1 共用來源描述

每個來源 adapter 至少提供：

```text
source_kind
source_id
source_version
snapshot_id（如適用）
content_hash
canonical_subject_ref（如適用）
display_name
source_status
archived
created_at
newer_version_ref（如有）
source_link
available_blocks
```

`source_id + source_version + snapshot_id + content_hash` 必須能固定到工作區建立時的精確內容。可變名稱、備註、標籤或角色狀態另行顯示，不得取代不可變身分。

### 9.2 區塊描述

每個 `ComparisonBlock` 至少提供：

```text
block_id
block_kind
schema_id
schema_version
formula_version
unit
axes
context_fingerprint
content_hash
availability
summary
payload_locator
```

`context_fingerprint` 只保存判定相容性所需的正式背景欄位與 hash，不保存完整成果 payload。

`availability` 至少區分：

```text
available
not_calculated
partial
failed
unsupported
missing
corrupt
```

### 9.3 延遲讀取

來源列表只回傳描述與必要摘要。完整矩陣值、NAV、分佈、地形或路徑資料只在使用者開啟對應區塊時讀取。

讀取區塊不得：

- 啟動來源任務。
- 自動補算未建立的分析。
- 更新來源 snapshot。
- 把 partial 當成 complete。
- 因圖表切換而寫回來源資料。

### 9.4 來源 adapter 邊界

來源 adapter 位於 SaaS 應用層，只負責權限檢查、描述轉換與讀取既有資料。它不得進入策略核心，也不得把資料庫、網路或 UI 狀態加入 `Step()`。

## 十、參數資料契約

每個參數來源必須提供：

- 穩定的參數 schema ID 與版本。
- 每個欄位的穩定 ID、群組、資料型別、單位及顯示名稱。
- 每個欄位的實際值。
- 固定值、研究變數、動態係數或結構欄位的角色。
- 合法格點起點與步長，如有。
- 欄位是否存在、是否啟用及不適用原因。
- strategy、instrument、interval、data source、execution mode 與其他 scope。
- 來源研究、回測、H/L/C 分析及參數庫 lineage 連結。

欄位以穩定 schema ID 對齊，不以顯示文字猜測相同欄位。不同 schema 恰好同名的欄位不得自動合併。

只有兩個數值欄位的 schema、單位與定義相容時才顯示有號差。只有合法格點起點與步長也相同時才顯示步數差。

不存在或未啟用的欄位顯示「不適用」，不得顯示為 `0`。

## 十一、逐區塊相容規則

### 11.1 四級相容狀態

每組待比較區塊必須得到下列其中一級：

1. `direct`
   - 定義、公式版本、單位、軸、必要背景與資料語義一致。
   - 可以共用表格、共用座標軸、疊圖及計算有意義的顯示差值。

2. `side_by_side`
   - 指標定義與單位一致，但商品、期間、dataset 或其他研究背景不同。
   - 可以同步並排觀察，但不得冒充控制變因實驗，不產生自動總排名。

3. `descriptive_only`
   - 來源屬於不同研究成果類型，沒有共同數值語義。
   - 各自顯示完整來源面板，只能作描述性對照，不共軸、不算差值。

4. `incompatible`
   - 外觀看似同一欄位或區塊，但公式版本、單位、schema、軸或資料語義衝突。
   - 顯示不相容原因並禁止合併；只能回來源建立相容成果，N 不自行轉換。

### 11.2 判定輸入

相容判定至少檢查：

- block kind、schema 與公式版本。
- 單位與數值方向。
- X/Y/Z 軸的定義、尺度與時間頻率。
- strategy、instrument、dataset hash、interval 與日期區間。
- execution mode、成交規則、成本、現金流及 DCA 基準。
- 回測核心、每日實際持倉、報酬與回撤定義版本。
- 來源完整度及資料是否損壞。

不同區塊需要的背景不同；例如參數矩陣不要求 dataset 相同，但 NAV 直接疊圖必須檢查時間軸與回測語義。

### 11.3 M 的既有判定優先

若區塊來自 M `ResearchComparisonSnapshot`，M 保存的四級比較資格與共同 manifest 是該受控比較的權威判定。

固定映射為：

| M 比較資格 | N 顯示等級 |
|---|---|
| `paired_direct` | `direct` |
| `context_matched_unpaired` | `side_by_side` |
| `descriptive_only` | `descriptive_only` |
| `incompatible` | `incompatible` |

N 可以因自身顯示能力不足而降級，但不得把 M 標記為 `context_matched_unpaired`、`descriptive_only` 或 `incompatible` 的結果升級成直接比較，也不得補造缺少的共同點。

### 11.4 判定保存

工作區保存相容規則版本、參與項目集合 hash、逐區塊結果與原因。若系統已有新版相容規則，舊工作區先顯示「判定規則已有新版」，不在背景靜默改寫；使用者明確更新判定後才保存新結果。

更新相容判定不會更新來源版本，也不建立研究成果。

## 十二、參數比較分頁

### 12.1 主矩陣

參數比較使用可轉置矩陣：

- 預設以參數欄位為列、所選參數為欄。
- 可以轉置成參數為列、欄位為欄。
- 可選一份參數作顯示基準。
- 可切換顯示原值、有號差及合法時的步數差。
- 可只顯示至少一份參數不同的欄位。

矩陣不得因欄位不存在而補零，也不得把固定值、動態係數、結構開關與一般核心參數混成沒有標示的數字。

### 12.2 視覺語義

- 相同值弱化顯示。
- 不同值清楚標示。
- 差異大小只表示數值距離，不暗示較大或較小較好。
- 顯示值使用來源 schema 的精度；內部比較不得先依畫面小數位截斷。
- 長欄位名稱、動態結構及不適用狀態不得重疊或撐壞矩陣。

### 12.3 固定 metadata

每份參數至少顯示：

- 名稱、來源、角色與版本。
- 參數 schema 與版本。
- 商品、週期、資料源與執行模式。
- 固定／動態結構摘要。
- 來源 M、Backtest、H、L、C 或參數庫連結。

### 12.4 明確禁止

參數分頁不提供：

- 雷達圖。
- 平行座標圖。
- 自動總分。
- 自動排名或最佳參數標籤。
- 以同名欄位猜測跨 schema 相容。

## 十三、研究結果比較分頁

### 13.1 共通背景與既有指標表

第一層固定顯示：

- 名稱、來源類型、狀態與版本。
- 受測參數或研究 subject。
- 商品、dataset 版本、週期與日期區間。
- execution mode、成本、現金流與基準。
- 回測核心、指標與來源 schema 版本。
- 各資料區塊的相容等級及理由。
- 來源已經存在且定義相容的績效與風險指標。

來源未建立某個分析時顯示「未計算」及返回來源的入口。N 不提供「立即計算」按鈕。

### 13.2 來源型別面板

第二層按來源使用既有共用元件：

- Backtest / G：NAV、日／週／月報酬分佈、日報酬累加、最長水下期、回撤與曝險。
- M：一維曲線、二維地形、可選 3D 曲面、穩健區域、候選前緣與中心。
- H：隨機參數與曝險打散分佈、無意義規則及受測參數位置。
- L：alpha 敏感度、seed 分位帶、逐筆結果、缺漏與失敗分佈。
- C：A/B 地圖、行為特徵、覆蓋率、完整路徑距離與失敗邊界。
- K：樣本外驗證、校準、聯合預測分佈、結構狀態與有效參數診斷。

N 優先重用各來源正式圖表元件或共享資料轉譯器，不另寫一套會改變公式的圖表資料生成邏輯。

### 13.3 顯示方式

- `direct`：可以疊圖或同步並排。
- `side_by_side`：只可同步並排。
- `descriptive_only`：顯示各自完整面板，不共用座標軸。
- `incompatible`：顯示原因，不建立共同圖。

面板只在使用者明確展開時載入。切換 metric、圖層或來源只讀已存在的資料，不得重新回測或補分析。

## 十四、工作區保存機制

### 14.1 必須保存的內容

每個工作區保存：

- 名稱、備註、建立者、建立時間與封存狀態。
- 參數項目及順序。
- 研究結果項目及順序。
- 每項的來源類型、ID、版本、snapshot ID 與內容 hash。
- 只供來源缺失時辨識用的最後已知顯示名稱、來源類型與 scope 摘要；不得包含成果 payload。
- 基準參數。
- 矩陣方向、欄位選擇及只看差異設定。
- 已開啟的成果區塊。
- 圖表 metric、X/Y、疊圖或並排模式。
- 使用者指定識別色。
- 相容規則版本與結果。

### 14.2 固定來源版本

H、L、C、M 或其他來源追加批次、分析或新版結果時，舊工作區仍指向原本 snapshot。N 只提示「已有新版」，不得自動替換。

使用者可以：

- 把新版另行加入同一工作區。
- 以新版替換某項引用。
- 複製工作區後再替換，保留兩種觀察配置。

### 14.3 可編輯工作區

工作區是畫面與引用狀態，不是不可變研究成果，因此可以：

- 新增、移除及重新排序項目。
- 修改基準與顯示方式。
- 改名、修改備註與識別色。
- 複製、封存、解除封存或刪除工作區。

一般拖曳、收合或欄寬變更不建立不可變版本歷史。需要保留另一套配置時使用「複製工作區」。

## 十五、正式資料模型

實作使用 GORM model 與 AutoMigrate，不建立 SQL migration。

| Model | 必要內容 | 限制 |
|---|---|---|
| `ComparisonWorkspace` | owner、名稱、備註、狀態、revision、兩分頁 view state、目前 compatibility snapshot、時間 | 只屬於有權限的使用者；封存不刪引用 |
| `ComparisonWorkspaceItem` | workspace、tab kind、source kind、source ID/version/snapshot/hash、canonical subject、順序、識別色、最小 last-known descriptor | 精確來源引用在同一分頁不得重複；last-known descriptor 不得包含成果 payload |
| `ComparisonCompatibilitySnapshot` | workspace、item set hash、規則版本、逐區塊等級與原因、建立時間 | 只保存相容 metadata，不複製來源 payload |

唯一性至少包含：

```text
(workspace_id, tab_kind, source_kind, source_id, source_version, snapshot_id)
```

工作區更新使用 revision 或等價 optimistic concurrency，避免兩個分頁同時儲存時互相覆蓋。

Postgres 是工作區真源。Redis 或瀏覽器快取只能依 immutable content hash 暫存可重讀的來源區塊。

## 十六、加入比較與操作流程

### 16.1 從 N 頁加入

N 提供來源選擇器，可依下列條件搜尋及篩選：

- 來源類型。
- 名稱。
- 商品。
- 週期。
- 日期區間。
- 狀態與建立時間。

選取項目時必須先顯示來源、版本、snapshot、背景摘要與是否已有新版，再加入目前工作區。

### 16.2 從來源頁加入

正式參數庫、Backtest/G、M、H、L、C、K 的適當結果頁提供「加入研究比較」。使用者可以：

- 選擇既有工作區。
- 建立新工作區。
- 加入後直接前往工作區。

同一精確來源版本已存在時不重複新增，而是定位既有項目。

### 16.3 一般使用流程

```text
建立或開啟工作區
→ 加入參數或研究成果的精確版本
→ 檢查逐區塊相容狀態
→ 在參數矩陣或研究面板比較
→ 調整基準、順序與顯示方式
→ 關閉後依同一引用與畫面狀態重開
```

## 十七、後端服務與 API 契約

### 17.1 服務邊界

| Service | 責任 | 禁止事項 |
|---|---|---|
| `ComparisonSourceRegistry` | 註冊來源 adapter、列出可用來源與區塊 | 不讀策略核心、不計算研究結果 |
| `ComparisonCompatibilityService` | 依版本化 metadata 作逐區塊判定 | 不插值、不升級 M 權威判定 |
| `ComparisonWorkspaceService` | 工作區、項目、順序、view state 與封存 | 不複製來源 payload |
| `ComparisonIntegrityService` | 版本、hash、缺失、封存及新版提示 | 不自動替換來源 |

### 17.2 API 類型

API 至少提供：

- 工作區列表、建立、讀取、修改、複製、封存、解除封存與刪除。
- 分頁式來源搜尋。
- 加入、移除與排序工作區項目。
- 讀取來源 descriptor。
- 按需讀取單一 comparison block。
- 建立或明確更新 compatibility snapshot。
- 從來源 deep-link 建立加入動作。

N API 不提供 `start backtest`、`calculate report`、`train`、`resume research` 或任何等價計算端點。

### 17.3 API 共通要求

- 所有列表分頁，完整 payload 不得混入列表 response。
- 每次區塊讀取驗證固定 source version、snapshot ID 與 content hash。
- stale workspace revision 回傳明確 conflict，不覆蓋其他分頁剛保存的變更。
- 缺失、不相容、不支援及 hash 錯誤使用穩定 error code。
- 後端重新驗證使用者對 workspace 與來源的存取權，不能信任前端傳入的 owner 或 scope。
- API 日誌不得記錄完整大型參數 payload、完整 NAV 或任何憑證。

## 十八、前端完成品

### 18.1 工作區列表

以密集、可掃描表格顯示：

- 名稱與備註摘要。
- 參數／成果項目數。
- 來源類型摘要。
- 缺失、已有新版或相容警告。
- 最近更新時間與封存狀態。

提供搜尋、篩選、建立、複製、改名、封存及刪除。操作使用既有 icon library；不使用巢狀卡片或大面積介紹區。

### 18.2 工作區工具列

固定提供：

- 加入項目。
- 儲存目前設定。
- 複製工作區。
- 改名與備註。
- 封存。
- 返回來源。

未儲存變更、來源缺失與相容規則過期必須有明確狀態，不以背景自動變更掩蓋。

### 18.3 大量資料畫面

- 參數矩陣使用虛擬化列與欄，只渲染可見範圍。
- 研究成果面板預設收合，展開後才載入完整資料及建立圖表。
- 工作區不設定任意的項目總數硬上限；以搜尋、篩選、分頁、收合與虛擬化處理。
- 疊圖只畫使用者當下明確選取的序列，不把工作區全部結果強制塞入同一張圖。
- 行動版可水平捲動矩陣，工具列與長文字不得互相重疊。

## 十九、效能與低功耗規則

- 初次開啟只讀工作區與來源 descriptor。
- 完整區塊依 `content_hash + block_id` 延遲載入及快取。
- 切換到未開啟區塊不得預抓全部 NAV、seed、路徑或地形。
- 切換來源或關閉面板時取消不再需要的讀取請求。
- 圖表不使用持續動畫。
- hidden tab 停止渲染、同步 hover 與高頻更新。
- 收合或離開面板時釋放大型圖表實例及非必要陣列。
- 不輪詢不可變成果；只有使用者明確重新整理 descriptor 時檢查新版或狀態。
- 來源區塊過大時使用後端分頁、分塊、下採樣顯示資料或來源既有摘要，但不得改寫正式統計值。

N 不顯示總計算量、研究進度或取消任務，因為它沒有計算任務。資料載入可顯示一般載入狀態及取消讀取，但不得冒充 I 任務。

## 二十、版本、缺失與錯誤處理

### 20.1 來源封存

來源封存後，工作區仍可讀取固定版本，並標示「來源已封存」。封存不得使舊工作區內容失效。

### 20.2 來源已有新版

N 顯示新版提示與來源連結，不自動替換。使用者必須明確加入、替換或複製工作區後更新。

### 20.3 來源缺失

若來源模組依自身規則允許硬刪，刪除前必須列出受影響的 N 工作區。刪除後 N 保留缺失 placeholder、原來源識別、版本、hash 與最後已知摘要，不從工作區偷偷移除。

來源模組原本有更嚴格的禁止刪除規則時，N 不會放寬該規則。

### 20.4 完整性錯誤

若實際 payload 與工作區保存的版本或內容 hash 不一致：

- 標示完整性錯誤。
- 禁止該區塊與其他資料合併繪圖或計算顯示差值。
- 保留來源連結與診斷資訊。
- 不自動接受新 hash。

### 20.5 不支援舊 schema

來源存在但目前 adapter 不支援該 schema 時，顯示：

- 原來源及版本。
- 不支援的 schema／公式版本。
- 可返回的來源連結。

N 不猜測轉換，也不把欄位名稱相同視為足夠。

## 二十一、封存、刪除與備份

- 工作區可以封存並從預設列表隱藏；解除封存不改變任何來源引用。
- 刪除工作區只刪除 N 擁有的引用與 view state，不刪來源參數、回測或研究成果。
- 工作區存在不必然凌駕來源模組既有刪除政策，但來源刪除流程必須能列出影響並留下缺失 placeholder。
- 備份必須包含三個 N GORM model、來源引用、view state、compatibility snapshot 與 revision。
- 還原後必須重新驗證引用完整性；不得因來源暫時不可用就自動移除項目。

## 二十二、測試矩陣

### 22.1 來源契約測試

正式參數庫、Backtest/G、M、H、L、C、K 每個 adapter 都必須通過相同契約測試：

- descriptor 可固定到精確版本與 hash。
- 列表不載入完整 payload。
- 單一區塊按需讀取且內容 hash 可驗證。
- `not_calculated` 不觸發計算。
- 封存、新版、缺失、partial、unsupported 與 corrupt 狀態正確。
- 無權限來源不可被搜尋或讀取。

### 22.2 相容規則單元測試

- 四級相容狀態的正例與反例。
- 同公式不同商品／期間降為並排。
- 同名但不同單位、公式或 schema 判為不相容。
- 異質成果只作描述對照。
- M 權威判定不可被 N 升級。
- 不同區塊可以得到不同等級。
- partial、missing 與 corrupt 不得冒充直接相容。

### 22.3 參數矩陣測試

- 轉置前後欄位與參數身分不變。
- 基準有號差正確。
- 相同格點起點與步長才計算步數差。
- 小數顯示不改變內部比較。
- 不存在／未啟用欄位顯示不適用而非零。
- canonical 去重不會把 H/L/C 引用重複成新參數。
- 相同內容 hash、不同 lineage 可同時保留且清楚標示。

### 22.4 工作區整合測試

- 建立、加入、排序、移除、重開、複製、改名、封存與刪除。
- 關閉後仍引用相同 source version、snapshot 與 hash。
- 來源追加新版不改變舊工作區。
- stale revision 不覆蓋另一個分頁的儲存。
- 來源缺失後 placeholder 保留。
- hash 不符時禁止共圖。
- 工作區刪除不影響來源成果。

### 22.5 前端與效能測試

- 兩個分頁不混用項目與畫面狀態。
- 來源頁「加入研究比較」與 deep-link 正確。
- 大型參數矩陣只渲染可見列欄。
- 收合成果面板不請求完整 payload。
- 只對使用者選定序列建立圖表。
- hidden tab 停止動畫及高頻處理。
- 桌面與行動 viewport 無重疊、截字或動態內容造成的版面跳動。

### 22.6 禁止計算回歸測試

所有 N API 與 UI 操作都必須證明不會呼叫：

- 回測核心執行入口。
- G 報酬分析建立入口。
- I 計算任務建立或續跑入口。
- M/H/L/C/K 的開始、追加、訓練或重算入口。
- 參數 Promote 或來源修改入口。

## 二十三、端到端驗收情境

至少完成下列情境：

1. 建立工作區，從參數庫、M 候選與 H 隨機參數庫加入多份參數。
2. 轉置參數矩陣、指定基準、查看有號差與合法步數差，確認不適用欄位沒有補零。
3. 從回測、G、M、H、L、C 與 K 各加入至少一份精確成果版本。
4. 確認同一工作區不同區塊可分別顯示直接、並排、描述及不相容。
5. 對直接相容資料疊圖，對不同商品或期間資料只允許並排。
6. 展開 M/H/L/C/K 面板後才讀取完整資料，收合後停止圖表工作。
7. 遇到未建立 G 報告時只顯示未計算及來源連結，不建立報告。
8. 來源追加新版後重開工作區，確認舊引用不變並出現新版提示。
9. 封存來源後仍可查看；模擬允許的硬刪除後確認缺失 placeholder 保留。
10. 製造 hash 不符，確認禁止共圖且不自動接受新內容。
11. 複製工作區後替換新版，確認原工作區完整保留。
12. 監測後端呼叫，確認整段流程沒有建立任何計算任務或修改來源。

## 二十四、完成判準

N 只有在下列條件全部成立時才能標記「已完成」：

- 獨立「研究比較」頁面與工作區列表、建立、重開及管理流程完整。
- 「參數比較」與「研究結果比較」兩個分頁完整且不混成單一通用表。
- 正式參數庫、M 候選、H 隨機參數與 fallback Backtest 快照皆可依 canonical 規則比較。
- Backtest/G、M、H、L、C、K 所有已列來源都具有正式唯讀比較資料介面。
- 每項引用固定到精確版本、snapshot 與內容 hash，來源新版不會靜默更新工作區。
- 參數矩陣的轉置、基準差值、步數差、只看差異與不適用語義正確。
- 四級逐區塊相容規則完整，且不能升級 M 的權威判定。
- 所有來源型別面板按需載入，未計算資料不會觸發補算。
- 工作區畫面狀態、相容結果、版本提示、缺失 placeholder 及完整性錯誤可保存與重開。
- 大量項目使用分頁、虛擬化、收合與延遲載入，hidden tab 與離開面板後不持續耗能。
- 所有權限、契約、單元、整合、前端、效能、備份還原及端到端測試通過。
- 自動化測試證明 N 不呼叫回測、G、I、M/H/L/C/K 計算或 Promote。
- 沒有把骨架、少數來源 adapter、假 payload、複製成果資料或只顯示摘要回報為 N 完成。

## 二十五、禁止的替代實作

- 不得把所有來源壓成只有名稱與幾個績效數字的摘要頁。
- 不得把完整來源 payload 複製進 N，形成第二套結果真源。
- 不得因開啟、拖曳、切圖或加入工作區而暗中重新計算。
- 不得把不同商品、期間、dataset 或回測語義的結果冒充直接可比。
- 不得用欄位顯示名稱取代 schema、公式、單位與版本檢查。
- 不得把缺失、未啟用、未計算、partial 或不相容資料顯示為零。
- 不得以插值、標準化、代理值或自動換算修補不相容來源。
- 不得建立總分、總排名、自動最佳參數、自動淘汰或 Promote。
- 不得用 N 取代 M `ResearchSeries` 的共同 manifest 與受控逐點比較。
- 不得為了前端方便放寬來源模組的封存、刪除、權限或完整性規則。
