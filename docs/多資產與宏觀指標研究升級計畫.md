# 多資產與宏觀指標研究升級計畫

**文件定位：** 本文件是重大更新前的開發計畫與討論稿，不直接取代三份真源文件。實作前必須把已確認的規格拆回 `docs/系統總體拓撲結構.md`、`docs/策略數學引擎.md`、`docs/進化計算引擎.md`。

## 1. 對現行系統理解的校正

目前系統不是「保證防止過擬合」，而是「用多個約束降低過擬合機率」。

現有保護包含：

- 策略核心只看截至當下已完成 K 線，不應看到未來資料。
- 價格特徵多數是無量綱比例、對數收益、標準化偏離，而不是直接記憶價格點位。
- 染色體欄位有限，且有邊界、結構驗證與固定窗長，降低自由度。
- 參數搜尋使用多窗口坩堝，包含 10y、5y、2y、6m 權重評分。
- 適應度與 Ghost DCA 比較，並懲罰超額回撤、交易次數與成本。
- 任務、參數與 champion 依標的、週期、資料源、執行假設隔離。

但這些仍不能消滅過擬合。只要搜尋次數夠多、特徵夠多、資料區間固定，就可能找到只適合該段歷史的參數。若要進一步防守，後續需要加入：

- Out-of-sample 保留區。
- Walk-forward rolling validation。
- 跨商品回測與跨週期穩健性檢查。
- 特徵數量懲罰或模型複雜度懲罰。
- 參數敏感度檢查，避免只有極窄區間有效。

使用者對槓桿 ETF 的理解大致合理：槓桿 ETF 回撤深、波動耗損大，若策略能避開部分深回撤，確實有機會在後續上升段拉開與定投的差距。非槓桿商品波動較小，減碼避險的好處較少，錯失趨勢與交易成本反而更容易吃掉超額報酬。

需要補充的風險是：槓桿 ETF 的優勢來自高度路徑依賴，不只看方向，也看波動順序。策略可能在歷史牛熊結構中很好，但遇到不同利率環境、不同產業循環、不同槓桿 ETF 追蹤誤差時失效。

## 2. 升級目標

把目前「單一交易商品價格序列」研究系統，升級成「多資產組合 + 外部指標特徵」研究系統。

新資料分成兩類：

| 類型 | 用途 | 範例 | 是否可配置倉位 |
|---|---|---|---|
| 交易商品 | 參與投資組合配置，策略可決定其目標權重 | SOXL、TQQQ、黃金 ETF、債券 ETF、現金 | 是 |
| 指標 | 只提供市場環境資訊，不直接配置倉位 | credit spread、swap spread、殖利率曲線、VIX、金銀比、美元指數 | 否 |

同一個序列可以在不同研究中扮演不同角色。例如 SPY 可作為交易商品，也可作為 SOXL 研究的市場指標。

## 3. 指標與商品是否能用同一套參數搜尋

可以共用 GA 尋優框架，但不能把指標與交易商品完全視為同一種東西。

建議設計如下：

- 資料層：統一成 `TimeSeries`，所有商品、指標、衍生比值都用同一套時間序列儲存與對齊。
- 特徵層：交易商品與指標都可轉成標準化特徵，例如報酬、斜率、偏離、z-score、百分位、比值變化。
- 策略輸入層：交易商品提供價格與可交易宇宙；指標只提供特徵，不可直接下單。
- 策略輸出層：單商品策略輸出一個目標權重；多資產策略輸出一組權重向量，例如 SOXL 60%、黃金 20%、現金 20%。
- GA 層：仍然搜尋參數，但基因空間會擴充到「如何使用哪些特徵」與「如何配置資產」。

也就是說，GA 邏輯仍可延續，但策略契約與資料集建構必須升級。

## 4. 必須優先處理的資料正確性問題

外部指標比股價更容易造成未來資料洩漏，因此必須先定義資料時間語義。

每筆資料至少需要：

- `observed_at`：資料代表哪一天或哪段期間。
- `available_at`：系統在歷史當下最早何時能知道這筆資料。
- `source`：資料來源。
- `frequency`：日、週、月、季、不定期。
- `revision_policy`：是否允許修訂值；第一版建議只使用當前可下載歷史值，並在 UI 標示非 point-in-time。

嚴禁用「未來才公布的經濟數據」去回測過去日期。例如某月 credit spread 若是月底後才確認，回測時不能讓月中策略提前看到。

第一版建議採保守做法：

- 股價、ETF、指數：使用已完成 bar。
- 利率、信用利差、VIX 類日資料：以資料日期隔一個交易日才可用為預設。
- 週/月資料：只能在該週/月完成後進入資料集。
- 缺值不得任意補 0；只能依規則 forward-fill，且必須標記距離上次更新已過多久。

## 5. 架構升級方向

### 5.1 資料模型

新增泛用研究序列概念：

- `ResearchSeries`
  - 序列 ID、名稱、類型、資料來源、頻率、單位、幣別、可否交易。
- `SeriesPoint`
  - `series_id`、`observed_at`、`available_at`、OHLCV 或單值、調整方式、來源版本。
- `DerivedSeries`
  - 由其他序列計算而來，例如金銀比、SOXL / SOXX 相對強弱、信用利差。

既有 `ResearchInstrument` 與 `KLine` 可先保留，避免一次破壞現有功能。新資料層可用 adapter 讀既有 K 線，再逐步遷移。

### 5.2 資料集建構器

新增 `ResearchDatasetBuilder`：

輸入：

- 交易商品清單。
- 外部參考序列清單。此清單可包含不可交易宏觀指標、衍生序列，也可包含本次不作為交易目標的商品序列；角色由本次資料集設定決定，不由序列本身永久綁死。
- 週期。
- 訓練區間。
- 執行假設。
- 特徵轉換設定。

輸出：

- 按時間對齊的 panel dataset。
- 每個時間點只包含 `available_at <= decision_time` 的資料。
- 每個欄位帶 metadata，讓 UI 能說明它原本是商品、指標或衍生序列，以及本次在資料集中扮演交易目標或外部參考角色。

這是整個升級最重要的地基。若資料集對齊錯誤，後面的 GA 再漂亮都沒有意義。

### 5.3 策略契約

保留既有單商品 `Step()`，新增多資產研究策略契約。第一版不應直接改壞現有 SigmoidDCA。

建議新增：

```text
MultiAssetStrategyInput
├── DecisionTime
├── TradableAssets[]
├── IndicatorFeatures[]
├── PortfolioSnapshot
├── RuntimeState
├── Params
└── SpawnPoint

MultiAssetStrategyOutput
├── TargetWeights[asset_id]
├── CashWeight
├── Diagnostics
└── RuntimeState
```

約束：

- 第一版只做 long-only，不做放空。
- 所有資產權重加現金權重不可超過 100%。
- 不做槓桿借款；槓桿曝險只來自商品本身，例如 SOXL。
- 回測、參數搜尋、市場狀態仍必須共用同一個策略入口。

### 5.4 GA 基因空間

多資產策略不應讓 GA 自由發明無限公式。建議先用受控基因空間：

- 資產配置反應速度。
- 各資產基準權重或權重上限。
- 指標特徵權重。
- 指標特徵啟用開關。
- 風險狀態下的現金上限或風險資產折扣。
- 調倉門檻、強制風險開關、交易成本敏感度。

為降低過擬合，第一版應加上：

- 啟用特徵數量上限。
- 每啟用一個外部指標可扣少量複雜度分數。
- 指標同類群組互斥或限量，例如信用類最多選 2 個、利率類最多選 2 個。
- 訓練區與驗證區分數同時顯示。

### 5.5 評分與基準

單商品策略目前使用 Ghost DCA 作基準。多資產策略必須新增基準定義。

可選基準：

- 單一主商品 DCA，例如 SOXL DCA。
- 使用者指定靜態組合，例如 SOXL 50%、GLD 30%、現金 20%。
- 等權交易商品組合。
- 風險平價基準，後續再做。

第一版建議允許使用者選一個主要比較基準，並保留策略淨值、基準淨值、各資產貢獻、交易次數、換手率、成本損耗。

## 6. UI 改動範圍

### 6.1 行情資料頁

新增「研究序列」管理：

- 商品序列。
- 指標序列。
- 衍生序列。
- 可交易 / 不可交易標記。
- 資料頻率、最早資料日、最新可用日、缺值狀態。

### 6.2 參數搜尋頁

新增研究設定：

- 策略類型：單商品 / 多資產。
- 交易商品組合。
- 指標清單。
- 特徵轉換清單。
- 基準設定。
- Out-of-sample 或 walk-forward 設定。
- 特徵數量懲罰與交易成本。

搜尋前必須顯示資料可用性檢查：

- 哪些序列缺資料。
- 哪些序列頻率不同。
- 起始日會被哪個序列限制。
- 是否存在可能的資料延遲或非 point-in-time 風險。

### 6.3 回測頁

多資產回測需新增：

- 總淨值曲線。
- 基準淨值曲線。
- 每個資產權重走勢。
- 現金權重走勢。
- 各資產貢獻。
- 換手率與交易成本。
- 指標狀態圖層，可選擇顯示。

### 6.4 市場狀態頁

單商品市場狀態保留。

多資產狀態新增：

- 當前建議權重向量。
- 相較上一期的權重變化。
- 主要指標目前狀態。
- 觸發權重調整的前幾個特徵貢獻。
- 資料新鮮度警示。

## 7. 分階段實作計畫

### Phase 0：規格落地

把本計畫中確認採用的內容拆回三份真源文件：

- 系統總體拓撲：新增研究序列、資料集建構器、多資產研究模組。
- 策略數學引擎：新增多資產策略契約、權重向量輸出與風險約束。
- 進化計算引擎：新增多資產任務設定、特徵選擇、驗證區與複雜度懲罰。

### Phase 1：資料層

- 新增研究序列資料模型。
- 建立商品 / 指標 / 衍生序列的基本 CRUD。
- 建立資料對齊與 `available_at` 防未來洩漏機制。
- 讓既有 K 線可以被包裝成 `ResearchSeries`。

### Phase 2：特徵層

- 建立標準特徵轉換：return、log return、z-score、percentile、moving slope、ratio、spread。
- 建立資料集建構器。
- 建立資料完整性檢查與 UI 預覽。

### Phase 3：單商品策略相容改造

- 讓既有 SigmoidDCA 可以透過新資料集讀取主商品價格。
- 保證舊參數、舊回測、舊市場狀態結果不被破壞。
- 補回歸測試：同一資料、同一參數，舊路徑與新路徑結果一致。

### Phase 4：外部指標版單商品策略

- 在不改成多資產配置前，先讓單商品策略可讀外部指標。
- 指標只影響風險倍率、目標權重或現金偏好。
- 加入特徵數量懲罰與驗證區顯示。

### Phase 5：多資產策略

- 新增多資產策略契約。
- 回測支援權重向量與多商品成交。
- 參數搜尋支援交易商品組合。
- 市場狀態顯示多資產建議配置。

### Phase 6：穩健性研究

- Walk-forward。
- 跨商品驗證。
- Monte Carlo 或 bootstrap。
- 參數敏感度熱圖。

## 8. 第一版建議範圍

不要第一版就同時做所有事情。建議第一版只做：

1. 研究序列與資料集建構器。
2. 既有單商品策略相容。
3. 單商品 + 外部指標特徵。
4. Out-of-sample 顯示。

多資產配置放第二波。原因是多資產會同時牽涉成交、現金、權重總和、基準定義、UI 圖表與參數庫隔離，若和指標資料層一起做，錯誤來源太多。

## 9. 待使用者確認問題

1. 第一波是否先做「SOXL 單商品 + 外部指標」，暫不做多資產配置？
2. 指標資料來源要先用免費資料源，還是接受之後可能接商業資料？
3. credit spread、swap spread 的具體序列代碼與來源要由使用者指定，還是先讓系統提供候選清單？
4. 多資產第一版是否只允許 long-only、總權重不超過 100%？
5. 多資產基準要用主商品 DCA、等權 DCA，還是使用者指定靜態組合？
6. 經濟指標修訂值是否可接受？若要求 point-in-time，資料源難度與成本會大幅提高。

## 10. 開發守則

- 不在策略核心中加入網路、資料庫、時間或 I/O。
- 所有資料拉取、對齊、延遲、補值都在外圈資料集建構器完成。
- 回測、參數搜尋、市場狀態必須共用同一套資料集與策略入口。
- 指標若沒有明確 `available_at`，不可直接進入歷史回測。
- 舊單商品策略結果必須有回歸測試保護。
- UI 可顯示指標名稱與狀態，但不要把內部策略術語當成使用者主要語言。

## 11. 本輪開發治理補充

本輪重大更新必須同時遵守 `docs/重大更新開發守則.md`。尤其是：

- 不得把 MVP、骨架、資料通道、UI 選項或暫時公式稱為階段完成。
- 若某階段必須先做 MVP，必須在寫程式前先列出 MVP 範圍、排除項、測試方式與補齊完整版的條件。
- 若沒有要做 MVP，必須明確說明該階段採一次到位，並列出完成定義。
- 外部序列各自可產生哪些特徵、每個特徵的 metadata、缺值規則、可用時間、演化欄位與評分方式，仍需與使用者確認；確認前不得重新定稿開發計畫，也不得宣稱「單商品 + 外部指標」完成。
