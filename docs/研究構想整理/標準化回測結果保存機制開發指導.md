# 標準化回測結果保存機制開發指導

> 狀態：已完成；標準結果版本為 `p03-result-v1`
>
> 用途：定義標準化回測結果的保存、去重、重用與跳轉機制。此文件不是三份真源文件，不取代既有穩定系統規格。

## 一、系統定位

標準化回測結果保存機制用來保存可被多個功能共用的回測結果。

它不是單純的回測頁紀錄，也不是參數搜尋紀錄。

它要支援：

- 回測頁。
- 參數搜尋頁。
- 報酬分析共用模組。
- 隨機參數與無意義規則對照系統。
- 使用 E 不可變重組行情的普通回測、參數穩健區域分析、長週期風險濾網與 L 擾動行情資料測試。
- K 動態參數回測與 M 參數績效地形研究。
- C 參數可獲利 K 線樣貌反推。
- N 通用研究結果與參數比較工具。

## 二、依賴關係

此機制依賴：

```text
docs/研究構想整理/回測核心模組開發指導.md
docs/研究構想整理/每日實際持倉計算機制開發指導.md
```

原因是標準化回測結果必須由回測核心產生，且每個 NAV point 必須包含每日實際持倉比例。

此機制完成後，會被下列功能依賴：

```text
docs/研究構想整理/報酬分析共用模組開發指導.md
docs/研究構想整理/隨機參數與無意義規則對照系統開發指導.md
docs/研究構想整理/計算任務與快取掃描工具開發指導.md
docs/研究構想整理/長週期風險濾網與過濾模型開發指導.md
docs/研究構想整理/參數穩健區域分析開發指導.md
docs/研究構想整理/動態適應參數機制開發指導.md
docs/研究構想整理/參數績效地形研究與穩健候選產生系統開發指導.md
docs/研究構想整理/擾動行情資料產生器開發指導.md
docs/研究構想整理/參數可獲利K線樣貌反推系統開發指導.md
docs/研究構想整理/通用研究結果與參數比較工具開發指導.md
```

開發順序上，此文件所定義的保存機制應在報酬分析、I、C、D、H、J、K、L、M 與 N 完整落地前完成。

## 三、與現有 backtest_runs 的關係

現有 `backtest_runs` 可以保留作為「使用者發起的回測任務紀錄」。

但標準化回測結果庫是更底層的共用資料。

建議關係：

```text
BacktestResult
↑
backtest_runs
參數搜尋觀察
M 研究評估點
隨機對照任務
L 擾動測試 run
C 生成路徑評估
報酬分析報告
```

也就是上層任務可以引用同一個標準化回測結果。

## 四、保存分層

標準化回測結果分三層保存：

1. Backtest Spec
2. Backtest Result Summary
3. Backtest Path Detail

## 五、Backtest Spec

Backtest Spec 保存「這次回測的條件」。

包含：

- 參數 ID 或參數快照。
- 參數內容 hash。
- 標的。
- 資料源。
- 週期。
- 起訖時間。
- execution mode。
- 初始資金。
- 每月投入。
- 手續費。
- 滑價。
- position structure。
- 回測核心版本。
- 策略版本。
- 資料集版本或資料範圍 hash。
- 長週期濾網設定與版本，如有。
- K 模型 artifact、預測 schema 與模型 hash，如有。
- K 動態政策、控制模式與政策 hash，如有。
- 每日預測或有效參數物化資料 hash，如有。

Backtest Spec 用來判斷兩次回測是否是同一份結果。

## 六、Backtest Result Summary

Backtest Result Summary 保存快速查詢用摘要。

包含：

- ROI。
- Final Equity。
- MaxDD。
- 交易次數。
- 持倉天數比例。
- 平均實際倉位。
- 最長水下期。
- Sortino。
- Beta，如果有指定基準。
- 結果 schema 版本與摘要內容 hash。
- 建立時間。
- 狀態。

列表頁、參數搜尋結果、對照任務與報酬分析入口可以先讀這層。

## 七、Backtest Path Detail

Backtest Path Detail 保存完整路徑資料。

包含：

- 每日 NAV。
- 每日價格。
- 每日現金。
- 每日資產數量。
- 每日實際持倉比例 `actual_exposure_weight`。
- 目標權重。
- 每日報酬。
- 交易/調倉摘要。
- 必要圖表資料。
- 每日有效核心參數快照，如有使用 K。
- K 結構狀態、occurrence ID、模型與政策版本，如有。
- 有效參數回退或不可用事件，如有。

此層資料較大，必須按需讀取。

## 八、Backtest Key 與去重

建立回測前，系統必須計算 `backtest_key`。

`backtest_key` 由下列內容組成：

- 參數內容。
- 標的。
- 資料源。
- 週期。
- 起訖時間。
- execution mode。
- 初始資金。
- 每月投入。
- 手續費。
- 滑價。
- position structure。
- 長週期濾網設定與版本，如有。
- K 模型 artifact hash，如有。
- K 預測 schema 與物化預測 hash，如有。
- K 動態政策與控制模式 hash，如有。
- 資料版本或資料範圍 hash。
- 回測核心版本。
- 策略版本。

若相同 `backtest_key` 的完成結果已存在，系統優先重用既有結果。

若資料更新、回測核心版本改變、參數改變或費用設定改變，必須產生新的回測結果。

完成結果必須另有不可變結果版本與內容 hash；`backtest_key` 用來識別輸入條件，結果內容 hash 用來驗證實際保存的摘要與 path block，不得混為同一用途。大型 path detail 可以分塊保存，但每個 block 必須有自己的內容 hash，並由結果 manifest 固定其集合與順序。

## 九、狀態

標準化回測結果狀態包含：

- pending
- running
- completed
- failed
- invalidated
- archived

若資料或核心版本更新導致舊結果不再適合作為當前結果，可標記為 `invalidated`，不得直接覆蓋舊結果。

## 十、與報酬分析報告的關係

一個標準化回測結果可以有多份報酬分析報告。

關係：

```text
BacktestResult 1 → N PerformanceReport
```

原因是報酬分析可能因下列設定不同而不同：

- Beta 基準。
- 無風險利率。
- 分析版本。
- 時間聚合方式。
- 未來新增指標後補算。

回測結果頁必須能看到已建立的報酬分析報告列表。

報酬分析報告必須能跳回原始回測結果。

## 十一、與參數搜尋的關係

參數搜尋可引用標準化回測結果以顯示報酬分析摘要。

現階段只顯示報酬分析摘要，不把新指標納入參數搜尋評分。

若未來要把 Sortino、最長水下期或曝險指標納入評分，必須另開文件討論。

## 十二、與 M 參數研究的關係

M 的每個 `ResearchEvaluationPoint` 必須引用標準化回測結果，不得自行保存另一份 NAV 或重新定義回測摘要。

關係：

```text
ResearchEvaluationPoint N → 1 BacktestResult
```

只要實際執行條件得到相同 `backtest_key`，即使來自不同研究設定、不同研究階段或不同參數空間 schema，也必須重用既有結果。研究設定與量化 schema 屬於 M 評估點 metadata，不得無故降低底層回測去重率。

`ResearchSeries` 配對比較不得在 `BacktestResult` 內另存一份比較專用 NAV 或績效。共同參數向量在各成員設定下各自引用其正確 `BacktestResult`；比較快照只保存成員結果引用、逐點衍生差值、缺漏狀態與比較版本。若兩個成員實際執行條件具有相同 `backtest_key`，仍只保存一份底層回測結果。

M 評估點另行保存：

- 研究設定 ID。
- 研究階段與取樣批次。
- 參數向量與 hash。
- BacktestResult ID。
- J 指標、合格狀態與地形 metadata。

上述資料屬於 M，不得塞入 `BacktestResult` 使底層回測結果綁死單一研究任務。

## 十三、與隨機對照系統的關係

隨機對照系統會引用標準化回測結果：

- 正式參數回測結果。
- 隨機參數回測結果。
- 無意義規則回測結果。
- 曝險序列重放回測結果。

對照任務若遇到相同回測條件與相同隨機參數，應優先重用既有標準化回測結果。

## 十四、與 L 擾動行情測試的關係

L 的每個受測參數在來源快照及每份 `seed × alpha` 擾動 dataset 上，各自引用一筆標準化回測結果：

```text
PerturbationTestRun N → 1 BacktestResult
```

規則：

- dataset content hash 必須進入 Backtest Spec 與 `backtest_key`。
- L test ID、batch ID、群組名稱、seed 分佈統計及圖表設定不改變實際回測時，不得塞入底層 `backtest_key`。
- 參數 NAV 與 Ghost DCA 必須使用同一份來源快照或擾動 dataset；不得共用原始行情 DCA。
- 相同 subject、dataset 與回測設定已有完成結果時必須重用。
- L 只保存回測結果引用、配對關係與跨 seed／幅度摘要，不得複製 NAV path。
- 未完成、invalidated 或內容 hash 損壞的 dataset／結果不得快取命中。

完整 L 編排與統計契約見：

```text
docs/研究構想整理/擾動行情資料產生器開發指導.md
```

## 十五、與 C K 線樣貌反推的關係

C 的每個實際生成路徑評估引用一筆標準化回測結果：

```text
KlineInverseEvaluation N → 1 BacktestResult
```

規則：

- C path hash 作為 W＋H 內部合成 dataset 的內容身分。
- Backtest Spec 同時保存完整 W＋H dataset hash 與 H 正式評估起訖位置。
- W 只有歷史前綴，不產生 NAV point；H 才形成標準化回測路徑。
- 參數與 DCA 的每月投入都固定為 0，且兩者必須使用同一條生成行情。
- 相同 path、參數值與回測條件已有完成結果時必須重用。
- C study、batch、CVT cell、父代、血緣與圖表設定不得進入 `backtest_key`。
- C 只保存 BacktestResult 引用、行為特徵、搜尋狀態及血緣，不複製 NAV 真源。
- 生成 path 保存在 C 研究內，不因建立 BacktestResult 自動發布為一般行情資料。

完整 C 規格見：

```text
docs/研究構想整理/參數可獲利K線樣貌反推系統開發指導.md
```

## 十六、與 N 通用比較工具的關係

標準化回測結果是 N 的研究成果來源之一，必須提供正式唯讀比較資料介面。

來源 descriptor 至少固定：

- BacktestResult ID、狀態與建立時間。
- Backtest Spec 版本、`backtest_key` 及內容 hash。
- 參數 canonical 來源；若不存在，提供凍結參數快照及參數內容 hash。
- 商品、dataset、週期、日期、execution mode、成本、現金流、DCA、濾網及 K metadata。
- 回測核心、策略、每日實際持倉及摘要指標版本。
- 已存在的 PerformanceReport 精確引用。

比較資料區塊至少分成：

- 回測背景與摘要。
- 績效與風險指標。
- NAV、價格、現金、交易與每日實際持倉路徑。
- 已存在的 G 報告連結。

完整 path detail 只在 N 使用者展開對應區塊時讀取。N 不得因加入工作區、切換圖表或發現 G 尚未建立而重新回測或補算分析。

N 工作區只保存精確結果版本、內容 hash 與畫面狀態，不複製 Backtest Spec、Summary 或 Path Detail。N 引用不進入 `backtest_key`，也不得降低既有回測去重率。

完整 N 規格見：

```text
docs/研究構想整理/通用研究結果與參數比較工具開發指導.md
```

## 十七、資料清理

系統提供人工清理，不自動亂刪。

可以：

- 封存舊結果。
- 刪除失敗結果。
- 刪除 path detail，只保留摘要。
- 清理未被任何任務引用的結果。

若回測結果已被報酬分析報告、M 研究評估點、候選、對照任務、L 擾動測試、C 生成路徑評估、N 比較工作區或使用者保存紀錄引用，刪除前必須提示影響範圍。

若來源規則允許硬刪，被 N 引用的結果刪除後必須讓 N 保留缺失 placeholder；不得要求 N 靜默移除工作區項目。既有更嚴格的限制刪除政策仍優先。

## 十八、完成判準

此保存機制完成後，至少必須滿足：

- 回測核心產生的結果可以保存為標準化回測結果。
- 相同回測條件可以被去重並重用。
- 回測頁可以引用標準化回測結果。
- 報酬分析報告可以引用標準化回測結果。
- 參數搜尋頁可以讀取標準化回測結果摘要。
- K 動態回測結果可追溯模型、預測、政策、每日有效參數與回退事件。
- M 評估點可以引用、去重並重用標準化回測結果，而不複製 NAV。
- 隨機對照任務可以引用標準化回測結果。
- L 的來源快照及擾動版本可形成不同 dataset key；L run 能去重引用結果，且參數與 DCA 保持同 dataset。
- C 的 W＋H 生成路徑可形成 dataset key；C evaluation 能去重引用只在 H 產生的結果，且參數與零月投入 DCA 保持同 path。
- 回測結果與報酬分析報告可以互相跳轉。
- BacktestResult 可向 N 暴露固定版本、內容 hash、摘要及按需 path detail，且 N 讀取不會觸發回測或 G 補算。

## 十九、P03 實作紀錄

完成日期：2026-07-15。

本階段採一次到位，已完成：

- 以 GORM model 與 AutoMigrate 建立 `BacktestSpec`、`BacktestResult`、`BacktestResultSummary`、`BacktestPathBlock`；沒有建立 SQL migration。
- `p03-key-v1` canonical `backtest_key` 涵蓋凍結參數、商品／來源／週期、實際資料範圍、execution mode、資金與成本、position structure、dataset content hash、核心／策略版本，以及已保留的濾網與 K metadata hash 欄位。參數來源任務 ID 不會在實際參數內容相同時降低去重率。
- Spec、Summary、每個 path block、path manifest 與完整 Result 各自保存版本及 SHA-256 內容 hash；path 預設每 256 點分塊，manifest 固定集合、順序、索引與時間範圍。
- 完成結果使用唯一 active key 防止同 key 併發重複建立；只有目前結果版本、狀態為 completed、path 尚在且完整性驗證通過的結果可以命中重用。損壞、failed、cancelled、invalidated、archived 或只剩摘要的結果不會命中。
- 新 `BacktestRun` 只保存使用者任務／請求與 `BacktestResult` 引用，不再複製完整 NAV；既有舊 `BacktestRun.Result` 仍可相容讀取。
- 回測 API 回傳 `backtest_result_id`、`backtest_key`、結果版本、內容 hash 與是否重用；另提供標準結果 descriptor、按 block 讀取 path 及完整性驗證唯讀接口。
- 每個標準 path point 保存現金、資產數量、成交後 `actual_exposure_weight`、每日報酬、交易摘要及 K 每日有效參數／結構 metadata（如有）。
- 支援 pending、running、completed、failed、cancelled、invalidated、archived；封存、失效、失敗結果刪除、path detail 清理與引用影響查詢由明確人工維護動作執行，不在啟動或排程中自動刪除。
- 增量備份格式升級為 v2，會保存 Spec、Result、Summary、全部 path block 與 `BacktestRun` 引用，並補齊跨增量時間邊界的依賴閉包；全量／增量還原後會執行引用及內容 hash 驗證。

Summary schema 已保留 nullable Sortino 與 Beta 欄位。P03 不自行發明 P04 尚未確認完整設定的 Sortino 年化／無風險利率或 Beta 基準公式；正式版本化分析值由 P04 `PerformanceReport` 負責，P03 只保存呼叫端已有明確版本契約時提供的值。

本階段不包含 P04 報酬分析 UI／報告，也不提前建立 M、L、C、N 的業務資料表；後續模組直接引用本階段的標準結果 ID、版本與 hash。
